# Lazy PDF — module contracts

Native PDF editor for Windows, macOS and the iPhone, the third of the Lazy apps with Lazy Scan (`../LazyScan`) and Lazy Print (`../LazyPrint`), whose layout and conventions it shares. The Windows app is .NET 10 and WPF. The Swift targets (`LazyPDFKit`, `LazyPDFMac`, `LazyPDFIOS`) follow once the C# engine has settled, the order Lazy Print was built in.

**System frameworks only.** Core has no third-party code. It may use `System.Security.Cryptography.Pkcs`, Microsoft's own CMS package, for signatures; that is the one package reference it has. PdfPig stays in the test project, as in Lazy Scan.

## The split: our engine, the system's pixels

Lazy PDF owns the file format and leaves drawing a page to the system. Everything that reads, understands or changes a PDF is in `LazyPDF.Core` and written by us. Turning a page into pixels is `Windows.Data.Pdf` on Windows and PDFKit on Apple, behind `IPageRenderer`. This is what keeps the app small: a renderer with full font, colour and transparency support is years of work and the systems already have one, while none of them will edit a file.

## Global rules

1. Core uses no UI and no OS-specific API. It takes bytes and gives bytes. Fonts, images it cannot decode, OCR and time reach it through small interfaces an app passes in.
2. A helper not listed here is `private` or `internal`.
3. Coordinates: the engine speaks PDF user space (points, origin bottom-left) in page objects and content. App geometry is points with origin top-left and y down, as in the sisters. `PageGeometry` converts between them and applies `/Rotate` and the crop box; nothing else does.
4. Reading is forgiving, writing is strict. The reader repairs what it can and says so (`PdfDocument.Repairs`); what the writer emits must pass a strict parser. No third-party file ever crashes the engine: bad input throws `PdfReadException`, and every recursion and allocation driven by file contents has a cap.
5. Never lose the user's data. A save goes to a temporary file, is read back, then replaces the original. Signed files get incremental updates only, unless the user chooses otherwise.
6. Files as written by us reopen in `Windows.Data.Pdf` and PdfPig. Every writer test does this.
7. User text is short, as in the sisters: a status line is six words at most with the full sentence for screen readers, a problem is titled by what is wrong and says what to do. It goes through `Loc.T` (English is the key) and Turkish lands with it. Texts both platforms show live in Core, in a `...Text` type.
8. Settings files load across versions by Lazy Scan's rules (Global rule 6 there), in `%APPDATA%\Lazy PDF`.
9. Code copied from a sister says so in its header: "From Lazy Scan's PdfSyntax.cs". Copying with the names changed is how code moves between the three repos.

## Names

"Lazy PDF" in text, `LazyPDF` in code. Scheme `lazypdf:`, mutex `Local\LazyPDF.App`, pipe `LazyPDF.Open.<session id>`, settings folder `Lazy PDF`, phone link `_lazypdf._tcp` on port 52733 with mutex `Local\LazyPDF.PhoneLink`. On Apple a Viewer of `com.adobe.pdf` at Alternate rank, so it never takes over a default.

## The edit session

An open file is one growing byte buffer. Each edit commits an incremental update (ISO 32000-1 7.5.6) to the end of it, and undo moves the end back to the previous `%%EOF`; redo moves it forward. So undo is exact and cheap, the renderer always reads a complete valid PDF, and a crash loses nothing that was autosaved. `Save` writes the buffer as it stands; `Save compact` rewrites it without the history.

## Feature target

Against Acrobat Pro. Skipped on purpose: XFA dynamic forms (detected and reported), 3D and rich media, Adobe DRM, cloud review and cloud signing requests, press separations and trapping.

Beyond Acrobat: scan into the open file through Lazy Scan, print with Lazy Print's booklets and N-up, one-click clean for sharing, redaction by pattern with a report of what was removed, signature checks in plain words, every saved version recoverable from the file, phone capture and signing over the phone link, folder rules, and all of it offline with no account.

## Windows app

The solution is `windows/LazyPDF.sln`: `LazyPDF.Core` (the engine, no UI), `LazyPDF.App` (WPF, net10.0-windows10.0.19041.0, references Core) and one test project for each. App code is code-behind and a view model, file-scoped namespaces, sealed classes, records for data, no MVVM toolkit. Handlers are named `Control_Event`. Every control has `AutomationProperties.Name`, and all text goes through `{loc:T}` in XAML and `Loc.T` in code. `scripts/gen_l10n.py --check` fails on a text the code uses and `l10n/shared.json` lacks, on one nothing uses, and on a missing Turkish.

### Shape

`AppViewModel` (split by job: documents, home, print) holds the tabs, the active tool, the info bar and the busy bar. `MainWindow` is the shell: tab strip, tool strip, side rail, stage, inspector, status line. A tab is a `DocumentTab` (the edit session, undo, the file on disk, the password or certificate it was opened with) or the `HomeTab`.

### Services

Everything that touches the system sits in `Services/` behind a small interface or a plain class, so tests pass stand-ins.

- `WindowsPageRenderer` draws pages through `Windows.Data.Pdf` (`IDocumentRenderer`); `Thumbnails` and the viewer's tile cache sit on it.
- `WicImageCodec`, `SystemFontSource`, `WindowsOcr` and `WindowsCertificates` give Core its images, fonts, text recognition and certificate store.
- `HttpSignatureTransport` fetches time stamps and validation data; it is cancellable. The transports refuse loopback and link-local addresses, follow at most 5 redirects, checking each, and stop after 200 requests per instance.
- `InstanceChannel` hands a second launch's files to the running window; `FileAssociation` and `LazyPdfAddress` handle Open with and `lazypdf:`.
- `SisterApps` starts Lazy Scan and hands a file to Lazy Print; the window prints itself when Print is not there. It finds a sister by its address under the classes key, and failing that by asking Windows (`Launcher.QueryUriSupportAsync`), since an app from the Store registers its address in its package. The answer is kept for 30 seconds.
- `Packaging.IsPackaged` says whether the process has a package identity (`GetCurrentPackageFullName`). `AppFolders` names the folders the app writes to. `AppInfo` gives About its version (the assembly's, from `Version` in `windows/Directory.Build.props`), copyright, addresses and the `THIRD-PARTY-NOTICES.txt` shipped beside the exe.
- `RecentFiles`, `AppPreferencesStore`, `StoreFiles` (the settings file rules) and `RecoveryStore`.

### A tool

A tool is one folder under `Tools/` with a `ToolPanel` subclass, listed once in `ToolCatalog` with its id, group, glyph, one-sentence summary and a factory. The shell builds the panel the first time the tool is picked and calls `Attach(tab, viewer, host)` and `Detach()`. `Action` is the accent button pinned under the panel; `RaiseActionChanged` tells the shell it changed. Work that takes time goes through `IToolHost.RunBusyAsync`, which shows the busy bar with a Cancel that arrives as a token. A tool changes the document only with `tab.Commit(label)`, which is one undo step. When it writes the file itself it calls `ReloadAsync`. Results that are a new file open as a new tab with `OpenNewAsync`. Problems and notices go to the host, never to a dialog of the tool's own, except Create and Compare, which have a window.

Panels with several jobs split into partial files (`PagesPanel.Edit.cs`, `PagesPanel.Drag.cs`); logic that needs no controls lives in a plain class beside it (`CreateJob`, `RedactJob`) so it is tested without a window. The side panels on the rail are built the same way and are listed in `ToolCatalog.SidePanels`.

### The viewer

`IDocumentViewer` is what panels may ask of the stage; `PageViewer` is the one implementation. Page numbers are 0-based and everything is for the UI thread.

- `Show`, `PageIndex`, `Zoom`, `GoToPage`, `GoToDestination`, `FollowAction`, `GoBack`, `GoForward`, `Reveal`.
- `VisiblePages`, `PageSize`, `PageToView`, `ViewToPage`, `Geometry`. Page space is points from the top left of the page as shown, y down; `PageGeometry` converts to PDF user space.
- `Overlay(page)` is a canvas over a page for previews and handles; it moves with the page.
- `PointerTool` takes the left button as press, move, release (`IPagePointerTool`); without one the pointer pans or selects text.
- `GetTextAsync`, `GetSelectionAsync`, `SelectAll`, `ClearSelection` for text; `SetLayerVisible` for layers.
- Events: `StateChanged`, `ViewChanged`, `PageChanged`, `ModeChanged`, `SelectionChanged`, `LayersChanged`.

### Settings and recovery

`preferences.json` (appearance, the side panel left open, inspector sections), `recent.json`, `signing.json`, `batch-sets.json` and the saved signatures live in `%APPDATA%\Lazy PDF`. A file that does not decode is moved aside and the defaults are used; one that cannot be read is left alone. A part of a file that is damaged resets only that property.

About is reached from the settings and shows the name, version, copyright, "Free. Source available under PolyForm Noncommercial 1.0.0.", the links to alazy.app/pdf, the privacy page and support@alazy.app, and the notices file.

The Home tab leaves the Lazy Scan tile out when Lazy Scan is not installed; the tool tiles that cannot start without an open file stay in place with their reason under the title, and choosing one puts the reason in the status line instead of doing nothing.

`RecoveryStore` keeps each open document as `id.pdf` and `id.json` in `%LOCALAPPDATA%\Lazy PDF\Recovery`, written after every edit on a background worker. Closing or saving on purpose removes the entry. At start, entries whose process is gone are offered back as documents with unsaved changes, and a file that is already open comes back as a copy that needs a name. Leftovers (temporary files over an hour old, a pdf or json whose partner is missing for a day) are removed at start.

### The Store package

`store/windows/Package.appxmanifest` is the package manifest: `runFullTrust` and no other capability, minimum Windows 10.0.19041.0, the `lazypdf:` address as a protocol (outside the Store the Open with switch registers it), and `.pdf` and the picture types of `FileKinds` as file associations. The address and the file associations pass `"%1"` as one quoted argument, so a path with spaces stays whole. A file association adds an Open with entry; Windows keeps the default, and the manifest has nothing that claims it. The identity is three names taken from Partner Center (`PartnerCenterIdentityName`, `CN=PartnerCenterPublisher`, `PartnerCenterPublisherDisplayName`) that `scripts/make_msix.ps1` replaces. `scripts/make_store_assets.py` draws the tiles and logos in `store/windows/Assets` and the listing images in `store/windows/Listing`; `release.yml` publishes x64 and arm64 self-contained and packs them with the runner's `makeappx`.

Running packaged changes four things.
- The settings that write `HKCU\Software\Classes` are hidden, and `FileAssociation.SetForCurrentUser` does nothing: the manifest registers Open with and the address. A key written from inside the package would only be the package's own copy.
- Writes under `%APPDATA%` and `%LOCALAPPDATA%` (preferences, recent files, signing settings, recovery, thumbnails) go to the package's store for the user. The app reaches them at the same paths, and they go with an uninstall. Nothing else on the PC sees them.
- For that reason the copy of a document made for Lazy Print (`AppFolders.PrintCopies`) and the copies of attachments opened in another program (`AppFolders.OpenedAttachments`) are under `%TEMP%\Lazy PDF`, which the package does not redirect. Lazy Print reads the first by path.
- The exe's folder is read-only. Nothing writes there: Core touches no files, and every folder the app uses is under AppData or temp (`PackagingTests` checks it).

The single-instance mutex and pipe, the pipe to Lazy Print and the `lazyprint:` and `lazyscan:` addresses work the same: a full-trust process is not in an app container. A start from a file or a `lazypdf:` address gets it as the argument, which `App.FilesOf` reads. Settings made by an unpackaged copy are not carried over to the packaged one.

### Not done


- Phone capture and signing over the phone link: the address and mutex are reserved, nothing listens.
- Scanning into the open file: the Scan tile starts Lazy Scan and stops there.
- Turkish is the only translation.
- The package has been built with `makeappx` but not installed or signed, so the manifest's activation and the AppData redirection are known from the documentation, not from a run. The arm64 build has not been built.
- The Swift targets.

# Modules

Each section below is written when its layer lands.

### Filters

Stream filters, predictors and image sample decoding. Uses only `Syntax/`. Every `PdfObject` argument is already resolved (no references); where a reference can occur inside (a colour space array, a function), the caller passes a `Func<PdfObject?, PdfObject?>` resolver.

**`PdfFilters`** (static)
- `byte[] Decode(byte[] data, PdfObject? filter, PdfObject? parameters)` and `Decode(..., long maxSize)`. `filter` is a name or an array of names, `parameters` a dictionary or an array of dictionaries (entry i goes to filter i, a null entry is fine). Handles FlateDecode/Fl, LZWDecode/LZW (`/EarlyChange`), ASCIIHexDecode/AHx, ASCII85Decode/A85, RunLengthDecode/RL, CCITTFaxDecode/CCF, Crypt. Predictors 2 and 10-15 run after Flate and LZW.
- `Crypt` only passes through when `/Name` is absent or `/Identity`; any other name is `Unsupported` (decryption is the document layer's job, before this call).
- DCT, JPX and JBIG2 are image codecs: `Decode` throws `Unsupported` for them. Use `PdfDecodedStream DecodeToCodec(byte[] data, PdfObject? filter, PdfObject? parameters, long maxSize = DefaultMaxSize)`: it undoes the filters in front of the codec and returns `record PdfDecodedStream(byte[] Data, string? Codec, PdfDictionary? Parameters)`. `Codec` is `"DCTDecode"`, `"JPXDecode"` or `"JBIG2Decode"` (abbreviation expanded), `Data` the raw JPEG or JP2 bytes, `Parameters` that filter's `/DecodeParms`. With no codec in the chain `Codec` is null and `Data` is fully decoded.
- `byte[] Inflate(byte[] data[, long maxSize])`, `byte[] Predict(byte[] data, PdfDictionary? parameters)`. `const long DefaultMaxSize = 256 << 20` (256 MiB).
- Limits: output of any filter in the chain larger than `maxSize` throws `PdfReadException` with `Unsupported` (decompression bombs, a CCITT image whose `Rows * stride` is too big, one-bit rows that expand). Unknown filter: `Unsupported`. Bad ASCIIHex or ASCII85 characters, a /Filter that is not a name, a bad predictor bit depth: `Damaged`.
- Tolerance: Flate reads the deflate stream without checking Adler-32, so a bad or missing checksum, a cut-off tail, and data with no zlib header still give what decoded; nothing decoded is `Damaged`; a Flate stream that ends cleanly with no data decodes to an empty array, one that breaks off or is not deflate data with nothing decoded is damaged. LZW stops at a bad code, RunLength and the ASCII filters at a short tail. PNG rows with an unknown filter byte are left as they are. A last predictor row cut short is kept as far as it goes. Predictors work at 1, 2, 4, 8 and 16 bits and any `/Colors`.
- CCITT: `/K` below, at and above zero, `/Columns` (default 1728, 1 to 1048576), `/Rows` (0 = until the data ends; missing rows come out white), `/EncodedByteAlign`, `/EndOfLine` (EOLs are accepted either way), `/BlackIs1`. Output is packed rows, each byte aligned. A bad Group 4 code ends the data; Group 3 resynchronises at the next EOL.

**`PdfFilterEncoders`** (static)
- `Flate(ReadOnlySpan<byte>, CompressionLevel level = Optimal)`, `AsciiHex(ReadOnlySpan<byte>)` (ends with `>`), `Ascii85(ReadOnlySpan<byte>)` (ends with `~>`, no line breaks), `RunLength(ReadOnlySpan<byte>)`, `Lzw(ReadOnlySpan<byte>, bool earlyChange = true)`. All return `byte[]`; the writer sets `/Filter` itself.

**`PdfFunction`** (abstract, `Filters/PdfFunction.cs`)
- `static PdfFunction Parse(PdfObject? function, Func<PdfObject?, PdfObject?> resolve, Func<PdfStream, byte[]> decodeStream)`. Types 0 (sampled, up to 8 inputs, 1 to 32 bits, multilinear), 2, 3 and 4 (PostScript calculator, 100 stack entries, 32 nesting levels). An array of functions is read as one function with the outputs joined. `decodeStream` gives a stream's data with its filters undone.
- `int Inputs`, `int Outputs`, `void Evaluate(ReadOnlySpan<double> input, Span<double> output)`; input is clipped to `/Domain`, output to `/Range`. Another type is `Unsupported`; broken structure is `Damaged`, and so is a calculator that pops an empty stack or passes 100 entries, found at `Evaluate`.

**`PdfImageSamples`** (static)
- `PdfRgbaImage ToRgba(PdfDictionary image, byte[] samples, Func<PdfObject?, PdfObject?> resolve, Func<PdfStream, byte[]> decodeStream)`, `record PdfRgbaImage(int Width, int Height, byte[] Rgba, double DpiX = 0, double DpiY = 0)`: straight RGBA8, top row first. `TooBig` (empty `Rgba` with a real `Width` and `Height`) marks a frame a codec would not decode for its pixel count.
- `samples` are the image data with every filter undone, an image codec's too (the caller decodes JPEG or JPX to raw samples first). `decodeStream` is called for Indexed lookup streams, function streams, `/SMask` and `/Mask` streams, and must return their decoded samples likewise.
- Handles `/BitsPerComponent` 1, 2, 4, 8, 16, `/ImageMask` (black where painted, alpha 0 elsewhere), `/Decode`, DeviceGray/RGB/CMYK (plain (1-c)(1-k), no profile), CalGray (as gray), CalRGB, Lab, ICCBased (by `/N`, else `/Alternate`; the profile is not applied), Indexed (string or stream lookup), Separation and DeviceN through the tint function, colour key `/Mask` arrays, stencil `/Mask` streams, `/SMask` (`/Matte` ignored). A mask of another size is sampled nearest. Inline image keys (/W /H /BPC /CS /IM /D) and colour space names (G, RGB, CMYK, I) work. No `/ColorSpace` (JPX): gray, RGB or CMYK by sample count. Short data reads as zero.
- Limits: `Width * Height` over `PdfImageSamples.MaxPixels` (2^27) or a row over 2^26 samples is `Unsupported`, checked before any allocation. Missing size, a bad depth or colour space is `Damaged`; Pattern or an unknown space is `Unsupported`.

### Crypt

The standard security handler (ISO 32000-1 7.6, ISO 32000-2 for R 6). Uses Syntax only; strings and streams go in and out as byte arrays, and the Document layer decides which objects to pass. Files: `PdfSecurity.cs` (reading, decrypting, encrypting), `PdfSecurityCreate.cs`, `PdfKeys.cs`, `PdfPasswords.cs`, `Rc4.cs` (the last three internal).

```csharp
public sealed partial class PdfSecurity
{
    static PdfSecurity? Open(PdfDictionary encrypt, byte[] firstId, string? password);
    static PdfSecurity Create(string userPassword, string ownerPassword, PdfPermissions permissions,
                              PdfCryptStrength strength, byte[] firstId, Random? random = null);
    bool OpenedAsOwner { get; }
    PdfPermissions Permissions { get; }
    bool EncryptMetadata { get; }
    int Revision { get; }
    PdfDictionary Dictionary { get; }
    byte[] DecryptString(int number, int generation, byte[] data);
    byte[] DecryptStream(int number, int generation, byte[] data, PdfDictionary streamDictionary);
    byte[] EncryptString(int number, int generation, byte[] data);
    byte[] EncryptStream(int number, int generation, byte[] data, PdfDictionary streamDictionary);
}
[Flags] enum PdfPermissions { None, Print, Modify, Copy, Annotate, FillForms, ExtractForAccessibility, Assemble, PrintHighQuality, All }
enum PdfCryptStrength { Aes256, Aes128 }   // R 6 (default), R 4
```

**Reading.** V 1 R 2 and V 2 R 3 (RC4, 40 to 128 bits), V 4 R 4 (crypt filters V2, AESV2, Identity, with separate `/StmF` and `/StrF`), V 5 R 5 and R 6 (AESV3). User and owner passwords work on every revision; the owner is tried first. `Open` takes the `/Encrypt` dictionary fully resolved (`/CF` and its filters direct) and the first string of the trailer's `/ID`, and returns null for a wrong password. A null or empty password tries the empty user password. Passwords for R 2 to 4 are Latin-1 (UTF-8 outside it); for R 5 and 6 they are SASLprepped and cut at 127 bytes, and the NFKD form PDFKit uses is tried second. `/Perms` is not checked.

**Throws** `PdfReadException`: `Unsupported` for another `/Filter`, V or R outside the list above, an unknown `/CFM`, or a cipher that does not fit the revision (AESV3 below R 5, RC4 or AESV2 on R 5 and 6); `Damaged` for missing or short `/O`, `/U`, `/OE`, `/UE`, or a `/StmF` or `/StrF` naming a filter not in `/CF`. Decrypting never throws on bad data.

**Decrypting.** AES takes the IV from the first 16 bytes and drops a trailing partial block. A bad PKCS#7 tail is kept as decrypted, not rejected; data under 32 bytes gives an empty array. `DecryptStream` and `EncryptStream` return the input array itself, untouched, for `/Type /XRef`, for `/Type /Metadata` when `EncryptMetadata` is false, and for a `/Crypt` filter naming Identity (or no name). A `/Crypt` filter naming another `/CF` entry uses that entry's method. The stream dictionary's `/Filter` and `/DecodeParms` must be resolved. An Identity string or stream method also returns the input array.

**The caller's side.** The `/Encrypt` dictionary itself, the `/Contents` of a signature dictionary, and strings inside object streams are never encrypted; the object-stream container is decrypted as a whole. Stream data is decrypted before its filters run and encrypted after they have been applied. Keep the `/ID` the key was made with: for R 4 the first `/ID` string is part of the key.

**Writing.** `Create` makes R 6 (V 5, AESV3) or R 4 (V 4, AESV2) with `EncryptMetadata` true. `Dictionary` is the value for the trailer's `/Encrypt` (direct strings in hex; write it as an indirect object, itself unencrypted). `OpenedAsOwner` is true on a created handler. A real owner password is kept; an empty one becomes random bytes nobody knows, so the permissions bind everyone. `/P` gets its reserved bits set. Keys, salts and IVs come from `random` (a seeded `Random` gives the same file, for tests), else the system generator. `Encrypt*` on an opened file uses its keys, so an incremental update of an encrypted file writes objects the existing keys decrypt; AES IVs there are always from the system generator. Output was read back by pypdf with both passwords for both strengths.

**Limits.** Public-key handlers, V 3 and R 7 or higher are Unsupported. A handler holds no mutable state and can be shared between threads. R 6 hashing costs a few milliseconds per password try, and the key is derived once per `Open`.

**Tests.** `windows/LazyPDF.Core.Tests/Crypt/`: fixtures (`locked`, `owner-only-*`, and pypdf's `crypt-rc4-40`, `crypt-aes128`, `crypt-aes256-r5`, `crypt-aes256`, user `secret`, owner `owner`, in `Tests/Fixtures/Documents`), synthetic dictionaries for every revision, stream rules, malformed dictionaries, creation.

### Fonts/Tables: encodings, glyph names, Standard 14, CMaps

Folder `Fonts/Tables/`, namespace `LazyPDF.Core`, no dependency on other layers. The data (glyph list, AFM metrics, CJK CMaps) is compiled in as deflated base64 strings and decoded on first use; nothing is read from disk.

**`static class PdfEncodings`** (ISO 32000-1 Annex D). Each table is an `IReadOnlyList<string?>` of 256 glyph names by code, null where the encoding assigns none: `Standard`, `WinAnsi` (unused codes are `bullet`, 160 is `space`, 173 `hyphen`), `MacRoman`, `MacExpert`, `PdfDoc`, `Symbol`, `ZapfDingbats` (the last two are the fonts' built-in encodings).
`IReadOnlyList<string?>? ByName(string pdfName)` takes `StandardEncoding`, `WinAnsiEncoding`, `MacRomanEncoding`, `MacExpertEncoding`, `PDFDocEncoding`, else null. `int CodeOf(IReadOnlyList<string?> encoding, string glyphName)` gives the first code or -1.

**`static class GlyphList`** (Adobe Glyph List specification, AGL plus the ZapfDingbats list).
- `string? UnicodeOf(string glyphName)`: drops everything after the first period, splits on underscores, maps each component by list, `uniXXXX[XXXX...]` or `uXXXX[XX]`; surrogates and values above 10FFFF do not map; a component that maps to nothing is left out; null when nothing is left (`.notdef`, `g123`). Names over 256 characters give null. Multi-character results are possible (`fi`, `dalethatafpatah`).
- `string NameOf(int codePoint)`: the AGL name, preferring the names the Annex D encodings use (`space`, not `spacehackarabic`); else `uniXXXX` or `uXXXXX`; `.notdef` for what is not a scalar value.
- `string? ZapfNameOf(int codePoint)`: the `a1`-style name, or null.

**`sealed class Standard14`**, with `readonly record struct FontBox(int Left, int Bottom, int Right, int Top)`.
- `static IReadOnlyList<Standard14> All` (14 fonts), `static Standard14? Find(string baseFont)`.
- `Find` ignores a subset tag, case, spaces, commas and the `PS` and `MT` of Windows names: Arial, ArialMT, Arial,Bold, Arial-BoldItalicMT, TimesNewRoman, TimesNewRomanPS-BoldMT, CourierNew, SymbolMT and so on map to the AFM font. Other faces (Arial Narrow, Arial Black) give null, they are not metric-compatible.
- Members: `Name`, `Ascent`, `Descent` (negative; the AFM Ascender/Descender, or the box top and bottom for Symbol and ZapfDingbats), `FontBox BBox`, `CapHeight`, `XHeight` (0 for Symbol and ZapfDingbats), `double ItalicAngle`, `StemV`, `IsFixedPitch`, `IsBold`, `IsItalic`, `IsSerif`, `IsSymbolic`, `Flags` (FontDescriptor /Flags), `BuiltInEncoding`, `int? WidthOf(string glyphName)` in 1/1000 em, null when the font has no such glyph. No kerning, no per-glyph boxes.

**`sealed class CMap`**
- `static CMap Parse(byte[] data, CMap? useCMap = null)`: reads an embedded CMap or ToUnicode stream: codespacerange, cidrange, cidchar, notdefrange, notdefchar, bfrange (string and array forms), bfchar (hex or glyph name), `/Name usecmap`, `/WMode`, `/CMapName`. Never throws; a malformed section is skipped from the bad entry on. Pass the stream dictionary's /UseCMap as `useCMap`. Bounds: linear in the data, at most 1,000,000 mappings and 100 codespace ranges kept, a destination string is cut at 128 UTF-16 units, hex codes longer than four bytes are skipped. Later mappings win over earlier overlapping ones. With no codespace given, any byte value at the lengths the mappings use is accepted.
- `static CMap Predefined(string name)`: `Identity-H`, `Identity-V`, and 61 of Adobe's CID CMaps (Adobe cmap-resources, BSD-3): GB (GB-EUC, GBpc-EUC, GBK-EUC, GBKp-EUC, GBK2K, UniGB-UCS2/UTF16), CNS (B5pc, ETen-B5, ETenms-B5, HKscs-B5, CNS-EUC, UniCNS-UCS2/UTF16), Japan (83pv, 90ms, 90msp, 90pv, Add, Ext-RKSJ, EUC, H, V, UniJIS-UCS2/UCS2-HW/UTF16), Korea (KSC-EUC, KSCms-UHC, KSCms-UHC-HW, KSCpc-EUC, UniKS-UCS2/UTF16), with their -H and -V forms. Instances are cached and shared; do not mutate. Not included: the `Adobe-*-UCS2` CID to Unicode maps and the `Adobe-*-N` ones. An unknown name returns a fallback with `IsFallback` true: two-byte codes, CID equal to the code. Callers decide whether to warn.
- `int NextCode(ReadOnlySpan<byte> bytes, out int length)`: ISO 32000-1 9.7.6.3, shortest prefix inside a codespace range, mixed lengths allowed. Bytes matching no range consume as many bytes as the shortest range that starts like them (else the shortest range), so a string stays in step. Empty input gives length 0. Codes are up to four bytes; a four-byte code above 0x7FFFFFFF is a negative int.
- `int? CidOf(int code)`, `int? CidOf(int code, int length)`: the CID, a notdefrange's id for unmapped codes in one, else null. Without the length the shortest code length with a mapping is taken, so <41> and <0041> clash; pass the length from `NextCode` when the CMap has mixed lengths.
- `string? UnicodeOf(int code)`, `string? UnicodeOf(int code, int length)`: bfchar and bfrange text, may be several characters or a surrogate pair. For the `Uni*-UCS2` and `Uni*-UTF16` predefined CMaps the code itself is the Unicode value and is returned.
- `Name`, `IsVertical` (WMode 1), `IsFallback`.

**`static class ToUnicodeCMap`**: `byte[] Write(IEnumerable<KeyValuePair<int, string>> map, int codeBytes = 2)` returns the stream body (ASCII): the usual CIDInit preamble, one codespace range 0 to FF..FF of `codeBytes` (1 to 4), bfrange for runs where code and the last UTF-16 unit both step by one without a low-byte wrap, bfchar for the rest, 100 entries at most per section, UTF-16BE text. Last text for a duplicate code wins, empty text is dropped. A code outside the byte length or `codeBytes` outside 1 to 4 throws `ArgumentOutOfRangeException`. The caller sets /Length and any filter.

### Fonts/Programs: font programs and embedding

Parsers over `byte[]` for the three font program formats a PDF holds, a TrueType subsetter and the builder that turns text into the pieces of an embedded font. No `PdfDocument`, no `Syntax` types, no other `Fonts/` folder. A damaged program gives zeros, empty outlines or a null, never an exception; every count read from a file is bounded by the data. Glyph names are plain strings.

**Outlines.** `GlyphOutline.Segments` is a list of `OutlineSegment(Op, X, Y, X1, Y1, X2, Y2)` in font units, y up. `Op` is `Move`, `Line`, `Quad` (control point X1,Y1), `Cubic` (X1,Y1 and X2,Y2) or `Close`. `Bounds()` gives a `GlyphBounds(XMin, YMin, XMax, YMax)` over all points, null when empty.

**`TrueTypeFont`** reads sfnt files, TrueType or OpenType/CFF.
- `static int CollectionCount(byte[])` is 1 for a plain file, n for a .ttc, 0 for no sfnt. `static TrueTypeFont? TryParse(byte[], int collectionIndex = 0)` is null without usable head and maxp.
- Metrics in font units: `UnitsPerEm`, `GlyphCount`, `Ascent`, `Descent` (negative), `LineGap`, `CapHeight` (OS/2, else the box of H), `XHeight`, `FontBounds`, `ItalicAngle`, `IsFixedPitch`, `WeightClass`, `FamilyName`, `PostScriptName`.
- `GetAdvance(gid)`, `GetBounds(gid)` (null for a blank glyph), `GetOutline(gid)` (composites resolved; null for a glyph that does not exist).
- `GlyphForCodePoint(cp)` is 0 when absent. It uses cmap (3,10), (0,x), (3,1) in that order, and for a font with only a (3,0) symbol table tries the code and 0xF000 + code. Also `GlyphForCmap(platform, encoding, code)`, `HasCmap`, `GlyphForVariation(cp, selector)` (format 14).
- `GlyphName(gid)` and `GlyphForName(name)` read post formats 1 and 2, else the CFF charset. The Windows system fonts have post format 3 and no names.
- `FsType`, `EmbeddingAllowed` (false for fsType 0x0002 and 0x0200), `SubsettingAllowed` (false for 0x0100). `Cff`, `IsCff`, `HasOutlines`, `HasTable(tag)`.

**`CffFont`** reads a bare CFF (FontFile3 /Type1C, /CIDFontType0C) or the 'CFF ' table of an OpenType font. `TryParse(byte[])` and `TryParse(byte[], offset, length)` copy the bytes and return null on a broken file.
- `Name`, `IsCid`, `GlyphCount`, `FontMatrix`, `FontBounds`, `GetWidth(gid)`, `GetOutline(gid)` (Type 2 charstrings including subroutines, hint masks, flex, arithmetic and seac-style endchar).
- Name-keyed: `GlyphName`, `GlyphForName`, `GlyphForCode(code)` through the built-in encoding. CID-keyed: `GlyphForCid(cid)` and `CidForGlyph(gid)`; per-glyph FDSelect widths. A name-keyed font used as a CIDFont takes CID = gid (9.7.4.2).
- Limit: the predefined Expert charsets and Expert encoding are not tabulated; they read as identity or empty.

**`Type1Font`** reads PFA (hex or binary eexec), PFB and a FontFile stream. `TryParse(byte[])` is null when no charstring is found.
- `FontName`, `FontMatrix`, `FontBounds`, `BuiltInEncoding` (name per code, null where none; `StandardEncoding` is expanded), `GlyphNames` in file order, `HasGlyph`, `GetWidth(name)`, `GetOutline(name)` (Subrs, flex, hint replacement, div, seac, sbw; lenIV honoured, RD/-| both).

**`TrueTypeSubsetter.Subset(byte[] font, IReadOnlyCollection<int> glyphIds, int collectionIndex = 0)`** returns `SubsetResult(Status, Data, GlyphMap)`.
- Glyphs are renumbered densely in the order of the old IDs; .notdef stays 0; `GlyphMap` is old to new. A PDF font from it uses the new ID as the character code and `/CIDToGIDMap /Identity`. Composite glyphs bring their components; unknown IDs are ignored.
- Glyph programs are copied as they are, so cvt, fpgm and prep stay; nothing else of the hinting is dropped. Output tables: head, hhea, maxp, hmtx, loca, glyf, OS/2, post (format 3), name, and the three hinting tables if present. No cmap. Checksums and the head adjustment are set; tables are sorted and 4-byte aligned.
- `Status` is `Ok`, `Unreadable`, `NotTrueType` (CFF or no glyf), `EmbeddingForbidden`, `SubsettingForbidden`. Data and map are empty unless Ok.

**No CFF subsetter.** An OpenType font with CFF outlines is embedded whole as `/FontFile3 /Subtype /OpenType` under a `/CIDFontType0` descendant; a CFF that is not CID-keyed uses CID = glyph ID, so no `CIDToGIDMap`.

**`EmbeddedFontBuilder.Build(byte[] font, IEnumerable<string> texts, out EmbedStatus status, int collectionIndex = 0)`** returns an `EmbeddedFont?`, null with `status` `Unreadable`, `NoOutlines` or `EmbeddingForbidden`. Characters are the Unicode scalar values of the texts (below U+0020 skipped).
- TrueType: subset, code = new glyph ID, `IsSubset` true, `IsCff` false (`/CIDFontType2`, `/FontFile2`, Identity CIDToGIDMap). A TrueType font with `SubsettingAllowed` false, and any CFF font, is passed through whole with code = glyph ID, `IsSubset` false. A collection is subset by index but never passed through (null).
- `BaseFont` carries a six-letter tag, derived from the glyph list, when subset. `Program` is the file bytes.
- `Codes` maps code point to code; `Missing` lists code points with no glyph (they encode as 0). `Encode(string)` gives the two-byte codes of Identity-H. `ToUnicode()` gives code to code point for the /ToUnicode CMap; characters sharing a glyph keep the lowest code point.
- `Widths` are `WidthRun(FirstCid, Widths)` in 1/1000 em, one `/W` entry each, consecutive codes merged; `DefaultWidth` 1000. `Descriptor` is `FontDescriptorValues(Flags, FontBBox, ItalicAngle, Ascent, Descent, CapHeight, StemV)` in 1/1000 em; flags are Nonsymbolic, plus FixedPitch and Italic when they apply; StemV is estimated from the weight class.
- Turkish ğ Ğ ş Ş ı İ go through this path like any other character; WinAnsi is not involved.

### Document: reading

`PdfDocument : IDisposable` (partial, `Document/`) holds a file as one `byte[]` (Open does not copy it; do not change it while the document is open). Not safe to share between threads. Objects load on first use and are cached, so `Get(n)` returns the same instance every time and an edit to it stays.

**Opening.** `static PdfDocument Open(byte[] bytes, string? password = null)` and `Open(string path, string? password = null)`. Throws `PdfReadException` only: `NotPdf` (no `%PDF-` in the first 1024 bytes), `Damaged` (no catalog and no pages anywhere), `Unsupported` (a handler or filter we lack), `PasswordRequired` (new in `PdfReadProblem`: the password does not open the file; a null password tries the empty one). Bytes before the header are cut off, so offsets count from `%PDF` and `Length` is the size after the cut.

**Repair.** If the cross-reference data fails (no or wrong `startxref`, broken `/Prev`, missing trailer, truncation, a catalog that does not resolve) the file is scanned once for `n g obj` and trailers, the newest definition of each object wins, object streams are read and the catalog is found by `/Type /Catalog`, or made from the page tree, or the page tree from the `/Type /Page` objects. Offsets slightly off are fixed object by object when it is loaded. A wrong or missing `/Length` is fixed at `endstream`, a missing `endobj` is no problem. `IReadOnlyList<string> Repairs` says what was done (at most 100 lines, set as it happens: stream and page repairs appear when the stream or page is first used). Linear in file size.

**Members.** `Trailer`, `Catalog` (never null), `Info` (`PdfDictionary?`), `Id` (`IReadOnlyList<byte[]>`), `Version` (header or catalog `/Version`, the newer), `Length`, `IsEncrypted`, `PdfSecurity? Security`, `IsSigned`, `IsCertified`, `HasXfa`, `IsLinearized`, `IsTagged`, `int? PdfAPart`, `string? PdfAConformance`.

**Objects.** `PdfObject? Get(int number)` (null if free, unlisted or unreadable), `PdfObject? Resolve(PdfObject?)` (follows 32 hops, null for null or a loop), `T? Resolve<T>(PdfObject?)`, `IReadOnlyList<int> ObjectNumbers`. Typed helpers take a dictionary and a key, resolve, and return null on a type mismatch: `Dict`, `Array`, `Stream`, `Name` (string), `Bool`, `Number` (double?), `Integer` (long?, accepts 90.0), `Rect` (also takes a `PdfObject?`; corners in any order, null if no area). `PdfReference Add(PdfObject)` (new number, generation 0), `void Set(int number, PdfObject)`, `void Delete(int number)`.

**Streams.** `byte[] RawData(PdfStream)`: decrypted, still filtered. `byte[] Data(PdfStream)`: decrypted and decoded; `/Length`, `/Filter`, `/DecodeParms` are resolved first, then `PdfFilters.Decode`. `PdfStream` now has `Data` (`byte[]?`, settable: the bytes to store, filtered, not encrypted; null while the data is in the file), `Number`, `Generation`, and a constructor `PdfStream(PdfDictionary, byte[])`. When `Data` is set, `RawData` returns it.

**Encryption.** `PdfSecurity.Open` gets the fully resolved `/Encrypt` and the first `/ID` string; null from it means wrong password. Strings are decrypted in place as their object loads (`PdfString.Bytes` is settable), except in object streams, in `/Encrypt` and in a signature's `/Contents`. Objects in memory are therefore always plain: the saver encrypts again with `Security`, using the object's number and `GenerationOf(number)`.

**Pages.** `IReadOnlyList<PdfPage> Pages`, walked from the catalog tolerantly (loops, wrong `/Count`, missing `/Type` or `/Parent`, junk in `/Kids`, depth 256; a tree with no pages falls back to the page objects in the file, the first time only). `PdfPage`: `Dictionary`, `Reference`, `Index`, `Resources` (inherited), `MediaBox` (US Letter if unusable), `CropBox` (clipped to the media box), `TrimBox`, `BleedBox`, `ArtBox` (default the crop box), `Rotate` (0, 90, 180, 270), `UserUnit`, `byte[] Contents()` (streams joined by `\n`; one that fails is left out and noted in `Repairs`). Properties read the live dictionary; only what a page inherits was taken at the walk. After changing the tree call `internal RefreshPages()`.

**Geometry.** `PdfRect(x1, y1, x2, y2)` is normalized (`Left Bottom Right Top`, `Width`, `Height`, `IsEmpty`, `Intersect`, `ToArray`). `PageGeometry(PdfPage)` or `(PdfRect box, int rotate, double userUnit = 1)`: `Width`, `Height` (display points), `Rotation`, `Matrix` (user to display), `ToDisplay(x, y)`, `ToUser(x, y)`, and the same for rects (`DisplayRect(X, Y, Width, Height)`, top-left origin).

**For the saver (internal).** Every loaded object keeps a fingerprint of its text as read (after decryption); a save finds changes by comparison, nothing to call. `ChangedObjects()` gives the numbers, ascending, of loaded objects whose text differs, whose stream has `Data` set, or that were made by `Add`/`Set`. `DeletedObjects` gives numbers freed. `TrailerChanged` compares the trailer. Also `StartXref` (0 after a rebuild), `XrefIsStream`, `XrefRebuilt` (after it the old table is useless: write a full one), `NextObjectNumber`, `GenerationOf(n)`, `Source` (the bytes). A stream is compared by its dictionary and `Data` only, so to change one, set `Data`.

**Syntax changes.** `PdfDictionary` has `Count`, `Remove`, a key index past 12 entries; `PdfNumber(double)`; `PdfString.Bytes` and `IsHex` settable. The lexer is more forgiving (odd numbers, unclosed arrays and dictionaries at `endobj`, stray keys and hex digits). `Syntax/` is split into `PdfSyntax.cs`, `PdfBytes.cs`, `PdfLexer.cs`. A name's Value is its bytes one char each; `FromText` and `Text` convert to and from UTF-8, and a char above 0xFF written directly is escaped as its UTF-8 bytes, and then so is every other non-ASCII char of that name. XFDF reads and writes names such as `icon` through `FromText` and `Text`.

### Document: writing

**Incremental.** `byte[] PdfDocument.SaveIncremental()` returns the bytes read followed by an update (ISO 32000-1 7.5.6); the original bytes are never touched, which signatures rest on. Only changed or added objects are written (found by comparison with what was read, see "For the saver" above), plus free entries for deleted ones. The section is a classic table when the newest one in the file is a table (a hybrid file too: the older `/XRefStm` stays reachable through `/Prev`), a cross-reference stream when it is a stream. The trailer carries every key the file's has, `/Size`, `/Prev`, a new `/ID` (first string kept, second fresh; both fresh when there was none). An object that came from an object stream is written as a plain one. Strings and streams are encrypted again with `Security`, except the `/Encrypt` object, a signature's `/Contents` and the cross-reference stream. After a rebuild (`XrefRebuilt`) the section lists every object and has no `/Prev`; so does the update after 4096 sections. With no change the result is the bytes read. A file with bytes before `%PDF` loses them (offsets count from the header). Edits to the document stay in memory until saved; saving does not reset the change tracking, so reopen the result (`PdfDocument.Open`) to edit on.

**Rewrite.** `byte[] PdfDocument.SaveRewrite(PdfSaveOptions? options = null)` writes a new file of the objects reachable from `/Root` and `/Info`, numbered from 1 in the order met (catalog first), generation 0, references to missing objects dropped, no history. `PdfSaveOptions(bool UseObjectStreams = false, PdfSecurity? Security = null, byte[]? DocumentId = null)`: `UseObjectStreams` packs plain objects 100 to a stream and writes a Flate cross-reference stream (header 1.5 at least; the catalog, streams and signature dictionaries stay plain, because PdfPig asks for the catalog before it can decrypt). `Security` encrypts the output; null leaves it open, so an encrypted document written with null is decrypted, and `document.Security` keeps its encryption (and its first `/ID`, which the older handlers' keys are made from). A handler from `PdfSecurity.Create` for `Aes128` must have been given the same first id as `DocumentId`. Header is raised to 1.6 for R 4 and 1.7 for R 6. A new `/ID` otherwise. Streams with no filter, or only LZW, ASCII85, ASCIIHex or RunLength, are deflated when that is smaller; Flate streams, streams with a predictor, DCT, JPX, JBIG2, CCITT, Crypt filters and metadata are copied as stored; a stream that does not decode is copied as it is. Signatures do not survive a rewrite; the app checks `IsSigned` first. No linearization. `byte[] SaveRewrite(PdfSaveOptions? options, out int dropped, CancellationToken cancel = default)` writes the same bytes and says in `dropped` how many objects the walk reached that the table lists (in use or in an object stream) but that could not be read and so are left out (a page, image or font that vanishes); a free or unlisted object, such as a trailer entry naming one, is not counted. No app shows this count yet.

**Safe save.** `static void PdfFileSaver.Save(string path, byte[] bytes, string? password = null)`: writes a hidden temporary file in the same folder, flushes it, reads it back, checks the bytes are equal and `PdfDocument.Open` takes them, then `File.Replace` (a rename where the file system has no ReplaceFile), keeping attributes and creation time. Any failure deletes the temporary file and leaves the original. Throws `IOException`, `UnauthorizedAccessException` (a read-only file is not replaced) or `PdfReadException`.

**Edit session.** `PdfEditSession` holds a file as one growing buffer. `Open(byte[] bytes, string? password = null)`, `Open(string path, string? password = null)` (`PdfReadException` as the reader). `PdfDocument Document` is the document to edit; `ReadOnlyMemory<byte> Current` is the committed bytes, a complete valid PDF, replaced by a new array (never changed in place) on every commit, undo and redo, so a renderer may keep what it holds. `bool Commit(string label, bool mergeWithPrevious = false)` writes `Document`'s changes as one incremental update (with `mergeWithPrevious` it joins the step before it, so both undo and redo together, for consecutive form-field fills; refused, and a step of its own, when there is no step before, the step before was saved, or its label differs), drops the redo steps, reopens `Document` on the new bytes (any page or object held from the old one is stale) and returns false, adding nothing, when nothing changed; the new bytes are read back before they are taken. `bool Undo()` and `bool Redo()` move the end to the previous or next `%%EOF` of the session's own steps and drop uncommitted changes; history never reaches before the file as opened. `CanUndo`, `CanRedo`, `UndoLabel`, `RedoLabel` (null when none). `bool IsDirty`: the position differs from the last save or open, or `Document` holds uncommitted changes (a file the reader had to repair is dirty from the start). `void Save(string path)` commits what waits as a step with an empty label, then `PdfFileSaver.Save`. `void SaveCompact(string path)` writes `SaveRewrite` (object streams unless PDF/A-1, encryption kept) and continues from that file with no undo history. The buffer exists twice in memory (`Current` and the longest state after an undo); a commit copies it once.

**Versions.** `IReadOnlyList<PdfVersion> Versions`, oldest first, of the file as opened: `PdfVersion(int Number, int End)`, `End` the byte length of that state, found by following the cross-reference sections back and taking the `%%EOF` whose `startxref` names each one (so a `startxref` inside stream data, or a linearized file's first-page section, does not count). A rebuilt file has none. `byte[] ExtractVersion(PdfVersion)` is the file cut at `End`; `void SaveVersion(PdfVersion, string path)` writes it by `PdfFileSaver`.

**Limits.** Files up to 2 GB (`byte[]`). Object streams hold 100 objects. Whole files are built in memory.

### Review fixes

Changes to behaviour and limits in the layers above after review. No public signature was removed; two members were added to the internal surface and `PdfFileSaver` gained an internal overload.

**Limits (rule 4).**
- An object that needs another object to load (a `/Length`, an object stream, an object stream inside an object stream) nests at most 32 deep; past that the object reads as null.
- `Flatten`, which resolves `/Filter`, `/DecodeParms` and `/Encrypt`, stops after 4096 values; the rest reads as null.
- `PdfFunction.Parse` parses an object shared by several functions once. A function has at most 64 outputs, `/Domain` and `/Range` must have each min at most max, and a type 0 sample count that would pass 2^34 bits is damaged.
- Predictor `/Colors` above 65536 is damaged.
- A decoded object stream may not pass 64 MB, nor `/Metadata` 16 MB, nor the streams of one page 256 MB together; the stream over the limit is dropped with a repair, not thrown. Cached object streams are capped at 256 and 128 MB together.
- A CFF font reads at most 256 font DICTs, each cut to 64 KB; a TrueType composite may build 100000 points in all.
- A `/Size` past the object number limit is ignored, and an `/Index` entry past it makes the cross-reference stream damaged.

**Reading.**
- `PdfDocument.Data` strips the Crypt stage of an encrypted file's `/Filter` once decryption has done it, so `[/Crypt /FlateDecode]` with `/Name /StdCF` decodes.
- The standard security handler reads `/EFF`: a stream of `/Type /EmbeddedFile` without a Crypt filter uses it, not `/StmF`. AES-128 with a key that is not 128 bits is `Unsupported` when the handler opens.
- A trailer key older sections would supply is not removed by leaving it out. `PdfUpdate` writes `/Info null` after the `/Info` of a file was taken out.
- Repair scans a value after `trailer` that is not a dictionary once; running out of object numbers while repairing is a `PdfReadException`.
- `PdfDocument.Set` copies file-backed stream data into `Data` before the stream takes its new number.

**Writing.**
- The cipher for a stream is chosen from the same resolved `/Filter` and `/DecodeParms` on writing as on reading (`PdfObjectWriter.WriteStream` takes the resolved view).
- Updates and rewrites keep the first `/ID` string the file key was made from (`PdfDocument.FirstId`); an indirect `/ID` no longer gives a garbled one. An unencrypted rewrite keeps the first string unless `PdfSaveOptions.DocumentId` gives another; the second is always fresh.
- `SaveRewrite` keeps the pages `Pages` shows even when the tree does not reach them, drops a Crypt filter when the handler changes or goes, and keeps the original bytes of a stream whose Flate data does not decode to a clean end (`Data` with `strict`).
- An update to a file with an xref stream throws `InvalidOperationException` when no object number is left for the stream itself.
- `SaveIncremental` and `PdfEditSession.Save` work from the bytes read, so anything before `%PDF` is gone from the result.

**Safe save.** `PdfEditSession` saves through `PdfFileSaver.Save(path, bytes, password, source, samePages)` (internal): the read-back is refused when it needed a rebuild the source did not, and, except for `SaveVersion`, when the page count differs. `Commit` refuses an update that reads back rebuilt, and an update that would make the file longer than 2 GB. Once the swap is done a failure to restore attributes or creation time is ignored. `Redo` drops uncommitted changes as `Undo` does.

### Content: parsing, writing, interpreting, fonts

Folder `Content/`, uses Document and Fonts. No user-visible text. Nothing here throws on file contents except `PdfReadException` from stream decoding; every loop and recursion has a cap.

**`ContentParser.Parse(byte[]) -> IReadOnlyList<ContentOperation>`** (ISO 32000-1 7.8.2, Annex A). Linear, about a million operations a second. `ContentOperation`: `Operator`, `Operands` (`PdfObject`s: numbers keep their text, strings their bytes and hex flag), `Start`/`End` (byte range from the first operand to just past the operator, so `source[..Start] + source[End..]` cuts it), `Image` (for `BI`), `Number(i)`. Tolerance: unknown operators stay and clear their operands, stray `) ] > { }` are skipped, an unclosed array or dictionary ends at the next known operator, `--5` is -5, `1.2.3` is 1.2 then .3, comments, `true false null` are operands. At most 512 operands per operator, 64 levels of nesting, operator names cut at 32 characters. Inline images: `InlineImage(Dictionary as written, Data)`; the end is found by the computed length when width, height, depth and a device space say it and no filter is set, else by `EI` between white space with ASCII text after it that starts a known operator; no `EI` runs to the end. `Expanded(Func<string, PdfObject?>? colorSpace)` gives full key names (`W`->`Width`...) and looks up named colour spaces.

**`ContentWriter`**. `static byte[] Write(IEnumerable<ContentOperation>)` writes operations one per line; parsing the result gives the same operators and operands (inline image data byte for byte). Instance builder, each call returns the writer: `Op(name, IReadOnlyList<PdfObject>)`, `Op(name, params ReadOnlySpan<double>)`, `Add(op)`, `Raw(text)`, `Save`, `Restore`, `Concat(PdfMatrix)`, `Rect`, `MoveTo`, `LineTo`, `CurveTo`, `Close`, `Fill`, `FillEvenOdd`, `Stroke`, `FillAndStroke`, `EndPath`, `Clip`, `LineWidth`, `Dash`, `FillGray/Rgb/Cmyk`, `StrokeGray/Rgb/Cmyk`, `GraphicsState(name)`, `BeginText`, `EndText`, `Font(name, size)`, `MoveText`, `TextMatrix`, `TextRenderMode`, `CharSpacing`, `WordSpacing`, `Show(ReadOnlySpan<byte>)` (hex string), `Paint(name)`, `Paint(name, PdfMatrix)` (q cm Do Q), `BeginMarked(tag[, mcid])`, `EndMarked`; `ToArray()`, `Length`. Numbers go through `PdfNumber(double)`: at most six decimals, no exponent, invariant.

**`PdfMatrix(A..F)`** record struct: `Identity`, `Translate`, `Scale`, `Multiply(m)` (this first, then m), `Transform(x, y)`, `Transform(PdfRect)` (bounding box), `Invert()`, `Determinant`, `ScaleFactor`, `FromArray`.

**`ContentInterpreter(PdfDocument)`**. `Run(PdfPage, ContentVisitor)` starts in the page's user space with its crop box as the clip; `Run(PdfStream form, ContentVisitor, PdfMatrix? = null)` runs one form. `WalkPatterns` (default true) runs a tiling pattern's cell once per run, on first paint with it. `IsTruncated` is set when the run hit 10 million operations. Limits: q stack 256 (deeper ones are counted so `Q` still pairs), form depth 20, 1024 marked-content levels, 1,000,000 segments a path, a form's data 64 MB; a form already running is skipped; a form that does not decode is empty. Resources are looked up in the current stream's, then the enclosing ones'. Clip is the bounding box only. Type 3 glyph procedures and text clip modes (Tr 4-7) are not run; invisible text (Tr 3) is reported.

**`ContentVisitor`** (abstract, all virtual no-ops): `ShowGlyph(ctx, in GlyphInfo)`, `PaintPath(ctx, PathInfo)`, `PaintImage(ctx, ImageInfo)`, `PaintShading(ctx, ShadingInfo)`, `BeginMarked/EndMarked(ctx, MarkedContent)`, `BeginForm/EndForm(ctx, FormInfo)` (patterns too, `IsPattern`). `ContentContext` is the interpreter's live object: `State` (`GraphicsState`), `Forms` (the `PdfStream` chain, outermost first, empty on the page), `OperatorIndex` and `Operation` (index into `ContentParser.Parse(page.Contents())` for the page, or of `document.Data(form)` for `Forms[^1]`), `Marked` (open sequences), `Mcid`, `OptionalContent`, `TextMatrix`, `TextLineMatrix`. Copy what you keep; the objects change as the walk goes.
- `GlyphInfo`: `Character` (`FontChar`), `Code`, `Unicode`, `Font`, `Matrix` (em square to the starting space: the text rendering matrix, a vertical font's origin shift included), `Bounds` (advance by ascent and descent, in the starting space), `Advance` (text space shift, spacing and Tz included), `Element` (operand index; the array item for `TJ`; 1 for `"`), `Offset` (byte position of the code in that string).
- `PathInfo`: `Operator` (S s f F f* B B* b b* n; `n` only when a clip is pending), `Segments` (`PathSegment(Kind Move/Line/Curve/Close, X1..Y3)`, already transformed), `Bounds` (control points count), `InkBounds` (plus half the line width), `Fill`, `Stroke`, `EvenOdd`, `Clips`. A tiling pattern's cell follows the path that first used it.
- `ImageInfo`: `Name`, `Stream` or `Inline`, `Dictionary` (full keys), `Width`, `Height`, `IsMask`, `Matrix` and `Bounds` of the unit square, `OptionalContent`. `ShadingInfo(Name, Shading, Bounds)`. `FormInfo(Stream, Name, Matrix, Bounds, IsPattern, OptionalContent)`. `MarkedContent(Tag, Properties, Mcid, OptionalContent)` (`OptionalContent` set for tag `OC`).
- `GraphicsState`: `Ctm`, `Clip`, `FillColor`, `StrokeColor` (`PdfColor`: `Space`, `Components`, `PatternName`, `Pattern`, `Rgb`), line width, cap, join, miter, `Dash`, `DashPhase`, `CharSpacing`, `WordSpacing`, `HorizontalScale` (1 = 100%), `Leading`, `Font`, `FontSize`, `RenderMode`, `Rise`, `FillAlpha`, `StrokeAlpha`, `BlendMode`, `SoftMask`. `ColorSpaceInfo`: `Family`, `Components`, `Definition`, `Base`, `ToRgb`; colour conversion is profile-free (Filters).

**`PdfFont.Get(document, fontDictionary)`**, cached per dictionary. Type1, MMType1, TrueType, Type3, Type0 over CIDFontType0 and 2. Members: `Subtype`, `BaseFont`, `Name` (no subset tag), `IsComposite`, `IsType3`, `IsVertical`, `IsEmbedded`, `HasToUnicode`, `Descriptor`, `Flags`, `IsBold/IsItalic/IsFixedPitch/IsSerif/IsSymbolic`, `Ascent`, `Descent`, `CapHeight` (1/1000 em), `FontMatrix`, `FontBBox`. `int Read(ReadOnlySpan<byte>, out FontChar)` takes the first character and returns the bytes used (always at least 1 for non-empty input); `Decode(span)`, `ToText(span)`. `FontChar(Code, Length, Cid, Width, Unicode, IsSpace, VerticalAdvance, OriginX, OriginY)`, widths in 1/1000 em (Type 3 scaled by its matrix).
- Simple fonts: `/Encoding` name or dictionary with `/BaseEncoding` and `/Differences`; without a base the font program's own encoding (embedded or symbolic Standard 14), else WinAnsi for TrueType and Standard for the rest. Width order: `/Widths`, then `/MissingWidth`; with no `/Widths` the Standard 14 metrics by glyph name, the font program, then Helvetica, Times or Courier metrics by flags.
- Composite fonts: `/Encoding` predefined or embedded CMap (`/UseCMap` one level), `/W`, `/DW`, `/DW2`, `/W2`, `/CIDToGIDMap`, at most 300,000 width entries.
- Unicode order: ToUnicode; the encoding's glyph name through `GlyphList`; for Uni* CMaps the code; the Adobe collection's Unicode CMap reversed (Japan1, GB1, CNS1, Korea1, incl. half-width); a TrueType cmap reversed (private use area skipped) then post names; the CFF or Type 1 glyph name. Null when none gives text.

**`PdfFontEmbedder(PdfDocument, IFontSource? = null)`**. `IFontSource.Find(family, FontStyles) -> FontFile?` (`FontFile(byte[] Data, int CollectionIndex = 0)`; `FontStyles` Regular, Bold, Italic). `PdfDrawFont? Add(family, style, IEnumerable<string> texts, bool embed = false)` adds a font object to the document: a Standard 14 Type1 with WinAnsi (Arial, Times New Roman and Courier New map to them) when every character fits and `embed` is false, else a subset Type0 font with Identity-H, `/W`, `/DW`, descriptor, `/FontFile2` (or `/FontFile3` OpenType) and `/ToUnicode` from `EmbeddedFontBuilder`; null without a usable file or when embedding is forbidden. Each call adds a new font holding the characters of its texts; give it all the text it will draw. `PdfDrawFont? AddCovering(family, style, texts)` is `Add` for text that may not fit the family: for text that fits WinAnsi it is just `Add` (null when the family gives no font, so the caller's Helvetica retry runs), else it builds a subset for `family` and then for each of the static `FallbackFamilies` (Arial, Segoe UI, Microsoft YaHei, Yu Gothic, Malgun Gothic, Arial Unicode MS, PingFang SC, Hiragino Sans, Apple SD Gothic Neo), stops at the first with no `Missing`, else takes the one with the fewest (the earlier wins a tie), and adds only that one to the document; one font draws the whole text. `PdfDrawFont`: `Reference`, `IsEmbedded`, `Missing`, `Encode(string)` (bytes for `Tj`), `Width(text, size)`, `Wrap(text, size, maxWidth)` (at spaces, at `\n`, a long word at the character), `Ascent`, `Descent` (em), `LineHeight(size)`.

**Helpers.** `ContentResources.ForEdit(document, page)` is the page's own `/Resources` (an inherited one copied onto the page); `Add(document, resources, category, value, prefix)` returns the new unused name. `ContentImages.AddRgba(document, w, h, rgba)` (Flate, `/SMask` when any alpha is below 255) and `AddJpeg(document, bytes)` (DCT as is; null for an unreadable header) return the image's `PdfReference`.

### Text: characters, words, lines, selection, search

Folder `Text/`, uses Content. No user-visible text. Everything is in page user space, as in the content; the viewer converts with `PageGeometry`. A `TextPage` never changes and may be shared between threads; it is stale once the document is edited. Nothing throws on file contents: a content stream that cannot be decoded gives the text up to it.

**`TextPage`** (`sealed partial`)
- `static TextPage Create(PdfDocument, PdfPage, TextPageOptions? = null)` and `Create(ContentInterpreter, PdfPage, TextPageOptions? = null)` (the second reuses the caller's interpreter and its caches; it sets `WalkPatterns` off for the run and restores it). `record TextPageOptions(bool IncludeArtifacts = true, bool RemoveDuplicates = true)`.
- `PageIndex`, `Box` (crop box), `IsTruncated` (interpreter operation limit, or more than 1,000,000 glyphs), `Chars`, `Words`, `Lines`, `Blocks` (all `IReadOnlyList`), `Text`.
- `string GetText(TextRange, bool joinHyphens = false)`, `IReadOnlyList<TextQuad> Quads(TextRange)`, `TextRange WordRange(int)`, `LineRange(int)`, `TextHit? HitTest(x, y, maxDistance = infinity)`, `int CaretAt(x, y)`.
- Text rules: lines are joined by a line feed, blocks by a blank line, table cells and cells of one row by a tab; spaces at line ends are dropped. `joinHyphens` removes a `-`, U+2010, U+2011 or U+00AD that ends a line after a letter and joins the next line when it starts with a letter; before a capital the hyphen stays and only the break goes.

**Model.** `TextRange(Start, End)` (end excluded, `Count`, `IsEmpty`). `TextChar`: `Index`, `Text` (empty when the font gives none; Arabic presentation forms and Latin ligature code points are folded to plain letters; a ligature is one char with several characters), `Quad`, `Font` (null for implied spaces), `Size`, `Color` (stroke colour for Tr 1), `RenderMode`, `OperatorIndex` and `Form` (the innermost form, null on the page; the index is into the parse of that stream), `Element`, `Offset`, `Mcid`, `IsArtifact`, `IsSpace`, `IsImplied`, `IsRtl`, `Word` (-1 for spaces), `Line`. `TextWord(Index, Range, Text, Bounds, Line)`. `PageLine(Index, Range, Text, Bounds, Quad, Block, TextBreak Before, IsVertical, IsRtl)`; `enum TextBreak {None, Tab, Line, Block}` is what separates it from the line before. `TextBlock(Index, Lines, Bounds, IsTable)`. `TextHit(Char, Word, Line, Distance)`. `TextQuad(X0..Y3)`: bottom-left, bottom-right, top-right, top-left of the glyph box in the glyph's frame (rotation and skew kept); `Bounds`, `Center`, `Contains`, `DistanceTo`, `ToQuadPoints()` (the eight numbers of `/QuadPoints`, top-left first).

**What goes in.** Every glyph the interpreter shows, with: render mode 3 (OCR) kept, mode 7 left out; glyphs wholly outside the clip box or the crop box dropped; `/ActualText` replaces its glyphs (one char per line the span covers, the text on the first, empty text hides them); `/Artifact` marked, dropped if asked; a glyph drawn again at nearly the same place with the same text (within 0.2 em, fake bold) dropped; control characters removed. Not included: text in annotations and form fields, Type 3 glyph procedures, optional content that is switched off.

**Layout.** Per page /Rotate (reading order is of the page as shown) and per direction group (text turned by other angles comes after the main text; a vertical font is its own group, columns right to left). Lines are glyphs on one baseline with script glyphs taken in; a gap over 1.2 em splits a line into cells. Rows of at least three lines with two or more short cells (24 characters, 3 words) are a table: a block of its own, rows kept, cells joined by tabs. Other cells chain into blocks by vertical neighbourhood, one child each so that a heading over two columns does not join them, and blocks are ordered by recursive cuts: horizontal bands first, then column gutters (a stretch of x under 4% covered, so a page number in the gutter does not join the columns), bands that are columnar with a shared gutter stay together. Spaces: a space glyph, or a gap over 0.1 em of the two sizes, becomes a space (`IsImplied`, with a quad over the gap). Right to left: lines with Hebrew or Arabic letters are put in logical order (levels from nearest letters, numbers kept, brackets mirrored back); columns go right to left on a page that is mostly right to left. Limits: depth 48 and 20,000 blocks in the order search, 200 neighbours looked at per cell.

**`TextSelection`** (`Page`, `Ranges`, `IsEmpty`, `GetText(joinHyphens = false)`, `Quads()` one per stretch of a line, spaces at the ends left out). `Between(page, x1, y1, x2, y2)` is from caret to caret (either order; above all text is 0, below is the end), `InRectangle(page, PdfRect)` takes chars at least half inside, by line, `WordAt` (a space takes the next word), `LineAt`, `Of(page, TextRange)` (clamped).

**`TextSearch`** (static). `record TextSearchOptions(bool MatchCase = false, bool WholeWord = false, bool Regex = false, bool FoldDiacritics = false)`; `record SearchMatch(int Page, TextRange Range, string Text, IReadOnlyList<TextQuad> Quads)` with one quad per stretch of line. `Find(TextPage, query, options?, CancellationToken = default)` returns a list; `Find(TextCache, query, options?, first = 0, last = int.MaxValue, CancellationToken)` is an `IEnumerable` that searches a page as it is read and throws `OperationCanceledException`. White space in the query and the text, line breaks included, is one space. A hyphen at a line end is both ways: `in-` `formation` matches "information", `well-` `known` matches "well-known" (U+00AD joins only the first way). Matches do not overlap; the first of two overlapping ones wins. Case is `ToLowerInvariant` except U+0130, so I and i match, dotted and dotless I match nothing but themselves. Folding strips marks (decomposition, Hangul and CJK left whole), maps `ı İ ß æ œ ø ł đ` and their capitals to ASCII, so I, İ, ı, i all match. Whole word looks at the edge characters of the query. A regular expression runs on the page text with `CultureInvariant` and `IgnoreCase` unless `MatchCase`, over the folded text when folding (write it without marks); `WholeWord` wraps it in lookarounds; a pattern that takes over two seconds on a page stops there (hits found before that are kept) and the page index is added to `SearchTimeouts.Pages` (Swift `pages`), a class the caller passes as the optional last argument `timeouts` of either `Find` (so a panel can say "timed out" instead of "Nothing found"; pages ascending, once each); a bad pattern throws `ArgumentException`.

**`TextCache(PdfDocument, int maxChars = 2_000_000)`**: `Get(pageIndex)` builds on first use, least recently used pages go first once the characters pass the cap (the page just asked for always stays), `PageCount`, `Clear()` after an edit. Calls are serialized; the document is not safe to share. **`TextExport`**: `Page(TextPage, joinHyphens = false)` and `Range(TextCache, first, last, joinHyphens = false, CancellationToken)`, a form feed after each page.

**Measured.** A page takes a median of 0.9 ms with the content parsed (p99 16 ms) on the 4,158 corpus pages. Against `pdftotext` (4.06) the word sets of a page agree at Jaccard 0.98 on 89% of pages, 0.95 on 93%, 0.90 on 96%, in both default and `-layout`; what differs is mostly annotation text, shadows drawn as white copies, and cells that `pdftotext` splits differently.

### Pages

Rotate, delete, reorder, insert, import, merge, split, extract, boxes and resize (`Pages/`; uses Document only). Edits are made to an open `PdfDocument` in memory and the caller commits them through `PdfEditSession.Commit`. Pages are named by index from 0 as the document is when the call starts. A call that changes the set or order of pages lays the page tree out again, so any `PdfPage` held from before is stale (`document.Pages` is fresh). Arguments are checked before anything is changed: a bad index is `ArgumentOutOfRangeException`, other bad values `ArgumentException`.

**Page ranges.** `PageRange.Parse(string text, int pageCount)` is Lazy Print's parser ("1-3, 5, 8-", 1-based, order and repeats kept) giving `PageRangeResult(IReadOnlyList<int> Pages, PageRangeError? Error)` with 0-based pages. Its words are in `PagesText`.

**PageOperations** (`static`):
- `Rotate(PdfDocument, IEnumerable<int> pages, int degrees)` adds a multiple of 90 (negative turns back) to what the page shows, inherited value included, and writes `/Rotate` as 0, 90, 180 or 270.
- `SetBox(document, pages, PageBox box, PdfRect? rect)`; `PageBox` is `Media, Crop, Trim, Bleed, Art`. A box is clipped to the media box (one that misses it, or has no area, is refused); null removes it, except for the media box.
- `Resize(document, pages, double width, double height, ResizeMode mode)` with the size in points as the page is shown (turned pages and `/UserUnit` allowed for), 0 to 14400. `ScaleContent` fits and centres the page's crop box in the new size under a `q ... cm` / `Q` pair added round the content, maps the annotations' `/Rect`, `/QuadPoints`, `/L`, `/Vertices` and the trim, bleed and art boxes, and sets media and crop to the new size. Appearance streams follow their `/Rect`; other annotation geometry (`/InkList`, destinations' coordinates) is not mapped. `ChangeBox` sets media and crop to the new size from the crop box's lower-left corner and removes trim, bleed and art; the content stays.
- `RemoveTransitions(document, pages)` removes `/Trans` and `/Dur`.
- `Delete(document, pages)` refuses to remove every page. It removes the pages and frees their objects, and first: takes `/Dest` and GoTo `/A` away from outline items, links and other annotations that point at them (the item stays, the destination goes), removes the open action, removes named destinations (`/Dests` and the `/Names` tree) that point at them, removes their widgets from `/AcroForm /Fields` and `/CO` (a field with no widget or sub-field left goes, up to the root), and renumbers `/PageLabels` (a range with no page left is dropped, one that lost its first pages continues its numbering through `/St`; the tree is written flat). When a deleted page was tagged (`/StructParents` or an annotation with `/StructParent`) the tag tree is pruned as `RedactionStructure.Prune` does with the deleted pages as pictures: elements whose content was all on them go, others lose `/Alt`, `/ActualText` and `/E`, and the parent tree loses only the keys of the deleted pages and annotations that no remaining page or annotation holds (keys owned by forms and images stay); `/MarkInfo` and the other pages' `/StructParents` stay. A tree of 200000 elements or more, or one that `Prune` could not follow to the end (it returns false past its depth and element limits), is dropped as before: `/StructTreeRoot`, `/MarkInfo` and every `/StructParents`, `/StructParent` and `/Tabs S` go. Resources that remaining pages inherit from the tree are left as they are.
- `Reorder(document, IReadOnlyList<int> order)`: the page at `order[i]` becomes page `i`; must name each page once. `Move(document, pages, int before)` puts the pages, in document order, before the page now at `before` (the count puts them last). Page labels stay with positions.
- `Duplicate(document, pages)` puts a copy after each page, sharing content, fonts and images; annotations and form fields are copied (a field is renamed "name_2").
- `InsertBlank(document, int at, double width, double height, int count = 1)`; `ImportPages(PdfDocument target, PdfDocument source, IReadOnlyList<int> sourcePages, int at)`.
- `Impose(PdfDocument source, IReadOnlyList<int> pages, ImposeOptions options, CancellationToken cancel = default)` (Swift `impose(source, pages, options)`) returns `ImposeResult(Document, Sheets, AnnotationsFlattened, AnnotationsDropped)`: a new document (not saved) of sheets with the pages at those indexes, in that order, placed as Form XObjects. `ImposeOptions(Mode, SheetWidth, SheetHeight, PerSheet = 2, Gap = 0, Border = false)`; sizes in points, 0 to 14400, `Gap` not negative and small enough to leave room (else `ArgumentOutOfRangeException`; Swift throws `damaged`), no pages is `ArgumentException`. `NUp` takes `PerSheet` 2, 4, 6, 9 or 16 as a grid of 2x1, 2x2, 3x2, 3x3, 4x4 (columns by rows) on a sheet of the size given, filled across then down; any other count is `ArgumentException`. `Booklet` puts two pages on a landscape sheet (the larger side as the width, whatever order the size was given in), padding the list with blank cells to a multiple of 4: sheets run front, back, front, back, with the last and first pages together on the first front, then the second and the second to last on its back, and so on inward. Each page is fitted to its cell (scaled up or down, aspect kept, centred, `Gap` between cells and from the sheet edge) with its `/Rotate` and `/UserUnit` applied and its crop box as the form's `/BBox`; the form holds the page's decoded content (written with Flate), its resources and `/Group`. `Border` strokes a 0.5 pt black rectangle round each placed page. Form widgets are redrawn from their values first, as `PdfForm.Flatten` does (all fields when the source has `/NeedAppearances`, else those with no normal appearance; a field that cannot be drawn keeps what it has). Annotations: every kind except Link and Popup that has a normal appearance, is shown and is not in a hidden layer is flattened into its page before the page becomes a form (as `PdfAnnotationFlattener` does, form widgets included); everything else (links, popups, annotations with no appearance) is dropped, and the result counts both. Not carried: bookmarks, page labels, names, tags, attachments and the other document-level data (no `/AcroForm`, since every widget is flattened or dropped); the `/Info` is. The source is not changed; the sheets share nothing with it.

**Import.** Everything a page uses is copied once per call. Source and target may each be encrypted (copied streams are decrypted and written again with the target's handler); the source may be the target. Inherited `/Resources`, `/MediaBox`, `/CropBox` and `/Rotate` are written onto the new page. Not copied: `/Parent`, `/B`, `/StructParents` and `/StructParent` (extract, split and merge keep them with the tag tree, see PageAssembly), the tree, names, threads and tags. `PageOperations.ImportPages` from another document (insert, paste, replace) adds the source's bookmarks that point at the imported pages at the end of the target's top-level bookmarks, with no wrapper item: one that points elsewhere is dropped unless a descendant is kept, and each goes to the page's new index; from the same document it adds none.  A reference to a page that did not come across, to a page tree node or to the catalog reads as nothing, whatever holds it. Resources the content never names are left out (a form without `/Resources` of its own is read for names; a Type 3 font without them, or a content stream that does not decode, stops the pruning for that page). Annotations are kept and copied for each copy of the page, `/P` points at the new page, a popup stays only with its note; links and GoTo actions to pages that came across are repointed (named destinations are looked up in the source and made explicit), a Link to a page that did not is dropped, any other annotation loses the dead `/Dest` or `/A`. Form fields join the target's `/AcroForm`: the chain above each widget is copied with only the widgets that came across; a root field whose `/T` is taken gets `_2`, `_3`... so values stay separate; `/DA` and `/Q` are carried to the root, the source's `/DR` entries the target lacks and `/NeedAppearances` are merged; a signature field loses its `/V`. References are followed through a queue (no recursion limit on chains), loops close on the copy.

**PageAssembly** (`static`): `Extract(source, pages, cancel = default, files = true)` (Swift `extract(source, pages, files: true)`; `files` false leaves the attached files out, for a copy that only goes back in as pages) makes a new `PdfDocument` (not yet saved) of those pages in that order, with the source's `/Info`. `Merge(IReadOnlyList<MergeSource>, CancellationToken cancel = default, IReadOnlyList<string>? titles = null)` with `MergeSource(PdfDocument Document, IReadOnlyList<int>? Pages = null)` (null takes all; a document listed twice is copied once; first source's `/Info`). `SplitEvery(source, n)`, `SplitByRanges(source, IReadOnlyList<IReadOnlyList<int>>)`, `SplitAt(source, IEnumerable<int> starts)` (page 0 implied, repeats ignored; pass the pages of the top-level bookmarks), `SplitBySize(source, long maxBytes, PdfSaveOptions? options = null)`: as many pages per part as save (`SaveRewrite(options)`) to no more than `maxBytes`, a page too big alone is a part; found from an estimate by galloping and bisecting; the document that fit is the part. A new document holds the pages and what they use and what belongs to them, and nothing else: no threads or open action. What belongs to them (`PageCarry`, after the pages are in the tree): bookmarks whose destination (explicit or named, written explicit) is on a page taken or that have such a bookmark below them, with their title, colour, style and open state and the destination at the page's new index; page labels restricted to the pages taken, a range with a gap going on counting where the source does (extract and split only); named destinations (`/Dests`, `/Names /Dests`) that point at a page taken; the document-level attachments (`/Names /EmbeddedFiles`; a split puts them in its first part only, so `SplitBySize` counts them against that part alone, while the `/Info` and `/Metadata` stay in every part; one that does not decode or is over the 1 GiB cap of PdfAttachments.Extract is left out and counted in `PdfDocument.SkippedAttachments` / `skippedAttachments` of the new document, and the operation goes on); `/Lang` and, when `/Info` is carried too, the `/Metadata` stream of the first source, without its `pdfaid` and `pdfuaid` properties (a part or a merge is not PDF/A or PDF/UA; a packet that cannot be read is copied as it is). On merge each source that has such bookmarks adds one top-level bookmark titled by its `/Info` `/Title`, else by `titles[i]`, else empty, holding them; labels are not written; all sources' attachments are carried, a document listed twice adding its own once (a name already taken gets ` (2)`, ` (3)`) and a named destination whose name is taken is left out. The tag tree is carried and pruned to the pages taken (`RedactionStructure.Prune`), and what the pruning would cut is not copied at all (`TagCut` finds it by reading the source tree, so a split costs a walk of the tree per part, not a copy; the parent and ID trees are rebuilt from the entries in use, and `HasTags` is checked once per split): an element that loses all its content goes, one that loses some loses its `/Alt`, `/ActualText` and `/E`, the parent tree keeps the keys of the pages and annotations taken and of the forms and images they use (nested forms too), and `/MarkInfo` follows. On merge each tagged source's top-level elements go under one new root, its parent tree keys (those of its forms and images too) moved past those of the sources before it, and `/MarkInfo` is written only when every source with pages was tagged; a document listed twice is tagged at each listing, the tree copied once for each. A tree of 200000 elements or more is not carried (untagged, as before). An object that the source lists (in use or in an object stream) but cannot read, reached from what came across, is left out of the copy and counted once per source in `PdfDocument.DroppedObjects` / `droppedObjects` of the new document (a merge adds the counts of its sources, a document listed twice counting once); the operation goes on. Nothing that reaches a page left out is copied; after `SaveRewrite` nothing of a page left out is in the bytes. Parts are built at once and share nothing with each other; the source is not changed.

**Page tree.** After any change the tree is rebuilt with at most 32 kids per node (flat up to 32 pages, a node per 32 and so on above), reusing the old inner nodes in order so that an edit near the end of a large file rewrites few objects. A page that took `/Resources`, `/MediaBox`, `/CropBox` or `/Rotate` from a removed inner node gets it written on itself. A tree that was damaged is rebuilt from `document.Pages`.

**Limits.** Trees, outline items and name trees are walked with node caps (1,000,000 and 100,000) and a depth of 32 for field and name chains; resource pruning stops after 64 rounds. An edit session keeps what a delete removed in its history; `SaveCompact` or `SaveRewrite` drops it.

### Structure: outlines, destinations, actions, links, labels, attachments, metadata, layers

Folder `Structure/`, namespace `LazyPDF.Core`, uses Syntax, Filters, Crypt, Fonts/Tables (PDFDocEncoding) and Document. Everything works on an open `PdfDocument` in memory: a reader returns a snapshot or reads the live objects, a writer changes the document's objects (new ones through `Add`), and the edit session commits them. Nothing reads a clock: dates come from the caller. Reading never throws on file contents; every loop, chain and tree walk is capped. A snapshot (`Outline`, records) is stale once the session has committed and reopened the document.

**Text.** `static class PdfText`: `string Decode(ReadOnlySpan<byte>)` (PDFDocEncoding, UTF-16BE or LE with mark, UTF-8 with mark, language escapes dropped; PDFDoc codes the table leaves out read as Latin-1), `byte[] Encode(string)` (PDFDocEncoding when every character is in it, else UTF-16BE with mark), `PdfString ToObject(string)` (hex when it holds bytes a literal would escape), `string? Read(PdfDocument, PdfObject?)` and `Read(PdfDocument, PdfDictionary?, string key)` (a string, or a stream's decoded data).
**Dates.** `static class PdfDate`: `DateTimeOffset? Parse(string?)` (ISO 32000-1 7.9.4, any part after the year may be missing, `Z`, `+HH'mm'`, apostrophes optional; no zone counts as UTC; null for nonsense), `Format` ("D:20261019213005+03'00'"), `FormatXmp`, `ParseXmp`.

**Trees.** `PdfNameTree` and `PdfNumberTree` (7.9.6, 7.9.7): `Read(PdfDocument, PdfObject? root)` gives the entries in the order met, values unresolved (depth 32, loops cut, a million entries). `Write(document, PdfDictionary? existing, entries)` returns the root: `existing` changed in place (old child nodes freed) or a new dictionary; one leaf up to 64 entries, else leaves of 64 with `/Limits` under `/Kids`, as many levels as needed; sorted, the last of a repeated key counts. Name keys are strings with one character per byte; `PdfNameTree.KeyOf(text)` and `TextOf(key)` convert to text strings.

**Destinations.** `enum DestinationFit {Xyz, Fit, FitH, FitV, FitR, FitB, FitBH, FitBV}`. `record PdfDestination(int PageIndex, DestinationFit Fit = Fit, double? Left, Bottom, Right, Top, Zoom, string? - Fonts: the `/DR` font named in `/DA` is used when it can show every character (simple fonts only; Type0 and Type3 are not used). ### Stamps: watermarks, backgrounds, headers, footers, Bates numbers, images

Folder `Stamps/`, uses Content and Fonts (and `PdfText` from Structure for the label strings). Nothing is saved here: the caller saves the document. Errors: `ArgumentException` for a spec with nothing to draw, `InvalidOperationException` with `StampsText.NoFont` when no font can draw the text (the document is then unchanged). `StampsText` holds the two user texts.

**`PdfImageWriter`** (static, also for signatures and pictures placed on a page). `record PdfImage(PdfReference Reference, int Width, int Height)`.
- `PdfImage? AddJpeg(PdfDocument, byte[] jpeg)`: DCTDecode as it is; colour and size from the frame header (1, 3 or 4 components; an Adobe CMYK file gets the inverting /Decode). Null for an unreadable header. `TryReadJpegHeader` is copied from Lazy Scan.

**`PdfStamper(PdfDocument, IFontSource? fonts = null)`**. All sizes and offsets are display points of the page as shown (crop box, `/Rotate` and `/UserUnit` applied through `PageGeometry`), y down, so text is upright on a rotated page. `Pages` in a spec are 0-based, null for all; out of range and repeated entries are ignored.
- `StampRun AddWatermark(WatermarkSpec)`, `AddBackground(BackgroundSpec)`, `AddHeaderFooter(HeaderFooterSpec)`. `record StampRun(int Id, int Pages, long NextBates, IReadOnlyList<int> Missing)`: the run's id, pages stamped, where the next document of a Bates batch starts (0 without Bates), code points the font has no glyph for.
- `StampRun Update(int id, WatermarkSpec | BackgroundSpec | HeaderFooterSpec)`: removes run `id` and adds the new one under it (adds it when there was none).
- `IReadOnlyList<StampInfo> List()`, `List(PdfPage)`: `record StampInfo(int Id, StampKind Kind, string? Label, bool Behind, IReadOnlyList<int> Pages)`, by id. `StampKind`: `Watermark`, `Background`, `HeaderFooter`, `Bates`. Label is the watermark text ("image" for a picture), or the header and footer texts joined by " | ".
- `int Remove(int id)` returns the pages it was on; it also takes out the run's resources and optional content group. `int RemoveAll()` returns the number of runs.

**Specs** (sealed records with `init` properties). `StampColor(R, G, B)` 0 to 1, `StampColor.Gray(l)`. `StampAnchor`: nine positions, `TopLeft` to `BottomRight`.
- `WatermarkSpec`: `Text` (lines split at `\n`) or `Image` (exactly one), `FontFamily` ("Helvetica"), `FontStyle` (Bold), `Color` (gray 0.5), `Opacity` (0.3, an /ExtGState `ca` and `CA`, none at 1), `Rotation` (degrees counter-clockwise about the centre), `Scale` (0.6: the unrotated width as a fraction of the page width, the text size follows; an image keeps its proportions), `Anchor` (Center), `OffsetX`, `OffsetY` (right and down), `Behind`, `LayerName`, `Pages`.
- `BackgroundSpec`: `Color`, `Image` (either or both, behind the content), `Fit` (`Cover` clips the overflow, `Contain`, `Stretch`), `Opacity` (1), `LayerName`, `Pages`.
- `HeaderFooterSpec`: `Header`, `Footer` as `HeaderFooterBand(Left, Center, Right)`; `EvenHeader`, `EvenFooter` replace them on the 2nd, 4th... page (null: same); `FontFamily`, `FontStyle`, `FontSize` (10), `Color`, `MarginX`, `MarginTop`, `MarginBottom` (36); `StartNumber` (1; page i shows StartNumber + i); `Date` (the app passes it, Core has no clock), `DateFormat` ("yyyy-MM-dd"), `Culture` (invariant); `FileName`; `Bates`; `Pages`. Tokens: `{page}`, `{pages}` (the last page's number), `{date}`, `{date:format}`, `{file}`, `{bates}` (left as typed without `Bates`). Unknown tokens, a lone brace and an invalid date format stay as typed. Slots are one line; left and right are set at the margin, centre on the page. A page whose slots are all empty gets nothing.
- `BatesSpec(Prefix = "", Suffix = "", int Digits = 6, long Start = 1)`, `Format(long)` pads to `Digits` (1 to 18). The pages stamped are numbered from `Start` in document order; pass the run's `NextBates` as the next document's `Start`.

**What is written.** Text uses `PdfFontEmbedder` with one font per run holding all its text: a Standard 14 font when WinAnsi fits, else an embedded subset from `fonts` (Turkish letters included; no source or file means `NoFont`). Per page one content stream: `q`, one `cm` into the shown page's y-up space, then each part inside `/Artifact <</Type /Pagination /Subtype /Watermark|Header|Footer /LazyPDF id>> BDC`, backgrounds as `/Type /Background`, and when a layer is named inside `/OC BDC` too; `Q`. A layer is an OCG named by `LayerName` with Print and View on and Watermark subtype, added to `/OCProperties` `/OCGs` and `/D /Order`, shared by the run, tagged with its id. The stream dictionary carries `/LazyPDF <</Id n /Kind /Watermark /Label (...) /Back true>>`; that key is what `List`, `Update` and `Remove` read. Resources are named `LPS<id>_F`, `_I`, `_G`, `_P` (font, image, state, layer).
- Placement: behind stamps (`Behind`, backgrounds) go first in `/Contents` and need nothing from the page. Stamps in front go last, between a pair of marked streams built once per page from the page's content: the first opens as many `q` as the content may pop (one more than its deepest underflow, at most 1000), the second closes `ET`, `EMC` and `Q` for what it leaves open. So unbalanced content, an open text object or open marked content cannot shift or break a stamp. The wrapper goes when the last front stamp on the page does.
- Ids are one more than the highest found in the file. A page with no `/Contents`, a single stream or an array takes stamps; an inherited `/Resources` is copied onto the page first.

**Limits.** A run is found only while its streams stay separate: a tool that merges a page's content streams loses the `/LazyPDF` key, and the stamp then reads as page content. The `Q` that a page pops without a `q` of its own pops the wrapper's, so a stray `Q` after a `cm` restores the initial state in front stamps' pages instead of being ignored. Removing leaves the font and image objects in the file until a rewrite. Optional content needs PDF 1.5, transparency 1.4; the header version is not raised. Only the 0-based page list selects pages (no "odd" or "even" ranges); `PageRange` in Pages parses typed ranges.

**Tests.** `windows/LazyPDF.Core.Tests/Stamps/`: every writer test reopens through `PdfDocument` and PdfPig; glyph positions are checked with the interpreter in display points on pages with `/Rotate`, `/CropBox`, `/UserUnit`; unbalanced pages; Turkish text with arial.ttf; a corpus run under `LAZYPDF_CORPUS`.

### Changes to finished layers

No signature changed. What differs in behaviour:

**Text.** `TextSearch` case folding turns U+0130 (dotted capital I) into `i`; dotless `ı` stays its own letter until `FoldDiacritics`. With `Regex` and `FoldDiacritics` the pattern is folded as the page is. A rejected whole-word candidate advances by one character, so an overlapping valid hit is found. Reading order follows the baseline, so a sheared matrix (synthetic italic) stays in its line. Type 3 glyph boxes and `Size` come from `/FontBBox` and `/FontMatrix`, not the font size. `/ActualText` without a byte order mark is read as PDFDocEncoding. Right-to-left lines: terminators (`%`, `$`) stay with their number, and a page that is right to left treats every line with a right-to-left letter as right to left.

**Content.** A bad `/ToUnicode` costs only the text; widths, `/Encoding` and vertical mode are still read. A ToUnicode map written at another code width than the font reads still applies, by numeric code. `/W` and `/W2` are bounded by entries written, not by distinct entries. `TJ` array items cost one operation each. A form with more than 1,000,000 operations is skipped; forms that are not cached cost operations in proportion to their size.

**Fonts.** `EmbeddedFont.Encode` skips control characters, as `Width` does. A CFF font embedded whole writes CIDs (through the charset) as codes. When characters are missing, CID 0 gets a `/W` entry with the `.notdef` advance. WinAnsi fitting accepts U+00A0 and U+00AD.

**Annotations.** `Regenerate`, `Resize`, `SetColor` and `SetOpacity` leave a stamp alone unless its appearance was drawn by `AddStamp` (it carries `/LazyPDFText true`): image stamps and stamps from other writers keep their artwork. `Delete` takes a widget out of its field's `/Kids` or `/Fields` and clears the owner's `/Popup` when a popup is deleted. `PdfAnnotationFlattener` does not burn an annotation whose `/OC` group is off. `PdfXfdf` writes and reads `justification` as left/centered/right, `symbol` as paragraph/none, `replyType` as reply/group, and names a parent before its reply. `PdfFdf.Export` leaves out `/StructParent`. `PdfFdf.Import` keeps a reply to an annotation the document already has, and skips a popup whose owner was skipped.

**Forms.** `AddWidget` repoints `/Annots` even when the widget has no `/P`, and the new widget takes the first one's `/MK` and `/BS`. A radio group's default on-state is the first `ChoiceN` not in use. Dates are read by the field's own format first; `AFNumber_Format` style 2 reads a lone `.` before three digits as a group mark; `AFSpecial_Format(2)` needs exactly 10 digits. A widget's own `/DA` and `/Q` win over the field's for colour, size and alignment. A push button with an `/MK /I` icon is not redrawn; redrawing keeps the other states of `/AP`. `SetFlag`, `SetMaxLength` and `SetDefaultValue` write an explicit empty value when an ancestor has one. `ExportFdf` writes a button's on-state name. Removing a radio or check box widget removes its `/Opt` entry and resets `/V` if it named that button.

**Pages.** `Extract`, `Merge` and `ImportPages` carry the optional content groups the pages use into `/OCProperties`, with the hidden ones in `/D /OFF`; direct dictionaries in `/Annots` are copied; field lists of `SubmitForm`, `ResetForm` and `Hide` keep only the fields that came across; `/AA` and `/Next` chains are fixed like `/A`; a form's own `/Resources` are pruned to the names its content uses. Merged runs of the same stamp id from different files are renumbered (`StampRuns.Separate`). `Delete` also cleans `/Threads`, `/Next` and `/AA` chains and `/OpenAction`, recomputes `/Limits` of the named destination tree and drops empty leaves, drops the structure tree when a deleted page has tagged annotations (removing `/StructParent` and `/Tabs /S`), and a page inserted at 0 into a labelled file gets `/S /D`. `Resize` with `ScaleContent` also maps `/InkList` and `/CL` and scales `/RD`.

**Stamps.** `PdfStamper.Update` draws the new run under a spare id first; if that throws the old run stays. `Remove` frees stamp streams only with the last page that lists them, and unlists the layer from `/ON`, `/OFF`, `/Locked`, `/RBGroups` and `/AS`. Background artifacts carry `/BBox`.

**Structure.** `Outline.Write` gives an item or root a new object when its old one was freed. `DocumentMetadata.Write` sets `dc:subject` from the keywords and keeps a `/CreationDate` or `/ModDate` that could not be parsed. `PdfAttachments.Remove` keeps a file specification another annotation still uses and deletes the popup and replies of the annotation. `/F` of a file specification is ASCII (`_` for the rest); `SubmitFormAction` writes a URL file specification.

### Editing: text, images and paths already on a page

Folder `Editing/`, namespace `LazyPDF.Core`. Uses Text, Content, Fonts and `PdfImageWriter` (Stamps). Everything is in user space. Work goes through a `PdfEditSession`: every public change is one `Commit`, so one undo step; a change that cannot be made commits nothing and says why in its result. Objects and `TextRange`s handed out before a change are stale after it (`PageEditor` reads the page again by itself after a commit, undo or redo; `Refresh()` forces it); a stale object is an `ArgumentException`. Nothing else throws on file contents. User words are in `EditingText`. `PdfFont` gained an internal `CanDraw(FontChar)` (does the embedded program have the glyph).

**`PageEditor(PdfEditSession, int pageIndex, IFontSource? fonts = null, IImageCodec? images = null)`**
- `Objects` (`IReadOnlyList<PageObject>` in painting order), `Text` (the `TextPage` whose `TextRange`s the text changes take), `HitTest(x, y, tolerance = 1)` (topmost: text by glyph box, images through the inverse placement, paths by fill or stroke reach), `Select(PdfRect, contained = false)`.
- `PageObject`: `Id`, `Kind` (`Text`, `Image`, `Path`), `Bounds`, `Forms` (the form XObject chain, empty on the page). `TextObject` is one block of the `TextPage` (paragraph, column piece, table): `Text`, `Range`, `Lines` (`TextObjectLine`), `Font`, `Size`, `Color`, `CharSpacing` of its first glyph, `Alignment` (`Left`, `Center`, `Right`, `Justify`, read from where the lines start and end), `LineSpacing`. `ImageObject`: `Name`, `Width`, `Height`, `Placement` (unit square to user space), `Opacity`, `IsInline`, `IsMask`. `PathObject`: `Segments`, `Fill`, `Stroke`, `FillColor`, `StrokeColor`, `LineWidth`, `Opacity`, `EvenOdd`, `Clips`. Every glyph is tied to its operation, string element and byte through the interpreter's operator index and form chain.

**Text** (results are `TextEditResult(Done, Substitutions, Grew, Overlaps, Problem)`)
- `ReplaceText(TextRange, text)`: the glyphs of the range are cut from their strings (`Tj`, `TJ`, `'`, `"` are rewritten over their own bytes, kerning numbers stay) and the new text goes in at the first one: same font, size, colour, spacing, baseline. Later text in the same run follows it; text in other runs keeps its place, and `Overlaps` says when the new text reaches it or leaves the page. A whole line of a centred or right aligned block is shifted to keep its centre or right edge. A word set in more than one size, font or colour (a drop cap) takes its new letters in the same parts. A glyph drawn twice at one place (fake bold) is replaced with its copy.
- Characters the font cannot show: a simple font through its encoding (a glyph the embedded program lacks does not count); a composite font with a whole program (no subset tag, TrueType, Identity-H, identity `CIDToGIDMap`) through its own cmap, with `/W` and `/ToUnicode` extended; else a stand-in from `fonts` through `PdfFontEmbedder` (family and style from the name and flags, a `Narrow` face kept), listed in `Substitutions`. No source, or no glyph: `Problem`, nothing committed.
- `DeleteText(range)` keeps the rest in place. `InsertText(index, text)`. `ReplaceParagraph(TextObject, text)`: lines laid out again in the block's width with its alignment (`Justify` by word spacing on simple fonts); a one-line block does not wrap; lines no longer needed go, extra lines are added after the text object over whatever is there, `Grew` is set and the blocks below stay put. Font and size are the first glyph's; each line keeps its own character and word spacing; a block set in more than one size (a heading with its text) is refused.
- `SetTextStyle(ranges, TextStyleChange(Family, Bold, Italic, Size, Color, CharSpacing))`: size, colour and spacing wrap the glyphs in operators that put the state back; family, bold or italic set the text again in the new font. `SetAlignment(TextObject, alignment)` shifts lines with `TJ` numbers; `SetLineSpacing(TextObject, spacing)` raises each line by a text rise. A range with an unbalanced `q` or `Q` in it is refused.
- `AddTextBox(PdfRect, text, TextBoxStyle?)`: wrapped inside the box, upright on the page as shown (`/Rotate` allowed for); `Overlaps` when the text is taller than the box.

**Objects** (results are `ObjectEditResult(Changed, Skipped)`, `SkippedObject(Id, Reason)`)
- `Move`, `Transform(objects, PdfMatrix)`, `Resize(objects, bounds)`, `Rotate(objects, degrees)`, `Flip(objects, horizontal)`: a matrix `G T G^-1` goes round each object, coordinates untouched (`q ... cm ... Q`; for text `cm ... cm` outside the text object, text matrices put back after, a string cut in two where a block starts or ends inside it). Skipped: a path that clips, text whose matrices cannot be put back, a run with an unbalanced `q`, an object of a form painted twice when another object of that form is changed in the same call. A pattern fill stays where the page puts the pattern.
- `Delete` (an image or path leaves no operators, a clipping path becomes `n`), `Crop(image, rect)` by a clip, `ReplaceImage(image, bytes, fit = true)` (through `PdfImageWriter.AddPicture`: a JPEG with an Exif orientation other than 1 is decoded and stored upright, as a quality 92 JPEG when the codec encodes one, else as pixels; other JPEGs are embedded as they are, other files go through `IImageCodec.DecodeFile`), `SetOpacity`, `Order(object, OrderMove)` for an image or path alone in a `q ... Q`, `SetPathStyle(paths, fill, stroke, lineWidth)`, `ExtractImage(image)` (`ExtractedImage(Data, Extension)`: JPEG and JPEG 2000 as stored, else PNG).
- `AddLine`, `AddRectangle`, `AddEllipse` with `ShapeStyle(Stroke, Fill, Width, Opacity)`.

**Streams.** Edits are splices at the byte ranges of the parse, so operators outside them keep their bytes. The page's streams are rewritten one by one as new objects (a stamp's `/LazyPDF` marker stays on its stream); two are merged only when one operation spans the break. Content added at the end is preceded by what closes an open text object, the open `q` levels and a stray matrix. A form XObject that is painted twice, listed twice, or reached through resources another page shares is copied and only the edited `Do` is pointed at the copy (the parent copied in turn when it is shared); one nothing else uses is edited in place. A form inside a copied form is copied.

**`TextReplacer.ReplaceAll(session, query, replacement, TextSearchOptions? = null, IFontSource? = null, label, CancellationToken)`** finds as `TextSearch` does and replaces on every page in one commit: `ReplaceReport(Replaced, Failed (ReplaceFailure(Page, Text, Reason)), Substitutions, Pages)`. With `Regex` the replacement takes groups. A match over two lines, in text with `/ActualText`, in vertical text, or with letters no font has stays as it was and is reported.

**Limits.** No vertical writing, no text whose font is set outside its form when a stand-in is needed. A simple font is never given new glyphs. A moved path leaves its clip behind. Rotated text is edited along its baseline.

**Measured** on 4,158 pages of the 294 corpus files that open: the first word of a line of 3,866 pages replaced by one of the same length, committed, reopened: 99.5% found with every other line unchanged (the rest are lines where the original already draws words over each other); every object of each page moved by one amount: 97.1% moved exactly, 2.6% with some objects skipped, 0.2% a glyph or path left (invisible or replaced text); about 30 ms a page for an edit, commit and reopen.

### Redaction: removing text, images, shapes, annotations and fields for good

Folder `Redaction/`, uses Text and everything below it (Forms, Annotations, Structure, Content). What is under a mark must not be in the output in any recoverable form; a box drawn over it is not redaction. The output is always a full rewrite, so no earlier revision of the file can hold what was removed, and there is no incremental way to apply.

```csharp
public sealed record RedactionMark(int Page, IReadOnlyList<TextQuad> Quads, double[]? Fill = null, string? OverlayText = null)
{ static FromRect(page, PdfRect, fill, overlay); static FromMatch(SearchMatch, fill, overlay); }
public sealed class PdfRedactor(PdfDocument document, IFontSource? fonts = null, IImageCodec? images = null)
{
    IReadOnlyList<RedactionMark> ReadMarks();                      // the /Redact annotations
    IReadOnlyList<PdfAnnotation> AddMarks(IEnumerable<RedactionMark>, AnnotationInfo? info = null);
    RedactionResult Apply(IEnumerable<RedactionMark>, RedactionOptions? options = null);
    RedactionResult ApplyMarked(RedactionOptions? options = null); // Apply(ReadMarks())
    static RedactionVerification Verify(byte[] output, IReadOnlyList<RedactionMark> marks, IReadOnlyCollection<string> removed,
                                        IReadOnlyCollection<string>? overlay = null, string? password = null);
}
record RedactionResult(byte[] Bytes, RedactionReport Report, RedactionVerification Verification);
record RedactionOptions { Fill; OverlayText; RepeatOverlay; FontFamily = "Helvetica"; IncludeText; ChangeMetadata; KeepEncryption = true }
```

**Marking** writes one `/Redact` annotation per mark (`/QuadPoints`, `/IC` fill, `/OverlayText`) through `PdfAnnotationWriter` and removes nothing; the edit session commits it. Marks come from those annotations, from `SearchMatch` quads, from rectangles or from the finders below. Quads are in page user space in any corner order; marks with no area, NaN, a page out of range or no quads are ignored.

**Applying** works on a copy made by `SaveRewrite` of the document as it is now (uncommitted edits included); the document is not changed. Per page, through the interpreter's operator indexes and form chains:
- Text: a glyph goes when the middle 70% of its box (ascent to descent, in the glyph's own frame) meets a mark, whatever its render mode, clip or font; zero-width glyphs by their point. `Tj`, `TJ`, `'` and `"` are rewritten as `TJ` with a number standing for the advance of each removed glyph (character and word spacing, `Tz` and vertical fonts allowed for), so the glyphs that stay keep their positions. Strings are cut only at code boundaries the font reports. A marked-content sequence that lost anything loses `/ActualText`, `/Alt` and `/E`; a named property list is inlined without them and dropped from `/Properties` when nothing else uses it.
- Images: pixels whose square a mark touches are zeroed in the samples (any depth, `/ImageMask`, `/SMask`, stencil `/Mask`, at the mask's own size) and the image is stored again as Flate with its other keys. DCT, JPX and JBIG2 go through `IImageCodec.Decode` and come back as RGB (JBIG2 as 1 bit); with no codec, a failed decode, a loop of masks or a bad size the placement is removed whole, never kept with the marked part visible, `Report.Images` counts it and `PageRedaction.WholeImages` (also in `Images`) says it was removed whole, which `ToString()` reports on its own line (JBIG2 and JPX are in this case on Windows, which has no JPX codec, and wherever the codec fails). Every placement gets its own copy; the original stays only where something else paints it. Inline images that meet a mark are removed.
- Paths: a path whose fill or stroke (half the line width counted) meets a mark is removed. A plain axis-aligned rectangle fill is cut instead into the rectangles around the marks' boxes (in page space, so a turned page or `cm` is allowed for). A path with a pattern fill, or `B`/`b`, is removed whole; a clipping path stays. A shading under a mark is drawn through a clip with a hole.
- Forms: a form with a hit is copied for that use (its resources too) and the call pointed at the copy; the original is dropped from resources that never paint it. Tiling patterns are not entered; Type 3 glyphs go as glyphs.
- Annotations whose `/Rect` meets a mark go with popups and replies, links included; a form field with a widget under a mark goes whole with its value; `/AcroForm` goes when no field is left and `/XFA` when any went. `/Thumb`, `/PieceInfo` and `/Metadata` of the page go. Resources inherited from the page tree are given to each page first, so no tree node keeps an original.
- Overlay: a polygon fill per quad in `Fill` (mark, then option, else black), and `OverlayText` (mark, then option) in bold `FontFamily` through `PdfFontEmbedder`, centred, shrunk to fit (not below 3 pt), white on a dark fill; `RepeatOverlay` repeats it across the width. No font gives `InvalidOperationException(RedactionText.NoFont)` before anything is done. Content is closed up (q, ET, EMC) and cut after its last complete operation before the overlay is added.

**Document.** Signature values, `/Perms`, `/DSS` and `/SigFlags` go (`SignaturesRemoved`; the output is unsigned). Tag tree: an element whose marked content is wholly removed, or whose annotation went, leaves the tree and the parent and ID trees; one that lost part loses `/ActualText`, `/Alt`, `/E`. Only page-level marked content ids are followed, not those inside forms. Strings of removed text (the page text under each mark, annotation contents, field values; 3 characters or more) are looked for in `/Info`, the XMP packet (UTF-8) and bookmark titles, case ignored, and reported; with `ChangeMetadata` they are replaced by `[redacted]`. Output keeps the input's encryption and first `/ID` unless `KeepEncryption` is false. Font programs of the pages stay as they are, including the glyphs of removed characters.

**Report.** `RedactionReport`: `Pages` (`PageRedaction(Page, Glyphs, Images, Paths, Annotations, Fields, Values, WholeImages)`, marked pages only), `Findings` (`RedactionFinding(Where, Changed)`), `SignaturesRemoved`, `Text` (the removed strings, empty unless `IncludeText`), totals, and `ToString()` in plain words from `RedactionText`, which never repeats removed text unless `Text` is filled.

**Verify** reopens the bytes and checks the text of each mark (glyph middles meeting it) is empty apart from the overlay texts, then looks for each removed string (500 at most) as Latin-1, UTF-8 and UTF-16 in every object's strings and every decoded stream. Page and form content is searched only in operands other than shown text (property lists, descriptions), since shown text is coded by the font and may legitimately appear elsewhere. Problems name a page or object, never the text. `Apply` runs it on the plain output; a file with metadata that was reported and not changed is not clean.

**Finders** (`RedactionFinder`, through `TextSearch`): `Find(TextCache | PdfDocument, RedactionKind)` for `Email`, `Phone` (9 to 15 digits), `UsSocialSecurity` (area not 000, 666, 9xx), `TurkishId` (both check digits), `Iban` (mod 97, an upper case word after it is cut off), `PaymentCard` (Luhn, 13 to 19 digits), `Date` (numeric, English and Turkish month names); `FindRegex(cache, pattern, matchCase)`, `FindWords(cache, words, wholeWord, matchCase)`. Each gives `RedactionMatch(Mark, Text, Kind)`; nothing is marked until the caller does.

**Values** (annotation contents and field values). `RedactionFinder.FindInValues(document, kind)`, `FindRegexInValues(document, pattern, matchCase)` and `FindWordsInValues(document, words, wholeWord, matchCase)` (Swift `findInValues`, `findRegexInValues`, `findWordsInValues`) search the `/Contents` of every annotation but widgets (comments, free text, popups, replies) and the value of text fields and editable combo boxes (once per field, reported at its first widget), with the same shapes and checks as the page finders. Each gives `RedactionValueMatch(Page, Annotation, Source, Start, Length, Text, Kind)`: `Annotation` is the index in `PdfAnnotations.Read` for that page, `Source` is `Comment` or `Field`, `Start` and `Length` are UTF-16 units of the value. `Apply(marks, options, values)` (also `ApplyMarked(options, values)`; Swift `apply(marks, options, values)`) rewrites them first, before marks remove anything, on the copy: the matched text is replaced by `RedactionOptions.OverlayText` or removed, a hit whose text is no longer at its place is skipped, and hits of one value that overlap or touch (from different finders) are replaced once as their union. Every annotation is looked up before the first one is rewritten and the groups run in page then annotation order, so a box or field removed on the way does not move the hits after it. A comment is set through `PdfAnnotationWriter.SetContents` (a free text box is drawn again; a box that cannot be drawn goes whole), and `/RC` and `/Subject` lose the text. A field is set through `PdfForm.SetValue` (appearance drawn again, calculations run; a value the field rejects is cleared; a field that cannot be set is removed), and `/RV` and `/DV` lose the text. The text found is a needle like any removed text: `Verify` looks for it, the metadata scan reports it, and `Report.Text` lists it with `IncludeText`. `PageRedaction.Values` counts the annotations and fields rewritten on a page and `ValuesWhole` those of them removed whole (a free text box that cannot be drawn again, a field that cannot be set), which the report names in a line of its own; a page that only had values gets an entry too, and `ToString()` says "text in N notes or fields". Check boxes, radio groups, list boxes and combo boxes that do not take typing are not searched. Tests: `RedactValueTests`.

**Limits.** Paths are tested by their outline, curves in 8 steps. Images over 2^27 pixels or 256 MB of samples are removed. Shadings and fonts are not edited. Text in annotations and fields is not page text, so it is covered through the annotation or field rule, or by the value search below. Tests: `LazyPDF.Core.Tests/Redaction/` (text, composite fonts, images, paths, forms, annotations, marker, overlay, finders, encryption, malformed input, geometry, corpus under `LAZYPDF_CORPUS`).

### Signatures: signing, verifying, time stamps, long term validation, revisions

Folder `Signatures/`, uses Document, Forms (to find and read fields), Content, Stamps (`PdfImageWriter`) and Structure (`PdfText`, `PdfDate`). System.Security.Cryptography, its X.509 types and the one Pkcs package are the only crypto; the network is the app's, behind `ISignatureTransport { byte[]? Post(url, contentType, body); byte[]? Get(url) }` (null means failed). Nothing reads a clock: times come from the caller. User text is in `SignatureText`.

**Signing** (`PdfSigner`, static; ISO 32000-1 12.8, ETSI EN 319 142). Always one incremental update; the file's own bytes stay and the signature covers them all.
- `byte[] Sign(byte[] pdf, PdfSignRequest request, string? password = null)` and `void Sign(PdfEditSession, PdfSignRequest)` (a step "Sign", then "Validation data" and "Time stamp" for the levels that add them; changes waiting in the document are signed with it).
- `PdfSignRequest(X509Certificate2 Certificate, DateTimeOffset Time)` with init properties: `Signer` (`delegate byte[] PdfHashSigner(byte[] hash, HashAlgorithmName)`, for a key held elsewhere: RSA PKCS#1 v1.5 or ECDSA as r then s; the certificate then needs no private key), `Chain` (certificates to embed, else the chain the system builds without its root), `Format` (`CadesDetached` default, or `Pkcs7Detached`), `Digest` (SHA-256 default, 384, 512), `FieldName` (an empty signature field, else "Signature1"... is made), `PageIndex`, `Rect` (user space; null or empty is invisible), `Look` (`SignatureLook`: `Text` null for name, date, reason, location, `""` for none; `FontFamily`; `Jpeg` or `Image` (`PdfRgbaImage`); `Ink` strokes in the unit square, y up), `Name`, `Reason`, `Location`, `ContactInfo`, `Certify` (`CertificationLevel` `None`, `NoChanges`, `FormFill`, `Annotate` = /DocMDP P 1 to 3), `Lock` (`FieldLock(FieldLockAction All|Include|Exclude, IReadOnlyList<string> Fields)`, written as /FieldMDP), `Timestamp` (`TimestampSettings(ISignatureTransport, string? Url)`, RFC 3161 token in the unsigned attributes), `Level` (`PadesLevel` B default; T needs `Timestamp`; LT adds /DSS and LTA a document time stamp after it, both through that transport), `Fonts`, `ReserveBytes`.
- The CMS is built by hand (signed attributes content-type, message-digest, signing-certificate-v2 and, for pkcs7, signing-time; RSA as rsaEncryption, ECDSA as ecdsa-with-SHAn). /Contents is a zero placeholder sized from the certificates (4 KB and 14 KB more with a time stamp); a signature that does not fit is made again with twice the room. /ByteRange has one gap, exactly the hex string of /Contents. Signing a rebuilt file writes a full table; a cross-reference stream file gets a stream. Encrypted files work (the signature dictionary's /Contents is never encrypted).
- Field and form: the widget is /F 132 (print, locked), /SigFlags is 3, /AP is a form XObject of the Annotations canvas with the text font from `PdfFontEmbedder` (Turkish letters need `Fonts`; none gives `InvalidOperationException(SignatureText.NoFont)` before anything is changed). A certification is the catalog's /Perms /DocMDP plus a /SigRef with /TransformParams; only a file with no signature can be certified.
- Seed values of the field's /SV are read and obeyed: /Filter, /SubFilter (picks the format), /Reasons, /DigestMethod, /MDP, /TimeStamp (URL), /AddRevInfo (raises the level to LT), /Cert Subject, Issuer, SubjectDN and KeyUsage. A required one that cannot be met throws `InvalidOperationException` with a `SignatureText.Seed...` message; /LegalAttestation, /Cert OID and URL are refused when required and ignored when not. A field's /Lock applies when it is signed.
- Errors are `InvalidOperationException` (key, taken field, certification, time stamp server, room), `ArgumentException` (page, digest other than SHA-2).
- `AddDocumentTimestamp(byte[]|PdfEditSession, TimestampSettings, DateTimeOffset)`: a /DocTimeStamp, ETSI.RFC3161, field "Timestamp1"... over the whole file. The settings need a `Url`.

**Long term validation** (`PdfLongTermValidation`). `Add(byte[] pdf, ISignatureTransport, DateTimeOffset time, string? password = null)` and `Add(PdfEditSession, ...)`: for every signature and every time stamp token in the file the chain is completed (issuers fetched from the AIA links), each certificate gets an OCSP response (POST to its AIA responder), else a CRL (its distribution point), and /DSS gets /Certs, /OCSPs, /CRLs and a /VRI entry keyed by the SHA-1 of /Contents, as one update. Data already in /DSS is reused: a second call adds nothing and returns the same bytes. A certificate nobody answers for is left without. `InvalidOperationException` when there is no signature.

**Servers for validation data** (`PdfLongTermValidation.Servers(byte[] pdf, string? password = null)` and `Servers(PdfEditSession)`; Swift `servers`): the servers `Add` would contact, listed without contacting any, so an app can show them and ask first. Each is `ValidationServer(Kind, Url, Host)` with `Kind` `Ocsp`, `Crl` or `CaIssuers` and `Host` lower case. Per signature and time stamp token the chain is built from the certificates in the file only; the OCSP and CRL links of every certificate that has an issuer in that chain are listed, and, when the top certificate is not self-issued, its own issuer (caIssuers), OCSP and CRL links, since `Add` asks for its revocation data once it has fetched the issuer. Only http and https links count; each URL once, in order of discovery. Issuers `Add` would fetch from those links may name further servers, and data already in /DSS is not subtracted, so the list is what the first round asks. `InvalidOperationException(SignatureText.NotSigned)` when there is no signature.

**Verifying** (`PdfSignatureVerifier.Verify(byte[] pdf, VerifyOptions? = null)` and `Verify(PdfEditSession, ...)`, one `SignatureReport` per signature dictionary found by its /ByteRange in the bytes, in file order, so a signature a later revision unhooked is still seen). `VerifyOptions { TrustAnchors, UseSystemStore, Now, Password, Transport }`; `PdfReadException` only when the file does not open.
- Byte range: four numbers, the first range from 0, the gap exactly the hex string of that object's /Contents, the second range ending at a `%%EOF` (a blank or two after it aside) of a revision that holds the signature. Anything else is `Broken` with `BadByteRange`. Extra non-zero bytes in /Contents are `Broken`.
- CMS: adbe.pkcs7.detached and ETSI.CAdES.detached; digests SHA-1 (reported as `WeakDigest`), 256, 384, 512; RSA keys under 2048 bits and ECDSA keys on curves under 224 bits are reported as `WeakKey`; RSA PKCS#1 v1.5, RSA-PSS with a digest-length salt, ECDSA; with or without signed attributes; signing-certificate-v2 must match the signer. Other sub-filters, algorithms and a missing signer certificate are `Unknown`. The embedded time stamp token is checked against the signature value; its signer chain is judged like the signer's.
- Trust: `X509Chain` with the anchors (and then the system store when asked), judged at the time stamp, else the signer's own claim (signing-time, else /M), else `Now`; without a trusted time stamp the chain is also judged at `Now`, and a certificate that expired since the claim is `CertificateExpired` (the claim is the signer's own). A certificate in the anchors is trusted when it is itself the signer, whatever signed it. Without a `Transport` nothing is downloaded; with one, a partial chain fetches up to four issuer certificates from caIssuers links (each fetched once per `Verify`, a miss too), and a fetched certificate never becomes an anchor. Revocation comes from the signature's revocation-info-archival attribute and the /DSS (OCSP signatures checked, CRLs checked against their issuer); revoked at or before the time stamp, else at or before `Now`, is `CertificateRevoked`, and `RevocationChecked` means every certificate but the last has good data.
- `SignatureReport`: `Index`, `FieldName`, `Kind` (`Approval`, `Certification`, `DocumentTimestamp`), `SubFilter`, `Verdict`, `Problems`, `SignerName` (certificate common name), `Certificate`, `Reason`, `Location`, `SigningTime`, `TimestampTime`, `TimeUsed`, `Certification`, `Level` (B, T, LT; LTA when a later valid document time stamp exists), `CoversWholeFile`, `Revision`, `Changes`, `RevocationChecked`, `Sentence`. `SignatureVerdict`: `Valid`, `ValidButUntrusted` (untrusted chain, not valid at that time, revoked, SHA-1, a weak key, bad time stamp), `ChangedAfterSigning`, `Broken`, `Unknown`.
- Changes: the signed revision and the file as it is are compared object by object (same cross-reference entry means same object; else the text, and stream bytes, are compared). Roles come from the signed revision. The level is the signed file's /DocMDP P, or 0 when it is not certified. Allowed: validation data, /DSS, document time stamps, SigFlags at every level; new signature fields and signing at 0, 2 and 3; filling fields, their appearances, metadata at 2 and 3 (a field locked by /FieldMDP never); annotations created, changed or deleted at 3. Not allowed: page content, /Resources, page tree, new fields other than signatures, a signature field's /V replaced or the field taken out, a new catalog, outlines and everything else reachable. A new object nothing allowed refers to is ignored, unless an object of the signed revision already pointed at its number (a dangling reference woken up). With 16 or fewer revisions in between, a definition after the signed revision that no table lists but whose number the signed revision uses is not allowed (a viewer that scans would show it). A final file that needed a rebuild when the signed one did not is not allowed; a signed revision that needs one is `Unknown` with `DamagedStructure`. `SignatureChangeReport(Changes, RevisionsAfter)`, `SignatureChange(Kind, Object, Page, Field, Allowed)`, `SignatureChangeKind` (`FormFill`, `Signature`, `ValidationData`, `Comment`, `Metadata`, `PageContent`, `PageStructure`, `Form`, `Other`).
- Limits: a signature costs one copy of its revision's bytes; 512 signatures, 100,000 revisions.

**Words.** `SignatureText.Sentence(report)` (the report's `Sentence`): "Signed by Ada on 10 Mar 2026. Not changed since." and its variants (changed only as allowed, not trusted, changed, not valid, could not be checked; "Time stamped on ..."). `Status(verdict)` is five words or fewer. `Title(problem)` says what is wrong, `Advice(problem)` what to do, `Describe(change)` one change. `SignatureProblem`: `UnsupportedFormat`, `BadByteRange`, `DigestMismatch`, `BadSignature`, `NoCertificate`, `UntrustedSigner`, `CertificateNotValid`, `CertificateRevoked`, `ChangedAfterSigning`, `DamagedStructure`, `TimestampInvalid`, `WeakDigest`, `WeakKey`.

**Digital IDs** (`PdfDigitalId`). `X509Certificate2 Create(string name, string? email, DateTimeOffset notBefore, int years = 10, int keyBits = 3072)` (self-signed RSA, digital signature and non-repudiation, e-mail and PDF signing usage), `byte[] ExportPfx(certificate, password)`, `X509Certificate2 ImportPfx(byte[], password)`.

**Revisions** (`PdfRevisions`). `IReadOnlyList<PdfRevision> List(byte[] file)` (`PdfRevision(Number, End)`, oldest first) finds each `startxref` that names a cross-reference table or stream and is closed by `%%EOF`, whatever the chain says; a `startxref` of 0 (linearization) or inside a stream does not count. `byte[] Extract(byte[] file, PdfRevision)` is the file cut at `End`. `PdfEditSession` gained `internal CommitBytes(label, bytes)` for a file built on its current bytes.

**Tests.** `LazyPDF.Core.Tests/Signatures/`: a CA chain, an RSA and an ECDSA signer, a time stamp server, OCSP responder and CRL host made in the tests; each key and format; visible, picture and ink; certification, locks and seed values; time stamps, B-LT, B-LTA; the five attacks (incremental save, shadow overlay, hidden or dangling objects, short or wide byte ranges and a field replaced, table tricks); signatures made by the framework; damaged-file fuzzing; a corpus run under `LAZYPDF_CORPUS`. Files were checked with `openssl cms -verify`, pyHanko and pypdf, and drawn through Windows.Data.Pdf.

### Crypt: public-key handler, /Perms, changing encryption

Files: `PdfSecurityPublicKey.cs`, `PdfRecipient.cs` in `Crypt/`; small additions to `PdfSecurity.cs`, `PdfKeys.cs`, `PdfDocument.cs`, `PdfDocument.Security.cs`, `PdfDocument.Save.cs` and the `PdfReadProblem` enum. Uses `System.Security.Cryptography.Pkcs` (`EnvelopedCms`).

```csharp
public sealed record PdfRecipient(X509Certificate2 Certificate, PdfPermissions Permissions = PdfPermissions.All,
                                  bool CanChangeEncryption = false)
{ static bool CanProtect(X509Certificate2 certificate); }
// PdfSecurity (additions)
static PdfSecurity? OpenPublicKey(PdfDictionary encrypt, X509Certificate2 certificate);

bool IsPublicKey { get; }
bool PermsMismatch { get; }
// PdfDocument (additions)
static PdfDocument Open(byte[] bytes, X509Certificate2 certificate);
static PdfDocument Open(string path, X509Certificate2 certificate);
// PdfReadProblem (addition)
CertificateRequired
```

**Public-key files.** `/Filter /Adobe.PubSec` with `/SubFilter adbe.pkcs7.s4` and `/V 4` (AESV2, or V2 on read) or `adbe.pkcs7.s5` and `/V 5` (AESV3). The recipients are in the crypt filter named by `/StmF` (`/Recipients`, an array of strings, at most 1000 read), each a CMS EnvelopedData holding a 20-byte seed and the recipient's 4 permission bytes (ISO 32000-1 7.6.4.3, big-endian, bit 2 = may change the encryption, the others as in `/P`). The file key is SHA-1 (first 16 bytes, V 4) or SHA-256 (V 5) of the seed, every EnvelopedData as stored and, when `/EncryptMetadata` is false, four 0xFF bytes. Strings and streams then follow the standard rules (algorithm 1 for V 4, the key itself for V 5). s3 (V 1 and 2) is `Unsupported`. `/EncryptMetadata` is read from the crypt filter, else the top level.

**Reading.** `PdfDocument.Open(bytes, certificate)` needs a certificate with its private key. `OpenPublicKey` returns null when no recipient opens with it (not a recipient, no private key, damaged entries are skipped); the document turns that into `PdfReadException` `CertificateRequired`. Opening a public-key file with no certificate or only a password is `CertificateRequired` too. A file with the standard handler opened with a certificate behaves as `Open(bytes, null)` (empty user password, else `PasswordRequired`); an unencrypted file ignores it. `Unsupported` for another SubFilter, V, or a cipher that does not fit the V; `Damaged` for a missing crypt filter or `/Recipients`. `Permissions` and `OpenedAsOwner` are those of the matching recipient (`OpenedAsOwner` is bit 2). `Revision` is 4 for V 4 and 6 for V 5.

**Writing.** `CreatePublicKey` makes one EnvelopedData per recipient (RSA key transport or elliptic curve key agreement, AES-256-CBC content), all with the same seed, so recipients differ only in permissions. `Aes256` gives s5, `Aes128` s4. Seed and content keys come from the system generator, so output is never repeatable. Pass the handler as `PdfSaveOptions.Security`; the header is raised to 1.6 or 1.7 as for the standard handler. The handler is an owner with all permissions. One to 1000 recipients, else `ArgumentException`. Recipients must have an RSA key that may encipher, or a P-256 or P-384 key whose key usage, if stated, includes key agreement (`PdfRecipient.CanProtect`); others, such as P-521 or a signing-only EC key, are refused with `ArgumentException`. Output was decrypted outside the engine (openssl cms on a recipient entry, then the file key and a stream by hand); PdfPig and pypdf cannot read this handler.

**Elliptic curve recipients.** `EnvelopedCms` cannot write or open a KeyAgreeRecipientInfo, so `PdfCmsAgreement.cs` (C#) and `PdfCmsAgreement.swift` (Swift, with the ECDH step in `PdfSecurityPublicKey.swift`) do it by hand (RFC 5753, RFC 5652 6.2.2). Written: EnvelopedData version 2, one `[1]` KeyAgreeRecipientInfo (version 3) per recipient with an `originatorKey` (id-ecPublicKey, the curve, the ephemeral uncompressed point), no ukm, key encryption algorithm dhSinglePass-stdDH-sha256kdf (P-256) or sha384kdf (P-384) with id-aes256-wrap as its parameter, and the recipient named by issuer and serial number. The key encryption key is the ANSI X9.63 KDF over the ECDH secret: Hash(Z || counter 1 as 32 bits || ECC-CMS-SharedInfo), shared info being the wrap algorithm without parameters, the ukm if any as `[0]`, and the key length in bits (256) as a 4-byte `[2]`. The AES-256 content key is wrapped with RFC 3394 and the content is AES-256-CBC as for RSA. Read: P-256, P-384 and P-521 originator keys (the curve in the key's algorithm parameters, or, when they are absent or NULL as OpenSSL and BouncyCastle write them, the recipient's own key's curve), the SHA-1, SHA-256, SHA-384 and SHA-512 forms of the KDF (standard or cofactor ECDH, the same on these curves), AES-128, 192 and 256 wrap, and AES-128, 192 and 256 CBC content. Entries are not matched to the certificate by name: every encrypted key is tried and the key wrap check (the A6A6A6A6A6A6A6A6 integrity value) decides, so a wrong certificate, a wrong curve or a damaged entry gives no match, never an exception. The recipient is opened with `ECDiffieHellman` from the certificate's private key; a key the system stores for signing only (a non-exportable ECDSA key in a Windows key store) cannot take part, and that certificate does not open the file. Checked outside the engine with `openssl cms -decrypt` on a P-256 and a P-384 entry; the golden envelopes in `EcGolden.cs` and `EcGolden.swift` are the C# output with every random input fixed, and the Swift engine writes the same bytes from the same ECDH secret.

**`/Perms`.** On R 6 the 16 bytes are decrypted with the file key and checked against `/P`, `/EncryptMetadata` and the marker `adb` (ISO 32000-2 7.6.4.4.9). `PermsMismatch` is true when `/Perms` is missing, short or disagrees; the file still opens and `Permissions` is still `/P`. It is false for R 2 to 5, public-key files and new handlers. The caller decides what to say.

**Changing encryption.** `SaveRewrite` writes the file with any `PdfSaveOptions.Security`: a `PdfSecurity.Create` handler for a password, `CreatePublicKey` for certificates, null for none. The rule is the same for both handlers. Keeping `document.Security` itself is always allowed, as is encrypting a file that has no encryption. Otherwise, if the opener is not an owner (`OpenedAsOwner` false: the user password, or a recipient without `CanChangeEncryption`) and `Permissions` is not `All`, `SaveRewrite` throws `UnauthorizedAccessException` before writing anything. With all permissions granted the restriction would protect nothing, so such an opener may change or remove the encryption. The owner password itself is only ever checked by `PdfSecurity.Open`; nothing re-asks for it at save time. `SaveIncremental` keeps the handler and has no such check.

**Not done.** `PdfEditSession`, `PdfFileSaver` and the `Save` readback take a password only: a public-key file cannot go through them until they carry the certificate. Signing and `/Perms` writing for R 5 are untouched.

**Tests.** `windows/LazyPDF.Core.Tests/Crypt/PublicKey*Tests.cs`: round trips for both strengths with and without object streams, two recipients with different permissions, wrong, missing and key-less certificates, malformed dictionaries, recipient list bounds, `/Perms` tampering, rights to change encryption for both handlers. Certificates come from `CertificateRequest`.

### Optimize: smaller files, clean for sharing

Folder `Optimize/`, uses Document, Content, Filters, Fonts and Structure (and Forms for form data). Nothing is saved or drawn here and the document passed in is never changed: both classes work on a copy made from a plain `SaveRewrite`, and return the new file's bytes. An encrypted source comes out open unless a handler is passed in the options. Signatures do not survive; the app checks `IsSigned` first. User words are in `OptimizeText`.

**`PdfOptimizer(PdfDocument, IImageCodec? codec = null)`**
- `SpaceAudit Audit()`: `SpaceAudit(long FileSize, IReadOnlyDictionary<SpaceKind, long> Bytes)`, `Of(kind)`. `SpaceKind`: Images, Fonts, Content, Forms, Annotations, Metadata, Structure, Attachments, Overhead, Unreferenced. Every reachable object goes to the first of these that reaches it (info and metadata, attachments, form, page tree, annotations, rest of the catalog); an image is Images and a font object Fonts wherever they are met. Overhead is what the objects leave of the file size; the kinds add up to `FileSize`.
- `OptimizePlan Plan(OptimizeOptions)`: `OptimizePlan(SpaceAudit Audit, IReadOnlyList<OptimizeStepKind> Steps)`, the steps the options turn on, `RemoveUnreferenced` first.
- `OptimizeResult Run(OptimizeOptions, CancellationToken cancel = default)`: `OptimizeResult(byte[] Bytes, long SizeBefore, long SizeAfter, SpaceAudit Audit, IReadOnlyList<OptimizeStepResult> Steps, IReadOnlyList<string> Notes, int Dropped = 0)`; `OptimizeStepResult(Kind, Count)`. `Dropped` is that count for the plain rewrite the run starts from. Notes are from `OptimizeText` (images that needed a codec, colour left, fonts left whole). Run throws OperationCanceledException when the token is raised, between steps and between images and streams.
- `OptimizeOptions` (record, init properties): `ObjectStreams`, `RecompressStreams`, `ConvertOldFilters`, `RemoveDuplicates`, `StripThumbnails`, `StripPieceInfo` (all on), `StripPrivateData`, `PruneResources` (on), `ImageDpi` (target, 0 leaves images), `ImageDpiAbove`, `JpegQuality` (75), `BilevelTolerance` (-1 off), `SubsetFonts`, `Grayscale`, `Security`, `DocumentId`. `OptimizeOptions.For(OptimizePreset.Small | Balanced | HighQuality)`: Small 96 dpi above 144, quality 50, tolerance 24, fonts trimmed, private keys stripped; Balanced 150 above 225, quality 80, no 1-bit step, fonts trimmed; HighQuality 300 above 450, quality 92, tolerance 0, application data kept.
- Result size: the best of the file with and without object streams, and never above a plain rewrite, except with `Grayscale`, `Security` or `DocumentId`, which change the file on purpose.

**Steps.**
- Recompress: every Flate stream is deflated again at the smallest level and kept when smaller. LZW, ASCII85, ASCIIHex and RunLength streams become Flate; a predictor stays on the new stream, and a chain with a predictor before its last stage is left. Metadata, streams that do not decode and image codecs are never touched.
- Duplicates: streams equal in dictionary (references compared after merging, up to eight rounds) and bytes, and plain dictionaries of fonts, descriptors, graphics states and functions. Pages, annotations and the like never merge.
- Strip: `/Thumb`; `/PieceInfo` everywhere; private data is `/LastModified` and second-class keys (prefix and `_` or `:`, not `GTS_`) of the catalog, pages, forms and images. Resources: names of `Font XObject ExtGState ColorSpace Pattern Shading Properties` that no content names; a dictionary shared by owners keeps the union; unreadable content, a Type 3 font with its own resources or without any, leave it whole.
- Images: placed resolution is the lowest pixels per inch over every use the interpreter finds, in pages, forms, patterns and appearance streams. Those above `ImageDpiAbove` are averaged down to `ImageDpi`, each side by its own factor. Flate and raw images keep their colour space, `/Decode` and `/SMask` (shrunk on its own, same factor); Indexed becomes RGB. JPEG and JPEG 2000 go through the codec to RGB and `EncodeJpeg`; not with `/Decode`, CMYK or Lab, `/SMaskInData`, colour-key or stencil `/Mask`, 1-bit images, or images only a Type 3 glyph reaches. An image is replaced only when the new data is smaller. Bilevel: images with every pixel within the tolerance of black or white become 1-bit DeviceGray (not with `/Decode` or colour-key masks).
- Fonts: TrueType programs with `glyf`, not already tagged as subsets, subsetting allowed, whose every font dictionary is listed only in `/Resources /Font` dictionaries. Used codes come from the interpreter (pages and appearance streams); a simple font keeps every glyph any of WinAnsi, MacRoman, Standard, `/Differences` and the symbolic cmap ranges could pick. Unused outlines are emptied and the rest stays in place (glyph numbers, cmap, metrics, tables head hhea maxp hmtx loca glyf cmap cvt fpgm prep name post OS/2 kept), so no code changes. A font also named by `/DR`, `/DA` or an ExtGState is left whole.
- Grayscale: colour operators in pages, forms and patterns (`rg RG k K cs CS sc scn`) by luminance, tracked through `q`/`Q`; in a form with no known colour space the operand count decides. Images of RGB, CMYK, ICC, Cal and Indexed spaces become DeviceGray (JPEG through the codec, as RGB with equal channels). Left and counted: shadings, patterns, Separation, DeviceN, Lab, inline images, images with colour-key masks.

**`PdfSanitizer(PdfDocument)`**
- `IReadOnlyList<SanitizeFinding> Scan()`: `SanitizeFinding(SanitizeItem Item, int Count)` in enum order, nothing for a count of 0.
- `SanitizeResult Run(SanitizeOptions)`: `SanitizeResult(byte[] Bytes, IReadOnlyList<SanitizeFinding> Removed, IReadOnlyList<SanitizeFinding> Kept, long SizeBefore, long SizeAfter)`. `Kept` is what was found and left: an option off, hidden text, invisible text not asked for. Options are bools on by default except `InvisibleText`, plus `Security` and `DocumentId`.
- Items: JavaScript (document, page, field, annotation `/A` and `/AA`, `/OpenAction`, the `/Names /JavaScript` tree, XFA with a script), LaunchActions (Launch, GoToR, GoToE, ImportData, SubmitForm, Thread, Movie, Sound, Rendition, RichMediaExecute), ExternalLinks (URI actions, `/URI /Base`), EmbeddedFiles (name tree, FileAttachment annotations, `/AF`, `/EF`, `/Collection`), HiddenLayers, HiddenText, InvisibleText, Comments (every annotation except Link, Widget and media, popups with them), FormData, Metadata (`/Info`, every `/Metadata` stream, `/LastModified`), PieceInfo, Thumbnails, PreviousVersions (always; the file is rewritten), SearchIndexes (`/SpiderInfo`, `/Names /IDS`, `/URLS`, page `/ID`), FilePaths (file specifications cut to the bare name, platform names dropped). `/Alt` is not touched.
- Actions are removed where they hang; in a `/Next` chain only the unwanted ones go. Form data: `/DV` is removed and the form reset, so appearances are drawn again; `/XFA` goes.
- Hidden layers: groups off in the default configuration. The `BDC ... EMC` spans of `/OC` (a group, or a membership dictionary by its `/P`; `/VE` counts as visible), `Do` of an image or form with a hidden `/OC` and annotations with one are cut out of the page and form streams (found by the interpreter, cut by operation range), the resources they named are pruned, and the groups leave `/OCProperties`, `/Order`, `/OFF` and every reference.
- Hidden text is only reported: runs whose glyphs are white where nothing darker was painted before (fill colour from the interpreter), or that lie wholly under an opaque image painted later. Invisible text is render mode 3; with `InvisibleText` the shows go from text objects whose every show is mode 3 (`'` and `"` keep their line move); a text object that also shows visible text is left and stays in `Kept`.

**Limits.** Scans stop at 100,000 glyphs and 20,000 paints a page. Images over 16 million pixels are not made bilevel or gray. Tests: `LazyPDF.Core.Tests/Optimize/`, every output reopened in `PdfDocument` and PdfPig, images with a fake codec, markers searched in raw and decoded bytes, a corpus run under `LAZYPDF_CORPUS`.

### Linearize: fast web view

Files `Optimize/Linearizer*.cs`, namespace `LazyPDF.Core`. Writes ISO 32000-1 Annex F files, laid out so a viewer can show page one and then any other page without reading the whole file. Uses Document only; everything is built in memory.

**`byte[] PdfDocument.SaveLinearized(PdfSaveOptions? options = null)`** (a member of the partial `PdfDocument`, in `LinearizerSave.cs`). Like `SaveRewrite` it writes the objects reachable from `/Root` and `/Info` and `document.Pages`, numbered afresh, generation 0, no history; references to nothing are dropped. `Security` and `DocumentId` are read as `SaveRewrite` reads them (null leaves the output open, the document's own handler keeps the encryption and its first `/ID`; the same owner-rights rule applies and `UnauthorizedAccessException` follows it). `UseObjectStreams` is ignored: both cross-reference sections are tables. Streams are copied as stored, never recompressed. The header is raised to 1.2, 1.6 or 1.7 as the encryption needs. Signatures do not survive; the app checks `IsSigned` first. A document with no pages throws `InvalidOperationException`; one over about 2 GB or whose walks pass 100 million visits is `PdfReadException` `Unsupported`.

**`bool IsLinearized`** is true when the first object is a dictionary with `/Linearized` and its `/L` equals the length of the file. A file with an update added, or cut short, is valid and reads as before, but is no longer linearized. `internal bool WasLinearized` ignores `/L` (the sanitizer's version count needs it: a linearized file has two sections that are one version, and after an update they still are).

**Layout.** Header; linearization dictionary (`/L /H /O /E /N /T`, fixed-width fields padded with spaces); first-page cross-reference table and trailer (`/Size` of the whole file, `/Root /Info /Encrypt /ID`, `/Prev` to the main table, `startxref 0`); the catalog and the objects of `/ViewerPreferences`, `/PageMode`, `/Threads`, `/OpenAction` and `/AcroForm` (what those reach is there whichever page uses it); the encryption dictionary; the hint stream; the first page (page object, content streams, then everything it uses, including objects shared with other pages, and the bookmarks when `/PageMode` is `/UseOutlines`); the other pages, each its page object, content streams and private objects; objects shared by pages other than the first, in order of first use; everything else (page tree, bookmarks otherwise, name trees, `/Info`, thumbnails); the main table, trailer and `startxref` naming the first table. Objects are numbered in file order, the main section's first (1 to `/T`'s table), then the first section's (linearization dictionary first), so each table is one run.
- A walk from a page stops at other page objects (a link does not pull in its target), leaves out `/Parent` and `/Thumb`, and treats what the open-document keys reach as not the page's. An object used by one page and its thumbnail goes with the thumbnails.
- Inherited `/Resources /MediaBox /CropBox /Rotate` are copied onto the pages and taken off the tree nodes; inherited direct resources become one object the pages share. A page with no resources gets an empty set. A tree that does not reach exactly the pages `document.Pages` lists, once each, or whose `/Count` is wrong, is replaced by one node over all pages; a clean tree keeps its shape. An integer past 64 bits is written as a real.

**Hint tables** (F.4, in the one hint stream, uncompressed, `/S` and `/O` naming the shared and outline tables). Offsets in them leave out the hint stream's own length, as the annex says. Page offset table: object count and length per page (the first page's count is everything in its section), shared references per page as indexes into the shared table, content stream offset and length inside the page (0 and 0 when the content streams are shared). Shared object table: the first page's objects one group each, then the shared section's, so the groups tile the file from the first page onward; each group is one object, with no MD5. Outline table when `/Outlines` exists.
- Left at simple values: the fraction of the page where a shared reference first occurs is 0 of 4 for all; every shared group is a single object; no signatures in groups. Not written: the optional thumbnail, thread, named destination, interactive form, `/Info` and page label tables (a reader finds those objects through the cross-reference tables).

**Checked.** qpdf 12.4 (`--check-linearization`) passes the output for all 294 files of the corpus that open, for unit-test files in every layout (plain, AES-128, AES-256, owner-only, nested trees, forms, thumbnails, bookmarks, inherited resources, large page counts) and for encrypted ones; it reads the hint tables back against its own layout rules. The tests carry their own reader of the tables, which compares them with the real object positions and the objects each page reaches. Output reopens in PdfPig, pypdf (strict) and `Windows.Data.Pdf`, whose first page matches the original's pixel for pixel.

**Tests.** `LazyPDF.Core.Tests/Optimize/Linearizer*Tests.cs` with `LinearizerKit.cs`: layout and hint tables on files of 1 to 300 pages, inheritance, links, bookmarks, thumbnails, open-document keys, encryption in each form, updates and `IsLinearized` after them, every source layout (table, stream, hybrid, object streams), repaired and malformed input, and a corpus run under `LAZYPDF_CORPUS` (page count, text, layout and PdfPig; `LAZYPDF_CORPUS_OUT` keeps the files).

### Standards: PDF/A checks and conversion

Folder `Standards/`, namespace `LazyPDF.Core`. Uses Document and Content, and for drawing missing appearances Annotations and Forms. Nothing is saved here and nothing reads a clock: the caller passes the date. Reading never throws on file contents (a file that does not open is a `PdfReadException` at `Open`); every walk is iterative or capped. PDF/X is out of scope, PDF/UA belongs to accessibility.

**Levels.** `enum PdfALevel { A1b, A2b, A2u, A3b, A3u, A4 }`; `PdfALevels` gives `Part()`, `Conformance()` ("B", "U", null for part 4), `NeedsUnicode()`, `Name()` ("PDF/A-2u"). Level A of parts 1 to 3 (tagging) is not checked. Part 4 means the plain "4", not 4e or 4f.

**`PdfAValidator.Validate(PdfDocument, PdfALevel) -> PdfAReport`.** `PdfAReport(Level, IReadOnlyList<PdfAIssue> Issues, bool Truncated)` with `IsValid`; `PdfAIssue(string Clause, string Where, string Message)`: the clause of ISO 19005 ("6.2.11.4.1"), a place ("Page 3", "Page 2, annotation 4", "Font ABCDEF+Arial", "Object 12", "Catalog", "Metadata") and one plain sentence from `PdfAText`. Listing stops at 1000 issues (`Truncated`); equal issues are listed once. Clause numbers are given for part 1 and for parts 2 and 3; part 4 is held to the part 2 numbers although ISO 19005-4 numbers some clauses differently.
- File: header version (1.0 to 1.7, 2.0 for part 4) and the binary comment; `%%EOF` last, at most one line break after it; `/ID` pair; no `/Encrypt`; rebuilt cross-reference data; part 1 also xref streams and object streams; stream keyword followed by CRLF or LF, `/Length` exact; `/F`, `/FFilter`, `/FDecodeParms`; LZW and Crypt filters; limits (integer range, name 127 bytes, string 65535 in part 1 and 32767 later, array 8191 and dictionary 4095 in part 1, q nesting 28, DeviceN 32).
- Content, found with the interpreter and a scan of every resource dictionary (so unused forms, patterns, graphics states and Type 3 procedures are held to the same rules): undefined operators, device colour without an output intent or default space (RGB needs an RGB intent, CMYK a CMYK one, gray any), ICC profile size, class, colour space against `/N` and version (2 in part 1, 4 later), Separation names with different alternates, rendering intents, `/TR`, `/TR2`, `/HTP`, `/Interpolate`, `/OPI`, `/Alternates`, `/Ref`, PostScript XObjects, JPX in part 1, and for part 1 every kind of transparency (opacity, blend mode, soft mask, image mask data, groups).
- Fonts: embedded and readable, `/FontFile3` subtype, widths of the glyphs shown against the program (1/1000 tolerance), `/Widths` present, `/CIDSet` and `/CharSet` covering the glyphs shown, CMap predefined or embedded, `/CIDSystemInfo`, `/CIDToGIDMap` on TrueType CID fonts, symbolic and non-symbolic TrueType encodings, and at level U a `/ToUnicode` or a Latin encoding whose glyph names map.
- Annotations: allowed subtypes by part, Print flag set and Hidden, Invisible, NoView clear (not for Popup), `/AP` with only `/N` (a stream, a state dictionary for buttons; Links and Popups need none), `/CA` in part 1; their appearance streams are walked. Actions: Launch, Sound, Movie, ResetForm, ImportData, Hide, SetOCGState, Rendition, Trans, GoTo3DView, JavaScript, Named other than the four page ones, along `/Next` chains and `/AA`; catalog and field `/AA`; `/NeedAppearances`; XFA.
- Catalog: `/Metadata` readable as XMP, `pdfaid:part` and `conformance` (`rev` 2020 for part 4), properties of unknown namespaces without an extension schema declaring the namespace (property names are not checked), `/Info` against the XMP (not in part 4, which allows only the two dates in `/Info`), output intents (identifier, profile, one profile for all), optional content (none in part 1; later a unique `/Name` per configuration, no `/AS`, `/Order` naming every group), embedded files (none in parts 1 and 4, PDF/A files in part 2, `/AFRelationship` and a MIME type in part 3).

**`PdfAConverter(IFontSource? fonts = null).Convert(byte[] pdf, PdfALevel level, DateTimeOffset date, string? password = null) -> PdfAConversion`.** `PdfAConversion(byte[]? Bytes, string? Refusal, IReadOnlyList<PdfAIssue> Remaining, IReadOnlyList<string> Changes)` with `IsClean`. It is a rewrite (`SaveRewrite`, no object streams) of a private copy; the result is validated and what remains is returned. `Changes` says in sentences what was altered.
- Refused (`Bytes` null, `Refusal` says why): not a PDF or wrong password; an encrypted file opened without owner rights or the Modify permission; a dynamic XFA form; part 1 with transparency in use (opacity, blend modes, soft masks, images with soft masks), since flattening is not done. A transparency group nothing needs is dropped in part 1.
- Done: encryption removed; the actions, scripts and annotation types above removed; Print flag set, hidden flags cleared, `/AP` cut to `/N`; missing appearances drawn (`PdfAnnotationWriter.Regenerate`, `PdfForm.Regenerate`), `/NeedAppearances` and `/XFA` dropped; LZW and Crypt stages recompressed with Flate, image codecs kept; `/Interpolate`, `/OPI`, `/Alternates`, `/Ref`, transfer functions and bad rendering intents removed; integers past 32 bits cut to the limit; layers dropped in part 1 and named, unique and without `/AS` later; attachments removed (parts 1, 4, and part 2 unless PDF/A), described in part 3; sRGB output intent added when no usable profile is there (an existing one is kept and labelled GTS_PDFA1); new XMP with identification, `/Info` made to agree (dates: creation kept or `date`, modified `date`); header set to 1.4, 1.7 or 2.0.
- Fonts: a font that is not embedded is changed in place into a Type0 font with a subset of the closest font the source gives (Arial, Times New Roman, Courier New, Symbol for the Standard 14; the name's family otherwise, else by flags), a one-byte embedded CMap keeping the content's codes, widths and `/ToUnicode` from the original text. A non-embedded Type0 font over Identity-H with a `/ToUnicode` gets a `/CIDToGIDMap`. Embedded fonts get widths from the program, a wrong `/CIDSet` or `/CharSet` dropped, TrueType encodings corrected and a `/ToUnicode` at level U.
- Not done, reported in `Remaining`: DeviceCMYK without a CMYK intent, JPX in part 1, text with no source font or no Unicode, unreadable font files, Type0 fonts over other CMaps, strings past the limit, hex string syntax (the reader cannot see it), transparency checks of part 2 and later beyond the group and device colour rules.

**Additive change elsewhere.** `Content/PdfFont.Metrics.cs`: internal `GlyphNameOf(code)`, `ProgramWidth(code)`, `ProgramCidWidth(cid)`, `CidWidths`.

To part 1, 124 clean, 10 with rules left, 165 refused for transparency. ### Accessibility: structure tree, auto tagging, checker, read-out order

Folder `Accessibility/`, namespace `LazyPDF.Core`. Uses Document, Content, Text, Structure (`PdfNumberTree`, `PdfText`, `DocumentMetadata`, `ViewerSettings`, `Outline`) and Forms (`PdfForm`, read only). Everything works on an open `PdfDocument` in memory; the edit session commits it. User text is in `AccessibilityText`. Reading never throws on file contents; trees, kids and content passes are capped.

**`StructureTree`** (ISO 32000-1 14.7, 14.8), a snapshot like `Outline`.
- `Read(document)` is null without `/StructTreeRoot`; `Create(document)` is empty and gets its root object at `Write`. `Roots`, `Elements` (parents first), `Contents`, `RoleMap`, `ClassMap` (both editable), `ParentTree` (entries as stored), `Dictionary`, `IsTruncated`, `ElementFor(key, mcid)` (the element a parent tree key names; `mcid` -1 for an object), `StandardType(type)` (through the role map, 16 hops, cycles stop), `static IsStandard(type)` (H1 to H999 count).
- `StructElement` (sealed): `Type`, `Title`, `Alt`, `Lang`, `ActualText`, `Id`, `PageIndex` (-1 none), `Reference`, `Dictionary` (live; `/A`, `/C`, `/R` and other keys stay), `Parent`, `Kids`, `Children`. Kids derive from `StructKid`: `StructElement`, `StructContent(PageIndex, Mcid, Stream)` (a marked-content sequence, in a form when `Stream` is set), `StructObject(PageIndex, Target)` (an OBJR).
- Editing: properties are settable; `Add(parent, kid, index = -1)` (null parent is the root), `Remove(kid)` (frees the objects at `Write`), `Move(kid, parent, index)` (also reorders; into itself is `ArgumentException`). `Write(document)` writes every element (a value already in place is left alone, so one edit changes few objects), `/K` of the root, `/RoleMap`, `/ClassMap`, `/ParentTree` (rebuilt from the elements with `PdfNumberTree.Write`; pages, forms and objects without a `/StructParents` or `/StructParent` get one), `/ParentTreeNextKey`, `/MarkInfo /Marked`. Content on the element's page is written as an integer, other content as an MCR. A truncated tree throws `InvalidOperationException` at `Write`.
- Read limits: 1,000,000 nodes, 128 levels, MCID up to 1,000,000; an element met twice is read once, junk kids are skipped, a missing `/S` reads as type "".

**`AutoTagger.Tag(document, AutoTagOptions? = null, CancellationToken = default)`** gives `AutoTagResult(AlreadyTagged, Pages, SkippedPages, Headings, Paragraphs, Lists, Tables, Figures, Artifacts, FiguresWithoutAlt)`. A document with a `/StructTreeRoot` or `/MarkInfo /Marked` is left alone (`AlreadyTagged`). `AutoTagOptions(Language)` sets `/Lang` when the file has none.
- Reading order is `TextPage`'s. Body size is the commonest size. A heading is a line at 1.15 times the body size or more (up to 4 lines), or a short bold line at body size (up to 2, not ending in a full stop); looks are ranked by size then weight into H1 to H6, and a level never goes more than one below the one before. Lists are two or more lines with the same kind of marker (bullets, `1.`, `a)`, `(i)`), a line without marker under an item belongs to it, and a marker in its own show operation becomes `Lbl` (else the item is `LBody` only). A table is a `TextPage` table block whose rows all have the same number of cells; the first row is `TH` with `/Scope /Column`. Paragraphs break at a gap over half the text size. Images are `Figure` with no `/Alt` (listed in the result); an image under 2 points is an artifact.
- Running headers and footers are lines in the top or bottom tenth that repeat (digits folded) on half the pages, and any page number such as "3", "Page 3 of 9" or "iv" in those bands; with one page only the page number goes. Paths, shadings, unclaimed text and images and tiny images are `/Artifact`. Content already in an `/Artifact` or a sequence with an `/MCID` is not touched.
- Content: each page gets `/Tag <</MCID n>> BDC ... EMC` around the show operations of one element, joined only while nothing between them is a text object, `q`, `Q`, `cm` or other marked content. Text drawn by a form is marked around its `Do`. The page's own streams stay separate; they are joined into one new stream only when an operator stands in a later stream than its operands. A page is skipped (and left unchanged) when its content is shared with another page, a stream cannot be read, or the interpreter ran past its limit; if every page is skipped nothing is written.
- Link, Widget and other annotations (not popups or hidden ones) get `Link`, `Form` or `Annot` elements holding an OBJR; a link gets `/Alt` from the text under it, its `/Contents`, or its URI, and `/Contents` when it had none. `/Tabs /S` is set on tagged pages. Nothing is saved.

**`AccessibilityChecker.Check(document, CancellationToken = default)`** gives `AccessibilityReport(Items)` with `Passed`, `Failed`, `NeedsPerson`, `this[AccessibilityRule]`. An `AccessibilityItem(Rule, Name, Status, Message, Where, Fix)`; `Status` is `Passed`, `Failed` or `NeedsPerson`; `Where` is up to 50 `AccessibilityPlace(PageIndex, Element)`; the message counts them all and names the first page.
- Rules, in order: `Tagged` (marked, a tree with roots, no `/Suspects`), `Title` (title and `DisplayDocTitle`), `Language` (`/Lang` as a language tag), `Security` (the accessibility permission), `Bookmarks` (over 20 pages), `Searchable` (no page with images and no text), `Encoding` (every shown glyph has Unicode text), `TaggedContent` (everything drawn is in an `/Artifact` or an `/MCID` that the tree holds), `TabOrder` (`/Tabs /S` on pages with annotations), `Contrast` (always `NeedsPerson`), `FigureAlt`, `TableStructure` (TR, TH, TD, same cells per row unless spans), `TableHeaders`, `ListStructure`, `HeadingOrder` (H1 first, no skipped level, not H with Hn), `RoleMap`, `Links` (tagged, with text or description), `FormNames` (name and tooltip), `FormTagged`. Without a tree the rules that need one are `NeedsPerson`.
- `Fix(document, AccessibilityFix, string? value = null)` returns whether something changed: `SetTitle` (value; also turns on `DisplayDocTitle`), `ShowTitle`, `SetLanguage` (value, a tag like `en-US`; a bad one is `ArgumentException`), `SetTabOrder`. The item's `Fix` says which applies.

**`ReadingOrder.Export(document, StructureTree? = null)`** gives the text in tag order, one line per block: `#` times the level before a heading, list items with their label, table rows with tabs, `[Figure: alt]`. Artifacts are not in it. Empty without tags.

**Limits.** Layout is that of `TextPage`: no tags for scanned pages without text, columns follow its order, a figure is placed by position. Tables with merged or empty cells are paragraphs. Text drawn by one form in two places is an artifact. No PDF/UA identification in XMP. Contrast and the sense of alt text are for a person. **Tests.** `LazyPDF.Core.Tests/Accessibility/`: hand-made tagged files, malformed trees, edits and reopen through PdfDocument and PdfPig, auto tagging of a report with PdfPig and `TextPage` text compared before and after, split streams, artifacts, encryption, every rule passing and failing, and a corpus run under `LAZYPDF_CORPUS`.

### Compare: documents, pages, report

Folder `Compare/`, uses Text (and Annotations, Structure, Forms, Pages, Content for the report). Nothing is saved or drawn here; page pictures come in through `IPageRenderer`. Nothing throws on file contents. User words are in `CompareText`.

**`PdfComparer.Compare(PdfDocument before, PdfDocument after, CompareOptions? options = null, CancellationToken = default) -> ComparisonResult`.** `CompareOptions(IgnoreCase, IgnoreWhiteSpace, IgnoreHeaderFooter)`: the last drops words whose centre is in the top or bottom 7% of the page as shown; `IgnoreWhiteSpace` makes "data base" and "database" equal. Throws `OperationCanceledException`. Compared: words, fonts, pictures and annotations of paired pages, and the metadata, bookmarks, attachments and form values of the files. Not compared: paths and shadings (use `PixelComparer`), text a font gives no Unicode for, popups and widgets as annotations.

**Result.** `ComparisonResult(Pages, Changes, Summary, OldPageCount, NewPageCount)`, `IsIdentical`. `PagePair(OldIndex, NewIndex, Similarity, Moved)` with `IsAdded`, `IsRemoved` (index -1 on the side without the page), in new-file order with removed pages where they stood. `CompareChange(Kind, Area, OldPage, NewPage, OldText, NewText, OldQuads, NewQuads, Detail)`: `ChangeKind` Added, Removed, Changed, Moved; `ChangeArea` Text, Format, Image, Annotation, Page, Document. Quads are `TextQuad` in user space of the page on their side. A side with no content of its own holds a quad of zero width where the text was removed or would go; for pictures and annotations the other side holds the same area; a removed page has no new quads, an added page no old ones; document changes have none. `Detail` says what differs (font, size and colour, picture moved or replaced, which annotation fields, bookmark, metadata field, form field, page size). `ComparisonSummary` counts by kind and by area, `WordsAdded`, `WordsRemoved`, `Total`.

**Pairing pages.** By similarity of page text, never by number: Dice on the hashed word pairs, candidates from an inverted index (words in more than 64 pages are skipped) plus the same-numbered neighbours and identical pages. The pairs in order with the most total similarity (at least 0.5) are anchors; leftover pages that are alike (0.5) are paired as moved; a gap with as many old as new pages is paired by position when the pages are 0.15 alike or both have under ten words. A page with under ten words also counts its picture hashes, so scans and slides pair. Others are inserted or removed.

**Words.** Myers shortest edit script over word ids per pair; past 2000 edits the stretch between the common ends is one change. A pure insertion or deletion slides to line boundaries. Neighbouring insert and delete are one `Changed`. A deleted and an inserted block of four words or more with the same words, on any pages, is one `Moved` (OldPage, NewPage, quads of both). A changed paragraph inside a move is not found. Equal words in another font, size (0.1 pt) or colour make `Format` changes, one per neighbouring run with the same difference. Pictures are matched by size and SHA-256 of the stored data, then place (1 pt); annotations by /NM, else kind and 60% overlap.

**`PixelComparer`** (static). `Compare(PdfRgbaImage before, PdfRgbaImage after, double dpi, PixelOptions? = null) -> PixelComparison` and `Compare(IPageRenderer, int, IPageRenderer, int, double dpi, PixelOptions? = null)` (null when either side cannot draw). `PixelOptions(Threshold = 40, Tolerance = 1, Align = true, MinPixels = 4)`. `before` is resized to `after`, turned (up to 3 degrees) and shifted by what a search over a shrunken copy finds (each page's skew from its row profile, the shift from correlation, refined at full size), then a pixel counts when no pixel within `Tolerance` of its place on the other page is within `Threshold` in each channel. Differing pixels within about dpi/25 of each other make a region. `PixelComparison(Differences, Similarity, Alignment, Overlay)`: `PixelDifference(DisplayRect Region, int Pixels)` in points as displayed, origin top left (`PageGeometry.ToUser` converts); `Similarity` is one minus differing over inked pixels; `PixelAlignment(ShiftX, ShiftY, Degrees)`; `Overlay` is the new page faded with ink only the new page has in green and only the old page has in red. At most 5000 regions. `ArgumentException` for an empty or short image. Transparent pixels count as white.

**`ComparisonReport`** (static). `byte[] Write(PdfDocument after, ComparisonResult, string oldName, string newName, IFontSource? fonts = null, DateTimeOffset? date = null)` rewrites a copy of `after` (the argument is not touched): a Highlight per change on its new page, green added, red removed (a sliver at the place), amber changed or moved; `Contents` holds "Was: " and the old text, the origin of a move, or the detail; author "Lazy PDF", subject the kind; a note at the top left of added, moved or resized pages. At most 5000 marks. Summary pages (A4, up to 20) go in front: files, counts, legend, removed pages, up to 60 document differences. Text outside Latin-1 prints as `?` without a font source. `string ToText(ComparisonResult, oldName, newName)`: totals, then changes grouped by page, then the document's.

**Limits.** About 8 ms a page pair in Debug (4158 pages of the corpus compared with themselves in 32 s). Page text for both files is cached up to 2 million characters each. Edit script memory is about 2000 squared ints. Signed files lose their signature in the report.

**Tests.** `windows/LazyPDF.Core.Tests/Compare/`: edit script, page pairing, text, moves, formats, pictures (JPEG included), annotations, document parts, pixel shift and skew on made scans, report reopened in PdfPig, corpus (`LAZYPDF_CORPUS`: every file against itself gives no change, and a copy with one word of its content changed gives exactly that change).

### Export: Word, Excel, PowerPoint, HTML, text, pictures, PDFs from pictures and text

Folder `Export/`, uses Document, Content, Text, Pages and `PdfImageWriter` from Stamps. System services come in as `IImageCodec`, `IPageRenderer` and `IFontSource`. Writers take bytes or strings out and keep nothing. Texts the files hold are in `ExportText`.

**Model.** `ExportLayout.Analyze(PdfDocument, IReadOnlyList<int>? pages = null, IImageCodec? codec = null, CancellationToken = default) -> ExportDocument(Title, Pages, BodySize)`. Pages are 0-based in the order given; a bad index is `ArgumentOutOfRangeException`. Nothing throws on file contents. All geometry is display points (`DisplayRect`, y down, `/Rotate` and crop box applied).
- `ExportPage(Index, Width, Height, Blocks, Lines, Pictures)`: `Blocks` is the reflowed content in reading order with running heads and page numbers left out; `Lines` are all text lines (`ExportTextLine(Bounds, Runs)`) with their places, heads included; `Pictures` are `ExportPicture(Bounds, ExportImage)`.
- Blocks: `ExportParagraph(Bounds, Runs, Heading 0..6, ExportListItem? Item)`, `ExportTable(Bounds, Rows, Widths?, Ruled)` (every row has `Columns` cells), `ExportPicture`. `ExportRun(Text, Bold, Italic, Size)`; a tab in text separates cells of one row. `ExportListItem(ListId, Ordered, Level 0..3, Number)`: one `ListId` is one list. `ExportImage(Data, IsJpeg, Width, Height)` has `Extension` and `MimeType`.
- Rules. Lines join into a paragraph unless the step to the next is well over the block's usual step, the size or boldness changes, the line starts a list item or an indent, or the line before ended short. Headings: a paragraph of at most 3 lines and 200 characters at 1.15 times the body size or more (the most common size) is level 1 to 6 by its size's rank; a bold line at body size over a paragraph of text is one level under. Items start with a bullet character or `n.` / `n)`; a marker drawn apart from its text is joined to it. Running heads: artifact-marked text, page numbers in the top or bottom 8% of the page, and rows there that repeat (digits ignored) on at least half the pages. Tables: a drawn grid (horizontal and vertical lines of at least 6 points, thin fills count) of at least 2 by 2 cells with at least 3 filled, its text taken in by cell; else a block the text layer calls a table. Pictures go before the first block below their middle that shares some width. Full-page pictures under invisible OCR text are dropped.
- Limits: a picture over 2^26 pixels, past 512 MB of pictures in one call, or a 401st on a page is left out; grids look at 20,000 drawn lines a page and give up past 4,000,000 horizontal-vertical pairs. JPEG data is kept as stored (a JPEG with a mask or `/Decode` goes through the codec when one is given); JPEG 2000 and JBIG2 need the codec. Pictures are placed upright by their bounding box; a turned or flipped placement is not turned. Memory holds every analysed page's pictures: pass a page list for large files.

**Writers** (static, take an `ExportDocument`):
- `DocxWriter.Make -> byte[]`: styles for Normal, Heading1 to 6, List Paragraph and Table Grid; real numbering (a `w:num` per list, ordered lists restart at their first number); tables with widths; inline pictures shrunk to the text width; each page after the first starts a page; paper is the first page's, margins are what the content leaves free (0.25 to 2 inches); title in core properties. Parts are deflated (`ExportZip`, from Lazy Scan's `ZipStore`).
- `XlsxWriter.Make -> byte[]`: a sheet per table ("Table 1 (p3)"); without any table, a sheet per page ("Page 3") with lines grouped into rows and left edges into columns. Numbers are numbers: sign, digits, `1,234.56` or `1.234,56`, a lone comma before three digits is thousands, a lone dot decimal, leading-zero integers and over 15 digits stay text. Inline strings, no formulas. At most 1000 sheets, 64 aligned columns.
- `PptxWriter.Make -> byte[]`: a slide a page at the first page's size (1 to 56 inches; others scaled to fit), pictures then one text box per line at its place with its sizes, bold and italic.
- `HtmlWriter.Reflowed -> string`: one file, `section` a page, `h1..h6`, `p`, `strong`, `em`, nested `ul`/`ol`, `table`, pictures as data URIs. `HtmlWriter.Fixed -> string`: a page-sized box with a `span` at the place of every line (points), no pictures.
- `RtfWriter.Make -> string` (non-ASCII as `\u` escapes, tables, pictures as `\pngblip`/`\jpegblip`), `MarkdownWriter.Make(document, embedImages = false) -> string` (GFM tables, specials escaped, a rule between pages, pictures only as data URIs when asked), `PlainTextWriter.Make -> string` (blank line between blocks, `- ` and `1. ` items, tab-joined cells, a form feed after each page). All UTF-16 strings; the caller encodes UTF-8.

**Pictures.**
- `PngWriter.Encode(PdfRgbaImage) -> byte[]`: 8-bit gray, RGB or RGBA by what the pixels need, adaptive row filters. `ArgumentException` when size and data disagree.
- `PageImages.Png(IPageRenderer, pageIndex, dpi) -> byte[]?` and `Jpeg(renderer, IImageCodec, pageIndex, dpi, quality = 85)` (transparency flattened on white; the renderer's pixels are not changed); null when the renderer cannot draw the page; dpi above 0 up to 1200 and quality 1 to 100 or `ArgumentOutOfRangeException`.
- `ImageExtractor.Extract(PdfDocument, pages?, IImageCodec? = null, CancellationToken) -> IReadOnlyList<ExportedImage(PageIndex, Name, ExportImage)>` with `FileName` ("page3_Im1.jpg"). Every image painted, forms included; one painted twice on a page once; inline images are `inline1`.... JPEG as its bytes, others PNG with `/SMask` as alpha; an image that cannot be decoded is left out.

**PDF from pictures and text.** `PdfPageSetup(PdfPaper Paper = A4, PdfOrientation Orientation = Auto, double Margin = 36, double CustomWidth = 595.276, double CustomHeight = 841.89)`; `PdfPaper` is `A4`, `Letter`, `A3`, `A5`, `Legal`, `Custom`, `Picture`. Portrait sizes in points: A3 841.89 x 1190.551, A5 419.528 x 595.276, Legal 612 x 1008; `Custom` is `CustomWidth` x `CustomHeight`, each clamped to 3..14400 (NaN reads as 3) and then put into portrait (shorter side first) like the named papers, so Landscape and Auto turn it the same way whichever side was typed first; the other papers ignore those two.
- `PdfFromPictures.Create(IReadOnlyList<byte[]> files, IImageCodec, PdfPageSetup? = null) -> PicturesPdf(Bytes, Pages, Unreadable, SkippedFrames = 0)`. A JPEG goes in as its bytes (`PdfImageWriter.AddJpeg`), anything else through `DecodeFile` (a frame a page; a `TooBig` frame gets no page and is counted in `SkippedFrames`, and a file of only such frames is counted there alone, not in `Unreadable`). Natural size is JFIF density, or for a decoded frame the density it carries (50 to 1200 on both axes, else 96 dpi); placed centred, shrunk into the margin, never enlarged. `Picture` sizes the page to picture plus margin (at most 14400 points). `Auto` is landscape for a wider picture. EXIF orientation is not applied. `ArgumentException` when no file can be read. Takes a `CancellationToken` (Swift: the calling task's cancellation) checked between files and pages; a cancel throws `OperationCanceledException` (Swift `CancellationError`).
- `PdfFromText.Create(string text, IFontSource? fonts = null, PdfPageSetup? = null, string family = "Arial", double size = 11) -> TextPdf(Bytes, Pages, Missing)`. Wrapped at the margin (a long word at the character), pages by line count, form feed starts a page (a trailing one adds none), tab is four spaces, other control characters dropped. Standard 14 when the text fits WinAnsi, else an embedded subset from `fonts`, so Turkish needs a source: `InvalidOperationException` with `ExportText.NoFont` otherwise. `Missing` lists code points the font lacks. `Picture` reads as A4. Takes a `CancellationToken` (Swift: the calling task's cancellation) checked between files and pages; a cancel throws `OperationCanceledException` (Swift `CancellationError`).

**Tests.** `windows/LazyPDF.Core.Tests/Export/`: a made report (running heads, headings, runs, lists, drawn table, picture) through every writer with zip, XML and relationship checks; Turkish through PDF, docx XML and back; PNG decoded by a test reader; extraction cases; made PDFs reopened in PdfPig; corpus run under `LAZYPDF_CORPUS`.

### Ocr: text layer for scanned pages, triage, correction, Make searchable

Folder `Ocr/`, after Text; uses Document, Content and Text. Recognition, drawing a page and fonts are the app's (`ITextRecognizer`, `IPageRenderer`). Work is on the open `PdfDocument` in memory and the edit session commits it, apart from `PdfSearchable`, which commits itself. Nothing reads file contents without a cap: a page takes at most `PdfOcrLayer.MaxWords` (5000) words, and a layer stream is read only up to 16 MiB and 40,000 operations (a `PdfReadException` past that), reading order stops cutting at depth 200. User text is in `OcrStatusText`.

**Recognizer.** `interface ITextRecognizer { Task<IReadOnlyList<OcrWord>> RecognizeAsync(PdfRgbaImage image, string language, CancellationToken cancellation = default); }`, `language` a BCP 47 tag. `record OcrWord(string Text, OcrBox Box, float Confidence = 1, double Angle = 0)`; `readonly record struct OcrBox(X, Y, Width, Height)` (`Right`, `Bottom`) in pixels of the image, origin top-left. Words may come in any order; a failure in the recognizer is thrown as it is. `Angle` is how far the word's line is turned, in radians, counter-clockwise as seen (a deskew angle); `Box` is then the word's upright box in the line's own frame with its bottom-left corner on the baseline where the word starts. 0 (the default), non-finite or a line whose median angle is 0 gives the straight layout, byte for byte as before.

**Reading order** (`OcrText.cs`, from Lazy Scan's OcrText). `OcrLine(Text, Box, Confidence, Words)`, `OcrPage(Lines, Width, Height)` with `OcrPage.Of(words, pixelWidth, pixelHeight)`, `OcrParagraph(Lines, PageWidth)` with `Text`. `OcrText.Lines(words)` joins words into lines and orders them by recursive X-Y cuts (blocks, columns, tables read row by row; a tab across a wide gap); `ReadingOrder(lines)`, `Paragraphs(page)`, `ParagraphText(lines, pageWidth)`, `PageText(page)`, `PlainText(pages)`, `CleanLine(text)`. Boxes with no area and empty text are dropped. The Lazy Scan thresholds are public constants.

**`PdfOcrLayer`** (static). The layer is one content stream per page, first in `/Contents`, wrapped in `q`..`Q`, with a `/LazyPDFOcr <</Lang (..)>>` key in its dictionary. Text is render mode 3 in a font with one empty half-em glyph (Type0, Identity-H, `/CIDToGIDMap`, `/ToUnicode`; from Lazy Scan's GlyphlessFont). One text object per line; each word has its own `Tm` and `Tz` so its glyphs cover its box, and a space glyph fills the gap to the next word. A line takes the median top and bottom of its words, so glyphs share a baseline; the font size is the line height. A line with a median angle other than 0 (clamped to 30 degrees either way) instead keeps each word's own baseline start and the median height, and every `Tm` is turned by the angle (and the space glyphs follow the baseline) so selection follows the skewed scan; `Words` then gives the box covering the turned word, and `Correct` keeps the angle. Words are placed through `PageGeometry`, so `/Rotate`, crop box and `/UserUnit` are right and the text runs along the shown page. Characters beyond the BMP get codes from D800 up in the order met (2048 at most, then U+FFFD). Words with Hebrew or Arabic letters are written in visual order, which `TextPage` turns back. The font lives under the name `LPOcrF` in a `/Font` dictionary copied for the page, so shared resources of other pages are not touched.
- `int Add(PdfDocument, IReadOnlyList<OcrPageWords> pages, string language)`: `record OcrPageWords(int PageIndex, IReadOnlyList<OcrWord> Words, int PixelWidth, int PixelHeight)`, pixels of the picture the words were read from. Replaces the page's layer; a page with no usable words ends without one. One font for the whole call. Returns the words placed. `ArgumentOutOfRangeException` for a page outside the document or a size of zero, before anything changes. Empty text, non-finite or flat boxes are left out; control characters become spaces.
- `bool Has(document, page)`, `string? Language(document, page)`, `bool Remove(document, page)` (drops the stream from the page's `/Contents` and the font entry; the objects stay until a rewrite, and a page copied by `Duplicate` keeps the shared stream). A layer by another tool has no key and is neither found nor removed.
- `IReadOnlyList<OcrLayerWord> Words(document, page)`: `record OcrLayerWord(int Index, string Text, DisplayRect Box)`, box on the page as shown, in the order written.
- `void Correct(document, page, int index, string text)`: changes word `index`, box kept; empty text removes the word. Writes a new stream; the font is replaced only when the text has a character beyond the BMP it lacks. `ArgumentOutOfRangeException` for no such word.

**`OcrTriage`** (static). `Classify(document, page)` and `ClassifyAll(document)` run the interpreter once per page and give `OcrPageKind`: `Blank` (nothing drawn), `Drawing` (paths or small pictures, no text), `Picture` (pictures cover at least `PictureShare` 0.6 of the crop box, summed, and visible text covers under `SparseTextShare` 0.02), `OwnLayer` (our layer is on the page, whatever else it draws), `ForeignLayer` (invisible text, no layer of ours), `Text` (visible text that is not sparse on a picture). Mode 7 and white-space glyphs count as nothing. `NeedsOcr(kind, replaceOwnLayer, force)`: pictures and drawings always, `OwnLayer` when replacing, everything else only when forced.

**`PdfSearchable.RunAsync(PdfEditSession, ITextRecognizer, IPageRenderer, OcrOptions, IProgress<OcrProgress>? = null, CancellationToken = default)`** gives `OcrResult(Added, NoWords, Skipped, NotRendered, Words, Committed)`. `OcrOptions(Language = "en-US", Dpi = 300, Existing = Skip | Replace, Pages = null, Force = false)`; `Dpi` outside 72 to 600 (`MinDpi`, `MaxDpi`) is `ArgumentOutOfRangeException`; `Pages` are 0-based, out of range and repeated entries ignored. Each page is triaged, drawn with `IPageRenderer.Render(index, dpi)` (null counts as `NotRendered`) and read; `OcrProgress(PageIndex, Done, Total, Outcome)` is reported after each page, `OcrOutcome` `Added | NoWords | Skipped | NotRendered`. `PdfSearchable.ReadAsync(PdfDocument, ITextRecognizer, IPageRenderer, OcrOptions, IProgress<OcrProgress>? = null, CancellationToken = default, bool keepPartial = false)` is the reading half and gives `OcrRead(Result, Pages, Stopped = false)`; with `keepPartial` a cancel does not throw but returns the pages finished before it (the one being read is left out, the counts are those of the finished pages) with `Stopped` true, for a caller that writes them with `PdfOcrLayer.Add`; `RunAsync` never keeps a partial read. Nothing is written until every page is read: cancel (`OperationCanceledException`) or a failure in the recognizer or renderer leaves the document and session as they were. Then `PdfOcrLayer.Add` (which adds its objects before it removes the old layers, so a failure leaves the page as it was) and one `Commit` labelled `OcrStatusText.Label`, so undo takes the whole run; `Committed` is true when anything changed, including a replace run that only removed layers. Under Replace a page where nothing is recognized loses its old layer. Encryption is kept (the saver encrypts the new streams).

**Limits.** A layer is found only while its stream stays separate from the page's other streams; a tool that merges them loses the key. A layer by another tool is not replaced: with `Force` a page gets a second layer. Boxes are used as given, a skewed page gives skewed boxes. Fonts of old layers stay in the file until `SaveRewrite`.

### Changes across layers

No public signature was removed. These are the behaviours that differ from the module sections above.

**Content.** `ShowPatch` (cuts and insertions in a text-showing operator, with the `TJ` shifts that keep the rest in place) lives in `Content/` and is the one implementation behind both text editing and redaction. `PageAppearances.Of(document, page, shownOnly)` gives each annotation's normal appearance with the matrix that places it on `/Rect`; the optimizer, sanitizer and `TextPage` use it.

**Text.** `TextPageOptions` has a third member, `IncludeAnnotations` (false). When set, the text of the appearances of annotations and form fields that are shown (not Hidden, not NoView, no popups) is added at its place on the page; those characters have `TextChar.Form` set to the appearance stream, which the page's own content does not reach, so editing and redaction by operator index must not be given a page built this way. Content in an optional content group that is off in the default configuration is never part of the text: marked content with `/OC`, form XObjects with `/OC`, and membership dictionaries by their `/P` policy (`/VE` counts as visible). `LayerVisibility` (Structure, internal) decides this and is shared with the sanitizer.

**Pages.**
- A document listed twice in `PageAssembly.Merge` is read once and each listing gets fields of its own.
- A font under a name the target's `/AcroForm /DR` already holds for a different font is copied under `Name_2` (and so on); the `/DA` of every copied field, and the form-wide `/DA` given to fields without one, name the new font.
- `/AcroForm /CO` is carried: the copies of the fields the source lists are appended to the target's list in the source's order.
- A radio or check box group that arrives with only some of its buttons (extract, split, import of some pages) keeps the `/Opt` entries of those buttons, by position, and a `/V` naming a button that stayed behind becomes `Off`.
- `Resize` with `ScaleContent` gives the page its own copies of its patterns with `/Matrix` followed by the scaling matrix, since a pattern is mapped by the page's default space and not by the `cm` written round the content (ISO 32000-1 8.7.3.1). Other pages sharing the resources keep the old patterns.
- Page labels and named destinations are read and written by `PdfPageLabels` and `PdfNameTree`, so a name tree comes out rebuilt (one node up to 64 names, else leaves with `/Limits`) after pages are deleted, not edited in place.

**Annotations.** `PdfAnnotationFlattener` draws an annotation with the NoRotate flag on a turned page upright, at its natural size, with the corner of `/Rect` that is shown top left kept in place (12.5.3).

**Forms.** A widget with a `/DA` of its own is redrawn in the font that `/DA` names, resolved from the form's resources like the field's; a replaced font renames it in that widget's `/DA`.

**Redaction, Editing.** Redaction writes its changed text-showing operators through `ShowPatch`: a string that lost glyphs and no shift is a `Tj` or `TJ` as before, an operator with nothing left is dropped (its line move stays for `'` and `"`). An element of the tag tree that lost content also loses its `/T`. `Verify` does not search font programs or `/ToUnicode` maps, which stay by design and match short words by chance. Editing's private PNG writer is gone; `PngWriter` is used.

**Tests.** `LazyPDF.Core.Tests/Integration/` holds the crossings: redact then sign, sign then fill (allowed with a certifying signature, a change with an approval signature), sign then redact, optimise, sanitize or linearize a signed file, PDF/A of a redacted and of an OCRed file, tag then redact, edit then compare, export after OCR, linearize then session commit, undo and redo, and every tool on password files at both strengths (redaction, optimizer, sanitizer, linearizer, converter, tagging, OCR, comparison, export, signing, text editing).

### Signatures: changed after signing, fail closed

- What follows a signature's bytes is accepted only as far as it can be placed exactly; everything else is `ChangedAfterSigning`, whatever the certification level, with one `SignatureChange(Unreadable, 0, -1, null, false)` (`SignatureChangeKind.Unreadable` is new, last in the enum; `SignatureText.Describe` says "Added data cannot be checked"). Public signatures are unchanged.
- The bytes are read by a strict reader of their own (`StrictReader`, `UpdateGate`), not by the lexer, and nothing is repaired. Allowed: `N G obj` bodies, then a table (20-byte entries) with its trailer or a cross-reference stream, `startxref`, `%%EOF`, repeated for each update, with one line end after the last (one `
`, `
` or `

` is all that may follow the signed bytes unread; any more white space is a tail the change rules judge, and fails). Numbers, names, strings and keywords must be exact (7.3); a comment, a repeated key, an unknown escape or keyword, an unterminated string, a missing `endobj`, a stream whose `/Length` is not a direct integer that lands on `endstream` fail it.
- Each entry points exactly at an `N G obj` of its own update (never into the signed bytes) with the same number and generation, each object is listed once, no number twice in a section. An object stream is walked member by member from its header (every byte between `/First` and the end belongs to one member, numbers once, the entry's index is the member's position, no `/Extends`). The table the document read must be the table the strict reader found; a document that needed any repair, or a rebuilt table, fails.
- The trailer has `/Size` (above every number listed, not below the section before), `/Prev` (the section before, once), and the signed revision's `/Root` and `/Encrypt` in the same bytes and `/Info` and `/ID` likewise, with two ISO 32000-1 14.4 exceptions: `/Info` may be added where there was none, only as a reference to an object the update gives (judged as metadata; a direct dictionary or an old object fails), and the second `/ID` string may change. `/Size` is exactly the first number nothing uses. `/XRefStm` fails; any other key fails unless the signed revision's trailer has it with the same bytes (our writers repeat such keys). A signed revision whose catalog is in the trailer accepts no update.
- The signed revision's own end is read the same way: its last section (from `startxref`) must run to the end of the signed bytes, so a comment or open object there cannot hide what comes next. The old object-by-object scans (`ChangeTokens`, `ChangeOrphans`, `ChangeTables`) and the per-revision documents are gone.
- Each object an update lists is judged by what the signed revision uses it for, from one walk over all of it (`Jobs`). Changed, new or freed only when every use is one kind the level allows; an object used twice for different things is not allowed. Not counted as uses: `/CO`, `/Fields` of SubmitForm and ResetForm, `/T` of Hide, `/Data` of a signature reference, the page of a destination (`[page /Fit]` and the like), the back links `/P` (a bead's too), `/Popup`, `/IRT`, and the structure tree's `/Pg` and `/Obj`, where they name a page, annotation or field; a structure element that holds a page, annotation or field any other way (a `/K` that is the annotation itself) is a second use of it. Each is plumbing without which a tagged file, a threaded file or a comment with a popup could not be commented or filled at all. `/Parent` is a back link only where the parent lists the child in `/Kids` or `/Popup`; any other is a use, because it carries inheritance. `/Fields` and `/T` of SubmitForm, ResetForm and Hide count only inside an action (`/A`, `/AA`, `/OpenAction`), and `/Data` only when it names the catalog.
- Default deny: the rule tables name the keys that may differ (catalog `/DSS`, `/Extensions`, `/Version`, `/Metadata`, `/AcroForm`; form `/Fields`, `/SigFlags`, drawing defaults; page `/Annots`; field `/V`, `/AS`, `/AP`, `/M`, `/I`; comments, appearances, validation data, information); any other key is not allowed. Comments have a key table too (text, colour, flags, rectangle, appearance, popup, and the keys of the markup types our writer emits: `/Sy`, `/OverlayText`, `/RO`, `/Repeat`, `/Cap`, `/CO`, `/Measure`; no action, destination, layer or tag), for changed and for new annotations, direct entries of `/Annots` included: a direct entry that differs counts as a removed annotation and a new one, so a changed direct link is a new annotation with an `/A`, which is not allowed. A read-only field (`/Ff` bit 1, inherited) is not filled, and neither is a pushbutton (`/FT /Btn`, `/Ff` bit 17): its appearance is fixed drawing. A fill may also write `/DA`, `/TI` and `/RV`. A widget no field lists answers for the field above it only when it has no `/T`, `/FT`, `/Ff` or `/Kids` and its `/Parent`, if any, is that field; any other widget has no field and is not allowed. A signature field typed only by a `/Parent` that does not list it is still a signature field. A lock on a name covers the fields under it, the names a reader qualifies by `/Parent`, and the parents that hand a value down; an `Exclude` name frees the fields below it. The `/DR` of the form is a use of its own, so a font that a new appearance also draws passes. With a lock, or any read-only field, `/NeedAppearances`, `/DA`, `/Q` and any change to a resource that exists are not allowed; the one change that passes is a new name in `/DR /Font` that no `/DA` of the signed revision uses, with its new font objects (unless the signed revision named that object number). Information may change `/ModDate` and `/Producer` at any level, and an XMP packet (the catalog's `/Metadata`) may change `xmp:ModifyDate`, `xmp:MetadataDate` and `pdf:Producer` and nothing else, as attribute or element, at any level. Validation entries may hold `/TS`. Signing a field that has no widget gives it one. A new object must be reached only through an allowed new use, so an unreachable one is not allowed. New fields and widgets are signature fields with a real signature or document time stamp in `/V`, no `/A`, no `/AA`, and at P=1 a `/Rect` written once as four numbers of an empty box, or none. `/Rect`, `/F` and `/P` of an unsigned signature field change only while it has no `/Subtype`: a field that was a widget when signed stays where it was. A changed generation, an object freed while a reference to it remains (or was dangling in the signed revision and was defined and freed again), and a number no rule names are not allowed. A cross-reference or object stream an update writes is not a change while nothing refers to it; a reference to its number makes it an object like any other. A walk that a cap ended early, a field nested deeper than 32 and a field chain that does not end are one `Unreadable` change. The signed copy of a replaced object may have an indirect `/Length` and a backslash before a character that needs none.
- `ChangeDetector.Compare(before, after, level, signatures)`: `before` is the file cut at the end of the signed range (not at the revision end), `between` is gone. A lock on a field name covers the fields under it. An xref offset beyond `int` is a failed gate, not an exception; nothing in `Verify` throws on file contents but `PdfReadException` when the file does not open.
- Honest updates that now read as changed: a comment inside an update or in an object it replaces, an indirect `/Length` in the update, table lines of other than 20 bytes, hybrid files, an update without `/ID`, a replaced `/Info` with more than dates and producer changed, junk before `%PDF`, more than 256 updates, tagged or plumbing designs that use a field a second way, a new object nothing refers to. Not checked: files from other writers beyond the pyHanko ones (one signature, countersigned, certified and countersigned, LTA with a dummy time stamp authority) and our own `PdfEditSession` updates.

### Redaction: what it cannot follow, it flattens

A page with marks is either understood in full or turned into a picture. Removing too much is a nuisance, leaving something is a failure.

**`RedactionOptions`** gains `IPageRenderer? Renderer` and `double FlattenDpi` (200 by default, above 0 and at most 1200, else `ArgumentOutOfRangeException` when a page is drawn). The renderer draws the document handed to `PdfRedactor`.

**`RedactionReport`** gains `IReadOnlyList<int> Flattened`, the pages (from 0) that became pictures. `ToString()` says for each: "Page 3 was turned into a picture. Its text can no longer be selected."

**Understood** is an allow-list. A page is understood when all of this holds, for its content and for every form, tiling cell, soft mask group and glyph procedure it paints:
- the bytes are whole tokens, read again without the parser's repairs: no comment, no stray `] } > ) {`, numbers spelled as 7.3.3 spells them and within 32 bits, no operands left at the end of a stream, no string, name or number running across the join of two content streams, every content stream of the page readable;
- the content parses whole, within the interpreter's limits (q stack 256, marked content 1024, forms 20 deep, one million operations a stream), with no operator outside Annex A, no operands of another count or kind than the operator takes, no `Q` without its `q`, no `BX`, and nothing but text, colour and state operators between `BT` and `ET`;
- an inline image has no filter, its dictionary holds only image keys once each (an abbreviation and its full name together are two), and its data is as long as the dimensions say;
- a name resolves in the resources of the stream that uses it, never only in an enclosing list; a pattern name follows a `/Pattern` colour space set in the same stream; a form that reaches itself by any route is not understood; nor is an XObject that is neither image nor form, a graphics state with `/Font`, or a font of a kind other than Type1, MMType1, TrueType, Type3 or Type0 with one CID font;
- every entry of a Type 3 font's `/CharProcs` paints only shapes and bitmaps, its `/FontMatrix` scales x, and a glyph of such a font under a mark makes the page a picture;
- under a mark there is no paint through a soft mask, a tiling pattern, a mesh or optional content that is off, declared nowhere or decided by an expression, and no form or picture that has something cut in one use and is shown again by another.

**Flattening.** The page is drawn at `FlattenDpi`, the marks are filled in the pixels with the overlay colour, and the page becomes one DeviceRGB image with new minimal resources. `/MediaBox`, `/CropBox`, `/Rotate` and `/UserUnit` stay; content, resources, annotations, form fields and every other page key go. Overlay text is drawn as text on top. A page the renderer returns nothing for throws `InvalidOperationException` with `RedactionText.NotDrawn(page)`.

**Without a renderer** a call that needs a picture throws `InvalidOperationException` with `RedactionText.NeedsPicture(page)`, naming the first such page, before anything is done. `Apply` never changes the document it was given.

**Resources** of a page, and of each form copied for a cut, are built from what the new content names. A font whose selection nothing shows after goes with the text.

**The sweep.** After the pages are done, every object a redacted page reached before and nothing painted reaches is emptied where it is: a stream loses its data and keys, a dictionary its entries, an array its items. Structure elements, `/PieceInfo`, thumbnails, `/AF` and page-level keys do not keep an object alive. What is painted is followed by key: a stream stays only when reached through a key that holds one (`/SMask`, `/FontFile`, `/ToUnicode`, `/CharProcs` and the like), so a private key naming a picture keeps nothing. What a page without marks paints stays, with the appearances of the annotations it keeps and its boxes, and so do the pages, the page tree (found by `/Kids`, whatever their `/Type`), the catalog, the layer dictionaries and the output profiles. A page without marks that shared lists with a redacted one gets lists of its own. One that cannot be followed keeps every stream it lists, and the verification says `RedactionText.NotFollowed` for it.

**`PdfRedactor.Verify`** judges the output by the same rule: a marked page that is not understood is `RedactionText.NotFollowed`, and a limit is a problem, not an exception: a stream that does not decode or is longer than is read, text that is longer than is spoken, an attachment in a format that is not opened (gzip and zip are, attachments are found by `/EF` as well as by their type) is `RedactionText.NotChecked`. The programs and character sets of fonts are exempt only inside font dictionaries. Past the tag tree's depth and size limits every description below is removed.

**Stricter reading.** All of this is a page that becomes a picture, or a problem in `Verification`; no public signature changed.
- A form's, pattern's or Type 3 font's matrix is absent or exactly six numbers. `Td`, `TD`, `Tm`, `Tj`, `TJ`, `'`, `"` and `T*` outside `BT`/`ET` are not understood. A move (`cm` and `Tm` translation, `Td`, `TD`) of 2^22 or more is not understood. An inline image whose data holds the bytes `EI` is not understood. A name for a colour space whose family is `/Pattern` counts as a pattern space.
- Fonts: a simple font has `/Widths` that agree with `/FirstChar` and `/LastChar` and lie between 0 and 2000, or has none and is a standard 14 font or carries its program. A Type 0 font's `/DW` and `/W` lie in the same range. A Type 3 font with more `/Differences` items than `PdfFont` reads is not plain.
- Second uses: a picture, form or mask that is cut on a marked page must be shown once per cut, counting every marked page, the masks of pictures and the appearances of annotations the page keeps. A marked page with another use becomes a picture. An annotation appearance that cannot be followed makes a marked page a picture, and on an unmarked page it is `NotFollowed`.
- The sweep: a stream is kept through a key only when it is not a picture, form, pattern cell, metadata packet, attachment or the content of a page (`/SMask` and `/Mask` keep a picture, and only on a picture). A root that is not painted itself keeps no stream. A resource list, or `/Resources`, that is not a dictionary of its own, or is a page tree node, is not understood, and a node found there is followed and swept. `/ProcSet` is rebuilt as names. `/JBIG2Globals`, `/UseCMap` and `/TransferFunction` are keys that keep a stream, and a page's `/B` is not reached.
- An understood page keeps only the page keys of Table 30 apart from the thumbnail, `/PieceInfo`, `/Metadata`, `/AF` and private keys. A description with `/MCID` among its properties loses every other key; named properties are rewritten the same way, and a `DP` on a stream that lost something is emptied. A touched structure element also loses `/AF`; one with no `/Pg` is touched when its number was cut on any page.
- Flattening refuses a picture whose shape differs from the page (`NotDrawn`), removes only the widget of a page that became a picture, and takes a field only with its last widget.
- `Verify`: a stream in an image codec is searched as the codec's bytes and is not unread; the pages of an attached PDF are read as a viewer reads them; an attachment that looks compressed or encrypted, or starts like an archive that is not opened, is `NotChecked`; a gzip, zip or PDF held anywhere is opened. A marked page whose annotation appearances cannot be followed is `NotFollowed`.
- What stays: a stream with none of the markers above, named by a font-program key under a private key of a painted object, stays.
- `RedactionOptions.FlattenMarkedPages` (false by default) turns every page with a mark into a picture, as an unknown page is; without a renderer the call throws `NeedsPicture` the same way.
- An XMP packet that is not XML, or cannot be written back after it was changed (the parser accepts an `xmlns` binding the writer refuses), is emptied and reported as `XmpUnreadable`; reading never throws anything else.

### Office: reading packages for the converter

Folder `Office/`, no third-party code and no `System.IO.Compression.ZipArchive`. The Swift twin (`Sources/LazyPDFKit/Office/ZipReader.swift`, `ZipLimits` with the same defaults, `PdfFilters.inflateRaw`) behaves the same and its tests run the same cases.

**`ZipReader.Open(bytes, ZipLimits? = null)`** (internal) reads the central directory (zip64 end record and extra fields, stored and deflate; data descriptors need no care since sizes come from the directory) and gives `Names` (files only, `/` separators, directory order), `Contains(name)` and `Read(name)`. Names compare case-insensitively like OPC part names. Open refuses with `PdfReadException`: no directory, a directory or header cut short, several disks, encryption, a method other than 0 and 8, a name that is rooted or has a `..` segment (`\` counts as `/`), two names equal ignoring case (all `Damaged`, the rest `Unsupported`). `Read` inflates through `PdfFilters.InflateRaw` no further than the declared size and checks the size and CRC-32, so a lying size cannot allocate or pass.

**`ZipLimits`** defaults: 20 000 entries, 256 MiB of declared size in all, 128 MiB per entry, ratio 200 to 1 for entries from 1 MiB up. All are checked at Open from the declared sizes, so a package is refused before any entry is inflated.

**`XmlTree.Parse(bytes, XmlLimits? = null)`** (internal, namespace `LazyPDF.Core.Office` because `System.Xml` types of the same names are in use elsewhere in Core) reads an XML part into a tree: `XmlElement` (`Uri`, local `Name`, `Attributes`, `Children` of `XmlElement` and `XmlText`; helpers `Elements`, `Child`, `Attribute`, `Text`). It is the reader every format reader shares, written so that both engines read a part alike; neither `System.Xml` nor Foundation's `XMLParser` is used. The Swift twin (`Sources/LazyPDFKit/Office/OfficeXml.swift`, types `OfficeXml`, `OfficeXmlElement` and so on, since the XMP tree owns the plain names) works on UTF-16 units and compares names unit by unit, so it matches the C# where Swift's `String` would not. Rules, all pinned by `Tests/Fixtures/golden/xml` (input and output, read by both test suites):
- Encoding: UTF-8, or UTF-16 with a BOM or detected from a leading `<`; bad bytes fail (`Damaged`); a declared encoding other than utf-8, utf-16 and us-ascii is `Unsupported`. The XML declaration is accepted only as the first bytes.
- A DOCTYPE of any kind is `Unsupported`, so no entity is ever defined, expanded or fetched. Only `&lt; &gt; &amp; &quot; &apos;` and numeric references to legal XML characters resolve; any other reference is `Damaged`.
- Line ends become `\n` in text and CDATA, and a space in attribute values (a reference such as `&#13;` stays as written). Comments and processing instructions are dropped; text on both sides of one is a single node, and CDATA joins its neighbouring text.
- Names: ASCII letters, `_`, `:` and anything from U+0080 start a name; digits, `-` and `.` continue it. Prefixes resolve through `xmlns` declarations (an unbound prefix, a doubled attribute after resolution, `xmlns:p=""` or a rebinding of `xml`/`xmlns` is `Damaged`); unprefixed attributes have no namespace, unprefixed elements take the default one. Namespace declarations are not attributes.
- `XmlLimits` defaults: depth 128, 1 000 000 elements, 128 attributes (declarations included) per element; over a limit is `Unsupported`. The parse is iterative; prefix lookup is constant time.

### Office: fonts for the converter

**`OfficeFontSource(installed, bundled)`** (internal, `Office/OfficeFontSource.cs`; Swift twin `Sources/LazyPDFKit/Office/OfficeFontSource.swift`) is the `IFontSource` the converter draws and measures with. `Find(family, style)` answers, in this order: the installed font of that name; the bundled font with the same advance widths (Calibri to Carlito, Cambria to Caladea, Arial and Helvetica to Liberation Sans, Times New Roman and Times to Liberation Serif, Courier New and Courier to Liberation Mono; a bundled family asked for by its own name is itself); the bundled default, Carlito; else null. Names fold only A-Z, so both engines agree for any input. Either source may be null. Pinned by `Tests/Fixtures/golden/office-fonts` (input and output, read by both test suites).

The bundled fonts are Carlito, Caladea and the three Liberation families, regular, bold, italic and bold italic, in `fonts/` at the repo root with their OFL.txt, under the SIL Open Font License 1.1 (text in THIRD-PARTY-NOTICES.txt). The tests check that A has the advance of Calibri, Arial, Times New Roman and Courier New in each. They are not read by Core: the app hands them in as the second source. `BundledFontSource` (Windows: `LazyPDF.App/Services`, files `Fonts/<Family without spaces>-<Regular|Bold|Italic|BoldItalic>.ttf` beside the exe, copied by the App csproj; Apple: `Sources/LazyPDFApp/Apple`, the same file names in the main bundle, where `mac/project.yml` and `ios/project.yml` copy `fonts/**/*.ttf` flat) is that source.

### Office: layout and paginator

The shared layout model and the page writer of the converter, in `Office/Layout/`. The format readers (DOCX first) fill a `LayoutDocument` and call `OfficePdfWriter.Create(document, fonts, cancellation)`; nothing in here knows a file format. The Swift twin (`Sources/LazyPDFKit/Office/`, `LayoutModel`, `LayoutFonts`, `LineBreaker`, `ParagraphLayout`, `Paginator`, `OfficePdfWriter`) matches it step for step and reads the same goldens in `Tests/Fixtures/golden/office-layout`; the Swift model uses `PlacedText` and `PlacedRect` as cases of an enum `LayoutBox`.

**Model** (internal, `LayoutModel.cs`): a `LayoutDocument` holds `LayoutSection`s (each starts a page; `LayoutGeometry` in points with margins, header and footer distance; header and footer paragraphs; body blocks) and the `Skipped` features the reader left out. A block is a `LayoutParagraph`, a `LayoutTable` (see below) or a `LayoutPageBreak`. A paragraph has runs (family, size, bold, italic, underline, strike, colour as 0xRRGGBB, highlight, baseline `Shift` in points, and a `Field` that header and footer paragraphs replace by the page number or the page count), alignment (left, center, right, justify), `Left`, `Right`, `FirstLine` (negative hangs), `Before`, `After`, line spacing (a factor, or points for `Exact` and `AtLeast`), `KeepWithNext`, `PageBreakBefore` and `WidowControl` (on by default). Text may hold `\n` (line break) and `\t`. The result of a layout is `LayoutPage`s of absolutely placed boxes, `PlacedText` (x, baseline, text, family, style, size, colour, extra space after each blank) and `PlacedRect` (highlights, underlines, strikes), in points from the top left.

**Result** (public, `OfficePdf(Bytes, Pages, Skipped, Missing)`): `Skipped` is a list of `SkippedFeature(Kind, Count)`; the kind is a stable code the app turns into words ("Made without Office. Layout can differ from Word. Left out: ..."). The layout adds `rtl-text` (Hebrew, Arabic and the like) and `complex-script` (Indic, Thai, Khmer and so on), counted per paragraph; these are still drawn, unshaped and in logical order, from whatever font has the glyphs. `Missing` lists the code points no font could draw, sorted.

**Rules**, all pinned by `layout-input.txt` and `layout-output.txt` (cases built from a small text format that both test suites read):
- Fonts: `LayoutFonts` asks the `IFontSource` (the app passes an `OfficeFontSource`) for the run's family and style, else for Carlito; no font at all is `InvalidOperationException(ExportText.NoFont)`. A character the font lacks is drawn from the first of Segoe UI, Segoe UI Symbol, Microsoft YaHei, Yu Gothic, Malgun Gothic, Arial Unicode MS, PingFang SC, Hiragino Sans, Apple SD Gothic Neo and Liberation Sans that has it, else it stays in the run's font as a missing glyph. Widths are the advances of the font file, no kerning. Soft hyphen, ZWNJ, ZWJ, word joiner, BOM and control characters other than tab and line feed are dropped.
- Line height: the tallest ascent plus the deepest descent of the line, hhea line gap included in the ascent, times the factor; `Exact` uses the points, `AtLeast` the larger. Extra height goes above the text. A shifted run raises or lowers its own ascent or descent. An empty line takes the style of the paragraph's first run (Carlito 11 without runs).
- Breaking: greedy, as Word fits lines, spaces hang at the line end and are not measured. `LineBreaker` allows a break after spaces (not before a closing mark or after an opening one), after a hyphen between letters or digits (not before a digit), after en dash, hyphen U+2010 and figure dash, before and after em dash, after a slash not followed by a digit, after a zero width space, and between Chinese, Japanese characters, except that closing marks, small kana and the prolonged sound mark never start a line and opening marks never end one. No break around no-break space, narrow no-break space, U+2011 or after quotes and currency signs. A word wider than the line is cut where it runs out. Hangul breaks at spaces only. Pinned by `linebreak-input.txt` and `linebreak-output.txt`.
- Tabs: to the next multiple of 36 points from the text area's left edge, or to the paragraph's left indent when the line starts to the left of it (the hanging indent of a list item), never past the right edge.
- Alignment: centre and right use the width up to the last visible character. Justify spreads the room over the plain spaces of a line that was wrapped (not the last line, not a line ended by `\n`, not a line with a tab); a justified piece is written with `TJ` adjustments after each space, since `Tw` does not work on two-byte codes.
- Pages: space before is dropped at the top of a page that overflow started, kept at the top of a page that a section, page break or `PageBreakBefore` started. Space before and after add up. A paragraph breaks across pages with widow and orphan control (two lines at least on each side when it is on). `KeepWithNext` moves a chain of paragraphs and the first two lines (one without widow control) of the next paragraph to a new page when they do not fit in what is left and do fit on a page. A page break block always starts a page, so two in a row leave an empty one. The body starts below the header and ends above the footer when they are taller than the margins; if that would leave under 36 points it falls back to the margins.
- Header and footer: laid out once per page, after the page count is known; the header from its distance below the top, the footer ending its distance above the bottom.
- Limits: a page size outside 72 to 14 400 points, a negative margin or a text area under 36 points is `PdfReadException` (Unsupported); so is a document of more than 10 000 pages. Sizes of a run are taken as 11 when not positive and capped at 1000. The cancellation token is checked per block and per page.

**Writer**: one embedded subset font per family and style used (`PdfFontEmbedder.Add` with `embed: true`, so Identity-H with /W and /ToUnicode and the text stays selectable), pages made with the section's own size, content streams Flate coded. Every coordinate is rounded to 1/100 point (away from zero) and colours to 1/1000 when written, so both engines write the same numbers. The golden output lists the boxes and the content stream of each page.

### Office: tables

Model and pagination in `Office/Layout/` (`LayoutTable` in `LayoutModel.cs`, `TableLayout.cs`, `PaginatorTables.cs`), reading in `Office/Docx/DocxTable.cs`. The Swift twin (`TableLayout.swift`, `PaginatorTables.swift`, `DocxTable.swift`) matches it step for step and reads the same goldens (`office-layout/tables-input.txt`, `office-docx/tables-input.txt`, with the outputs beside them); the Swift reader keeps its own type names (`TblEdges`, `TblCell` and so on) because Swift types are module wide.

**Model**: a `LayoutTable` is a block with `Columns` (widths in points; 0 means no width of its own), `Indent`, `Align` and `Rows`. A `LayoutRow` has `Cells`, `Header`, `CantSplit`, `Height` and `HeightExact`. A `LayoutCell` has its first `Column`, `Span`, `RowSpan`, paragraphs, `Fill`, four `LayoutBorder?` edges (width in points, 0xRRGGBB), four margins and a vertical alignment. The cells that continue a vertical merge are not in the model; the cell above them has the `RowSpan`.

**Reading** (DOCX)
- Grid: `tblGrid` gives the columns. A row that reaches past the grid adds columns of width 0; without a grid the widths come from `tcW` in `dxa` (a cell over several columns shares its width). `gridSpan` is held to 1 to 63, `gridBefore` shifts the first cell. Other widths (`tblW`, percentages, autofit) are not read. More than 63 columns, more than 5000 rows, 100 000 cells in the document, a table inside a table or cell, and a table in a header or footer are read as their paragraphs in order and counted as `table` skipped.
- Vertical merge: `vMerge` with `restart` begins a merged cell; one without a value or with `continue` extends the cell above in the same column with the same span, and its own content is dropped. A continuing cell without a cell above it starts a new one.
- Borders: each cell has, per side, a candidate from its own `tcBorders` or else the table's (`top`, `bottom`, `left`, `right` on the outer edge, `insideH`, `insideV` between cells). `nil` and `none` are borders of width 0 that still count as stated. Where two cells share an edge: a cell's own border beats the table's; between two of the same kind the wider wins, then the darker (red plus blue plus twice green), then the one of the cell above or to the left. The neighbor across an edge is the cell at the edge's first row or column. The width is `sz` / 8 point held to 0.25 to 12 (0.5 when missing); the line style is not read, every border is solid. The bottom edge of a merged cell comes from the last cell that continues it.
- Shading: `shd` `fill` (a theme fill too) or, for the `solid` pattern, `color`; `nil` and `auto` clear it. Other patterns are taken as their fill.
- Margins: `tblCellMar`, then `tcMar`, in twips, held to 0 to 144 points; 5.4 left and right and 0 top and bottom without any.
- `vAlign` top, center and bottom. `trHeight` is a minimum, or exact with `hRule="exact"`; `tblHeader` and `cantSplit` as in Word. `tblInd` and `jc` of the table (left, center, right) position it.
- Table styles: the `type="table"` style (the default one when the table names none) and its `basedOn` chain give borders, cell margins, shading, vertical alignment, and paragraph and run properties. Conditional parts (`tblStylePr`) apply in this order, later ones over earlier: `band1Vert` or `band2Vert`, `band1Horz` or `band2Horz`, `lastCol`, `firstCol`, `lastRow`, `firstRow`, as `tblLook` (attributes or the hex `val`) and `tblStyleRowBandSize`, `tblStyleColBandSize` allow; the corner cells are not read. Without `tblLook` no conditional part applies. Order of properties on a cell: style layers, the table's own `tblPr`, the cell's own `tcPr`. A paragraph in a table takes the style layers' paragraph and run properties above the document defaults and below its own paragraph style, as in Word.
- A page break, column break or section break inside a cell is a line break or nothing.

**Pagination**
- Columns are placed from the text area's left edge plus `Indent` (or centered or right aligned). Columns of width 0 share what the others leave. A table wider than the text area (less the indent) is narrowed in proportion to fit; Word would let it run into the margin.
- A cell's text is laid out in the cell's width less its margins, like any paragraph; space before and after count inside the cell. Row height is the tallest cell with margins, at least `Height`; with `HeightExact` it is `Height` and the lines that do not fit are not drawn. A merged cell that needs more than its rows give makes the last of them taller.
- Rows joined by a vertical merge are kept on one page. A group that does not fit moves to a fresh page when the current page has content. A merge taller than a page is undone: the cell goes back to its first row, which then breaks like any row.
- A single row that does not fit is cut between lines (no widow control inside cells) unless it is `CantSplit` and fits a page, or only its minimum height does not fit; each cell gives as many lines as fit. At least one line per cell is taken on a page that has nothing else, so the table always advances. Vertical alignment applies only to a row that is not cut.
- Header rows (the `Header` rows at the start of the table, shortened to a group boundary) are drawn again at the top of every page the table continues on, unless they take over half of the body.
- Drawing per piece of a row: fills, then text, then borders. A shared edge is drawn once as a filled rectangle centered on the edge, its length and thickness extended by its own width at the ends. A cut row has no bottom border on the first page and no top border on the next.
- A keep-with-next paragraph before a table keeps with its first row.

### Office: the DOCX reader

`OfficeConverter.FromWord(docx, fonts, cancellation)` (internal until the app wires it) is `DocxReader.Read` (`Office/Docx/`) followed by `OfficePdfWriter.Create`. `DocxReader` fills a `LayoutDocument`; `OpcPackage` (`Office/OpcPackage.cs`) is the package layer the XLSX and PPTX readers share: `[Content_Types].xml` defaults and overrides, relationships resolved against their source part (absolute and `..` targets, external ones dropped), parsed parts cached. The Swift twin (`Sources/LazyPDFKit/Office/Docx*.swift`, `OpcPackage.swift`) matches step for step and reads the same goldens in `Tests/Fixtures/golden/office-docx` (`docx-input.txt` lists parts as XML, `docx-output.txt` is a dump of the layout model; the dump format is in `LazyPDF.Core.Tests/Office/DocxSpec.cs`).

**Refusals** (`PdfReadException`): not a zip, no `[Content_Types].xml`, no main part (Damaged); a main part whose content type is not WordprocessingML, a root outside the transitional namespace, an OLE file (Word 97-2003) and anything over the zip or XML limits (Unsupported).

**Rules**
- Styles: document defaults, then the style and its `basedOn` chain from the far end (a loop or a chain past 50 stops there), then direct formatting; paragraph style properties apply to the runs in it, then the character style (the default one when a run names none), then the run's own. Toggle properties (bold, italic, strike) are set by the nearest layer, not exclusive-or'ed across styles as Word does. An unknown style id falls back to the default style. Without a default size the size is 10 and the family Times New Roman, as in Word.
- Fonts: `rFonts` theme attributes (`minor*`, `major*`) resolve to the latin typeface of `word/theme/theme1.xml`, else `ascii`, else `hAnsi`. Only the latin face is used; the layout's per-character fallback covers the rest. Colour: a six digit `val` wins over `themeColor`; `auto` is black. Highlight takes the named colours of Word, `none` clears it.
- Run text: `w:t`, tab and `ptab` as `	`, `br` and `cr` as `
`, `noBreakHyphen` as U+2011. `caps` upper-cases A-Z only. Hidden text (`vanish`) is dropped. Superscript and subscript use 2/3 of the size, raised by 0.33 or lowered by 0.14 of the original size. Adjacent runs in one format are one run; an empty paragraph keeps one empty run in the format of its paragraph mark so that its line has the right height.
- Paragraphs: `jc`, `ind` (twips; `hanging` wins over `firstLine`; `start` and `end` alias left and right), `spacing` (`line` with `auto` is 240ths of a line, `exact` and `atLeast` twips), `keepNext`, `pageBreakBefore`, `widowControl`. Lengths are clamped to plus or minus 1584 points; a number that does not parse is ignored.
- Page breaks: a `br` of type page (or column) in a paragraph ends the paragraph so far (dropped when it has no text) and adds a page break block; the rest is a paragraph of the same format, so a break-only paragraph leaves an empty line at the top of the next page, as Word 2013 and later do. Breaks in headers and footers are line breaks.
- Sections: a `sectPr` in a paragraph ends a section after that paragraph, the one in `w:body` ends the last. Size and margins in twips; `orient="landscape"` with a portrait size swaps it; negative top and bottom margins are taken as positive; the gutter is added to the left margin. A `continuous` section with the same page setup as the one before joins it, any other starts a page (odd and even page types too). A last section left empty by a section break at the very end is dropped.
- Headers and footers: the default one of each section, inherited from the section before when not given. `PAGE` and `NUMPAGES` fields (complex or `fldSimple`) there become field runs in the format of the field's first run; elsewhere every field shows its cached result.
- Lists: `word/numbering.xml` (`DocxNumbering`, both engines). A paragraph with `numPr` (direct or from its style; `numId` 0 switches it off; an unknown list or level leaves it plain) gets its label as text in front of the paragraph, in the paragraph mark's format with the level's `rPr` on top, followed by a tab (`suff` space and nothing are honoured). Level properties sit between the style and the paragraph's own: style, level `pPr`, direct. Without `ilvl` the level whose `pStyle` names the paragraph's style is used, else level 0. Counters run in document order; `num`s of one `abstractNum` share them unless the `num` has a `startOverride`, which gives it counters of its own starting there; a `lvlOverride` `lvl` replaces the level. A level starts over after any higher level, or after the level `lvlRestart` names (1 based, 0 never). `lvlText` `%1` to `%9` insert the counter of that level in its own format, or decimal when the level is `isLgl`. Formats: decimal, decimalZero, lowerLetter and upperLetter (a to z, then aa, bb), lowerRoman and upperRoman (1 to 3999, else decimal), bullet and none; any other is decimal. Bullets in Symbol, Wingdings or Webdings are mapped from the private use area to bullet, small square, arrowhead, check mark or diamond and drawn in the paragraph's font. Counters stop at 32767, a label at 64 characters, definitions at 10000 each. The first explicit tab stop of the level (`left`, `center`, `right`, `decimal`) becomes `LabelTab` on the paragraph, and the tab after the label runs to it (to the hanging indent first when that is nearer); other tab stops are not read.
- Wrappers read through: `sdt` content (block and inline), `hyperlink` (text only, no link), `smartTag`, `customXml`, `dir`, `bdo`, `ins` and `moveTo`; `mc:AlternateContent` takes `Choice`, else `Fallback`.

**Skipped kinds** (count per occurrence, listed sorted by code): `table` (a table read as its paragraphs in order, see Office: tables), `text-box`, `picture`, `chart`, `shape`, `drawing` (the content is not read), `footnote`, `endnote`, `comment` (the reference only), `equation`, `tracked-change` (insertions are shown, deletions dropped, counted per `ins`, `del`, `moveTo`, `moveFrom`), `field` (outermost field other than PAGE, NUMPAGES and HYPERLINK; cached text shown), `header-variant` (a section with a first-page header or footer that is not used).
