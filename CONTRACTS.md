# Lazy PDF — module contracts

Native PDF editor for Windows, macOS and the iPhone, the third of the Lazy apps with Lazy Scan (`../LazyScan`) and Lazy Print (`../LazyPrint`), whose layout and conventions it shares. The Windows app is .NET 10 and WPF. The Swift targets (`LazyPDFKit`, `LazyPDFMac`, `LazyPDFIOS`) follow once the C# engine has settled, the order Lazy Print was built in.

**System frameworks only.** Core has no third-party code. It may use `System.Security.Cryptography.Pkcs`, Microsoft's own CMS package, for signatures; that is the one package reference it has. PdfPig stays in the test project, as in Lazy Scan.

## The split: our engine, the system's pixels

Lazy PDF owns the file format and leaves drawing a page to the system. Everything that reads, understands or changes a PDF is in `LazyPDF.Core` and written by us. Turning a page into pixels is `Windows.Data.Pdf` on Windows and PDFKit on Apple, behind `IPageRenderer`. This is what keeps the app small: a renderer with full font, colour and transparency support is years of work and the systems already have one, while none of them will edit a file.

## Global rules

1. Core uses no UI and no OS-specific API. It takes bytes and gives bytes. Fonts, images it cannot decode, OCR and time reach it through small interfaces an app passes in.
2. A helper not listed here is `private` or `internal`.
3. Coordinates: the engine speaks PDF user space (points, origin bottom-left) in page objects and content. App geometry is points with origin top-left and y down, as in the sisters. `PageGeometry` converts between them and applies `/Rotate` and the crop box; nothing else does.
4. Reading is forgiving, writing is strict. The reader repairs what it can and says so (`PdfDocument.Repairs`); what the writer emits must pass a strict parser. No third-party file ever crashes the engine: bad input throws `PdfReadException`, and every recursion and allocation driven by file contents has a cap.
5. Never lose the user's data. A save goes to a temporary file, is read back, then replaces the original. Signed files get incremental updates only, unless the user chooses otherwise.
6. Files as written by us reopen in `Windows.Data.Pdf` and PdfPig. Every writer test does this.
7. User text is short, as in the sisters: a status line is six words at most with the full sentence for screen readers, a problem is titled by what is wrong and says what to do. It goes through `Loc.T` (English is the key) and Turkish lands with it. Texts both platforms show live in Core, in a `...Text` type.
8. Settings files load across versions by Lazy Scan's rules (Global rule 6 there), in `%APPDATA%\Lazy PDF`.
9. Code copied from a sister says so in its header: "From Lazy Scan's PdfSyntax.cs". Copying with the names changed is how code moves between the three repos.

## Names

"Lazy PDF" in text, `LazyPDF` in code. ## The edit session

An open file is one growing byte buffer. Each edit commits an incremental update (ISO 32000-1 7.5.6) to the end of it, and undo moves the end back to the previous `%%EOF`; redo moves it forward. So undo is exact and cheap, the renderer always reads a complete valid PDF, and a crash loses nothing that was autosaved. `Save` writes the buffer as it stands; `Save compact` rewrites it without the history.

## Feature target

Against Acrobat Pro. Skipped on purpose: XFA dynamic forms (detected and reported), 3D and rich media, Adobe DRM, cloud review and cloud signing requests, press separations and trapping.

Beyond Acrobat: scan into the open file through Lazy Scan, print with Lazy Print's booklets and N-up, one-click clean for sharing, redaction by pattern with a report of what was removed, signature checks in plain words, every saved version recoverable from the file, phone capture and signing over the phone link, folder rules, and all of it offline with no account.

# Modules

Each section below is written when its layer lands.

### Filters

Stream filters, predictors and image sample decoding. Uses only `Syntax/`. Every `PdfObject` argument is already resolved (no references); where a reference can occur inside (a colour space array, a function), the caller passes a `Func<PdfObject?, PdfObject?>` resolver.

**`PdfFilters`** (static)
- `byte[] Decode(byte[] data, PdfObject? filter, PdfObject? parameters)` and `Decode(..., long maxSize)`. `filter` is a name or an array of names, `parameters` a dictionary or an array of dictionaries (entry i goes to filter i, a null entry is fine). Handles FlateDecode/Fl, LZWDecode/LZW (`/EarlyChange`), ASCIIHexDecode/AHx, ASCII85Decode/A85, RunLengthDecode/RL, CCITTFaxDecode/CCF, Crypt. Predictors 2 and 10-15 run after Flate and LZW.
- `Crypt` only passes through when `/Name` is absent or `/Identity`; any other name is `Unsupported` (decryption is the document layer's job, before this call).
- DCT, JPX and JBIG2 are image codecs: `Decode` throws `Unsupported` for them. Use `PdfDecodedStream DecodeToCodec(byte[] data, PdfObject? filter, PdfObject? parameters, long maxSize = DefaultMaxSize)`: it undoes the filters in front of the codec and returns `record PdfDecodedStream(byte[] Data, string? Codec, PdfDictionary? Parameters)`. `Codec` is `"DCTDecode"`, `"JPXDecode"` or `"JBIG2Decode"` (abbreviation expanded), `Data` the raw JPEG or JP2 bytes, `Parameters` that filter's `/DecodeParms`. With no codec in the chain `Codec` is null and `Data` is fully decoded.
- `byte[] Inflate(byte[] data[, long maxSize])`, `byte[] Predict(byte[] data, PdfDictionary? parameters)`. `const long DefaultMaxSize = 1 << 30`.
- Limits: output of any filter in the chain larger than `maxSize` throws `PdfReadException` with `Unsupported` (decompression bombs, a CCITT image whose `Rows * stride` is too big, one-bit rows that expand). Unknown filter: `Unsupported`. Bad ASCIIHex or ASCII85 characters, a /Filter that is not a name, a bad predictor bit depth: `Damaged`.
- Tolerance: Flate reads the deflate stream without checking Adler-32, so a bad or missing checksum, a cut-off tail, and data with no zlib header still give what decoded; nothing decoded is `Damaged`. LZW stops at a bad code, RunLength and the ASCII filters at a short tail. PNG rows with an unknown filter byte are left as they are. A last predictor row cut short is kept as far as it goes. Predictors work at 1, 2, 4, 8 and 16 bits and any `/Colors`.
- CCITT: `/K` below, at and above zero, `/Columns` (default 1728, 1 to 1048576), `/Rows` (0 = until the data ends; missing rows come out white), `/EncodedByteAlign`, `/EndOfLine` (EOLs are accepted either way), `/BlackIs1`. Output is packed rows, each byte aligned. A bad Group 4 code ends the data; Group 3 resynchronises at the next EOL.

**`PdfFilterEncoders`** (static)
- `Flate(ReadOnlySpan<byte>, CompressionLevel level = Optimal)`, `AsciiHex(ReadOnlySpan<byte>)` (ends with `>`), `Ascii85(ReadOnlySpan<byte>)` (ends with `~>`, no line breaks), `RunLength(ReadOnlySpan<byte>)`, `Lzw(ReadOnlySpan<byte>, bool earlyChange = true)`. All return `byte[]`; the writer sets `/Filter` itself.

**`PdfFunction`** (abstract, `Filters/PdfFunction.cs`)
- `static PdfFunction Parse(PdfObject? function, Func<PdfObject?, PdfObject?> resolve, Func<PdfStream, byte[]> decodeStream)`. Types 0 (sampled, up to 8 inputs, 1 to 32 bits, multilinear), 2, 3 and 4 (PostScript calculator, 100 stack entries, 32 nesting levels). An array of functions is read as one function with the outputs joined. `decodeStream` gives a stream's data with its filters undone.
- `int Inputs`, `int Outputs`, `void Evaluate(ReadOnlySpan<double> input, Span<double> output)`; input is clipped to `/Domain`, output to `/Range`. Another type is `Unsupported`; broken structure is `Damaged`, and so is a calculator that pops an empty stack or passes 100 entries, found at `Evaluate`.

**`PdfImageSamples`** (static)
- `PdfRgbaImage ToRgba(PdfDictionary image, byte[] samples, Func<PdfObject?, PdfObject?> resolve, Func<PdfStream, byte[]> decodeStream)`, `record PdfRgbaImage(int Width, int Height, byte[] Rgba)`: straight RGBA8, top row first.
- `samples` are the image data with every filter undone, an image codec's too (the caller decodes JPEG or JPX to raw samples first). `decodeStream` is called for Indexed lookup streams, function streams, `/SMask` and `/Mask` streams, and must return their decoded samples likewise.
- Handles `/BitsPerComponent` 1, 2, 4, 8, 16, `/ImageMask` (black where painted, alpha 0 elsewhere), `/Decode`, DeviceGray/RGB/CMYK (plain (1-c)(1-k), no profile), CalGray (as gray), CalRGB, Lab, ICCBased (by `/N`, else `/Alternate`; the profile is not applied), Indexed (string or stream lookup), Separation and DeviceN through the tint function, colour key `/Mask` arrays, stencil `/Mask` streams, `/SMask` (`/Matte` ignored). A mask of another size is sampled nearest. Inline image keys (/W /H /BPC /CS /IM /D) and colour space names (G, RGB, CMYK, I) work. No `/ColorSpace` (JPX): gray, RGB or CMYK by sample count. Short data reads as zero.
- Limits: `Width * Height` over `PdfImageSamples.MaxPixels` (2^27) or a row over 2^26 samples is `Unsupported`, checked before any allocation. Missing size, a bad depth or colour space is `Damaged`; Pattern or an unknown space is `Unsupported`.

### Crypt

The standard security handler (ISO 32000-1 7.6, ISO 32000-2 for R 6). Uses Syntax only; strings and streams go in and out as byte arrays, and the Document layer decides which objects to pass. Files: `PdfSecurity.cs` (reading, decrypting, encrypting), `PdfSecurityCreate.cs`, `PdfKeys.cs`, `PdfPasswords.cs`, `Rc4.cs` (the last three internal).

```csharp
public sealed partial class PdfSecurity
{
    static PdfSecurity? Open(PdfDictionary encrypt, byte[] firstId, string? password);
    static PdfSecurity Create(string userPassword, string ownerPassword, PdfPermissions permissions,
                              PdfCryptStrength strength, byte[] firstId, Random? random = null);
    bool OpenedAsOwner { get; }
    PdfPermissions Permissions { get; }
    bool EncryptMetadata { get; }
    int Revision { get; }
    PdfDictionary Dictionary { get; }
    byte[] DecryptString(int number, int generation, byte[] data);
    byte[] DecryptStream(int number, int generation, byte[] data, PdfDictionary streamDictionary);
    byte[] EncryptString(int number, int generation, byte[] data);
    byte[] EncryptStream(int number, int generation, byte[] data, PdfDictionary streamDictionary);
}
[Flags] enum PdfPermissions { None, Print, Modify, Copy, Annotate, FillForms, ExtractForAccessibility, Assemble, PrintHighQuality, All }
enum PdfCryptStrength { Aes256, Aes128 }   // R 6 (default), R 4
```

**Reading.** V 1 R 2 and V 2 R 3 (RC4, 40 to 128 bits), V 4 R 4 (crypt filters V2, AESV2, Identity, with separate `/StmF` and `/StrF`), V 5 R 5 and R 6 (AESV3). User and owner passwords work on every revision; the owner is tried first. `Open` takes the `/Encrypt` dictionary fully resolved (`/CF` and its filters direct) and the first string of the trailer's `/ID`, and returns null for a wrong password. A null or empty password tries the empty user password. Passwords for R 2 to 4 are Latin-1 (UTF-8 outside it); for R 5 and 6 they are SASLprepped and cut at 127 bytes, and the NFKD form PDFKit uses is tried second. `/Perms` is not checked.

**Throws** `PdfReadException`: `Unsupported` for another `/Filter`, V or R outside the list above, an unknown `/CFM`, or a cipher that does not fit the revision (AESV3 below R 5, RC4 or AESV2 on R 5 and 6); `Damaged` for missing or short `/O`, `/U`, `/OE`, `/UE`, or a `/StmF` or `/StrF` naming a filter not in `/CF`. Decrypting never throws on bad data.

**Decrypting.** AES takes the IV from the first 16 bytes and drops a trailing partial block. A bad PKCS#7 tail is kept as decrypted, not rejected; data under 32 bytes gives an empty array. `DecryptStream` and `EncryptStream` return the input array itself, untouched, for `/Type /XRef`, for `/Type /Metadata` when `EncryptMetadata` is false, and for a `/Crypt` filter naming Identity (or no name). A `/Crypt` filter naming another `/CF` entry uses that entry's method. The stream dictionary's `/Filter` and `/DecodeParms` must be resolved. An Identity string or stream method also returns the input array.

**The caller's side.** The `/Encrypt` dictionary itself, the `/Contents` of a signature dictionary, and strings inside object streams are never encrypted; the object-stream container is decrypted as a whole. Stream data is decrypted before its filters run and encrypted after they have been applied. Keep the `/ID` the key was made with: for R 4 the first `/ID` string is part of the key.

**Writing.** `Create` makes R 6 (V 5, AESV3) or R 4 (V 4, AESV2) with `EncryptMetadata` true. `Dictionary` is the value for the trailer's `/Encrypt` (direct strings in hex; write it as an indirect object, itself unencrypted). `OpenedAsOwner` is true on a created handler. A real owner password is kept; an empty one becomes random bytes nobody knows, so the permissions bind everyone. `/P` gets its reserved bits set. Keys, salts and IVs come from `random` (a seeded `Random` gives the same file, for tests), else the system generator. `Encrypt*` on an opened file uses its keys, so an incremental update of an encrypted file writes objects the existing keys decrypt; AES IVs there are always from the system generator. Output was read back by pypdf with both passwords for both strengths.

**Limits.** Public-key handlers, V 3 and R 7 or higher are Unsupported. A handler holds no mutable state and can be shared between threads. R 6 hashing costs a few milliseconds per password try, and the key is derived once per `Open`.

**Tests.** `windows/LazyPDF.Core.Tests/Crypt/`: fixtures (`locked`, `owner-only-*`, and pypdf's `crypt-rc4-40`, `crypt-aes128`, `crypt-aes256-r5`, `crypt-aes256`, user `secret`, owner `owner`, in `Tests/Fixtures/Documents`), synthetic dictionaries for every revision, stream rules, malformed dictionaries, creation.

### Fonts/Tables: encodings, glyph names, Standard 14, CMaps

Folder `Fonts/Tables/`, namespace `LazyPDF.Core`, no dependency on other layers. The data (glyph list, AFM metrics, CJK CMaps) is compiled in as deflated base64 strings and decoded on first use; nothing is read from disk.

**`static class PdfEncodings`** (ISO 32000-1 Annex D). Each table is an `IReadOnlyList<string?>` of 256 glyph names by code, null where the encoding assigns none: `Standard`, `WinAnsi` (unused codes are `bullet`, 160 is `space`, 173 `hyphen`), `MacRoman`, `MacExpert`, `PdfDoc`, `Symbol`, `ZapfDingbats` (the last two are the fonts' built-in encodings).
`IReadOnlyList<string?>? ByName(string pdfName)` takes `StandardEncoding`, `WinAnsiEncoding`, `MacRomanEncoding`, `MacExpertEncoding`, `PDFDocEncoding`, else null. `int CodeOf(IReadOnlyList<string?> encoding, string glyphName)` gives the first code or -1.

**`static class GlyphList`** (Adobe Glyph List specification, AGL plus the ZapfDingbats list).
- `string? UnicodeOf(string glyphName)`: drops everything after the first period, splits on underscores, maps each component by list, `uniXXXX[XXXX...]` or `uXXXX[XX]`; surrogates and values above 10FFFF do not map; a component that maps to nothing is left out; null when nothing is left (`.notdef`, `g123`). Names over 256 characters give null. Multi-character results are possible (`fi`, `dalethatafpatah`).
- `string NameOf(int codePoint)`: the AGL name, preferring the names the Annex D encodings use (`space`, not `spacehackarabic`); else `uniXXXX` or `uXXXXX`; `.notdef` for what is not a scalar value.
- `string? ZapfNameOf(int codePoint)`: the `a1`-style name, or null.

**`sealed class Standard14`**, with `readonly record struct FontBox(int Left, int Bottom, int Right, int Top)`.
- `static IReadOnlyList<Standard14> All` (14 fonts), `static Standard14? Find(string baseFont)`.
- `Find` ignores a subset tag, case, spaces, commas and the `PS` and `MT` of Windows names: Arial, ArialMT, Arial,Bold, Arial-BoldItalicMT, TimesNewRoman, TimesNewRomanPS-BoldMT, CourierNew, SymbolMT and so on map to the AFM font. Other faces (Arial Narrow, Arial Black) give null, they are not metric-compatible.
- Members: `Name`, `Ascent`, `Descent` (negative; the AFM Ascender/Descender, or the box top and bottom for Symbol and ZapfDingbats), `FontBox BBox`, `CapHeight`, `XHeight` (0 for Symbol and ZapfDingbats), `double ItalicAngle`, `StemV`, `IsFixedPitch`, `IsBold`, `IsItalic`, `IsSerif`, `IsSymbolic`, `Flags` (FontDescriptor /Flags), `BuiltInEncoding`, `int? WidthOf(string glyphName)` in 1/1000 em, null when the font has no such glyph. No kerning, no per-glyph boxes.

**`sealed class CMap`**
- `static CMap Parse(byte[] data, CMap? useCMap = null)`: reads an embedded CMap or ToUnicode stream: codespacerange, cidrange, cidchar, notdefrange, notdefchar, bfrange (string and array forms), bfchar (hex or glyph name), `/Name usecmap`, `/WMode`, `/CMapName`. Never throws; a malformed section is skipped from the bad entry on. Pass the stream dictionary's /UseCMap as `useCMap`. Bounds: linear in the data, at most 1,000,000 mappings and 100 codespace ranges kept, a destination string is cut at 128 UTF-16 units, hex codes longer than four bytes are skipped. Later mappings win over earlier overlapping ones. With no codespace given, any byte value at the lengths the mappings use is accepted.
- `static CMap Predefined(string name)`: `Identity-H`, `Identity-V`, and 61 of Adobe's CID CMaps (Adobe cmap-resources, BSD-3): GB (GB-EUC, GBpc-EUC, GBK-EUC, GBKp-EUC, GBK2K, UniGB-UCS2/UTF16), CNS (B5pc, ETen-B5, ETenms-B5, HKscs-B5, CNS-EUC, UniCNS-UCS2/UTF16), Japan (83pv, 90ms, 90msp, 90pv, Add, Ext-RKSJ, EUC, H, V, UniJIS-UCS2/UCS2-HW/UTF16), Korea (KSC-EUC, KSCms-UHC, KSCms-UHC-HW, KSCpc-EUC, UniKS-UCS2/UTF16), with their -H and -V forms. Instances are cached and shared; do not mutate. Not included: the `Adobe-*-UCS2` CID to Unicode maps and the `Adobe-*-N` ones. An unknown name returns a fallback with `IsFallback` true: two-byte codes, CID equal to the code. Callers decide whether to warn.
- `int NextCode(ReadOnlySpan<byte> bytes, out int length)`: ISO 32000-1 9.7.6.3, shortest prefix inside a codespace range, mixed lengths allowed. Bytes matching no range consume as many bytes as the shortest range that starts like them (else the shortest range), so a string stays in step. Empty input gives length 0. Codes are up to four bytes; a four-byte code above 0x7FFFFFFF is a negative int.
- `int? CidOf(int code)`, `int? CidOf(int code, int length)`: the CID, a notdefrange's id for unmapped codes in one, else null. Without the length the shortest code length with a mapping is taken, so <41> and <0041> clash; pass the length from `NextCode` when the CMap has mixed lengths.
- `string? UnicodeOf(int code)`, `string? UnicodeOf(int code, int length)`: bfchar and bfrange text, may be several characters or a surrogate pair. For the `Uni*-UCS2` and `Uni*-UTF16` predefined CMaps the code itself is the Unicode value and is returned.
- `Name`, `IsVertical` (WMode 1), `IsFallback`.

**`static class ToUnicodeCMap`**: `byte[] Write(IEnumerable<KeyValuePair<int, string>> map, int codeBytes = 2)` returns the stream body (ASCII): the usual CIDInit preamble, one codespace range 0 to FF..FF of `codeBytes` (1 to 4), bfrange for runs where code and the last UTF-16 unit both step by one without a low-byte wrap, bfchar for the rest, 100 entries at most per section, UTF-16BE text. Last text for a duplicate code wins, empty text is dropped. A code outside the byte length or `codeBytes` outside 1 to 4 throws `ArgumentOutOfRangeException`. The caller sets /Length and any filter.

### Fonts/Programs: font programs and embedding

Parsers over `byte[]` for the three font program formats a PDF holds, a TrueType subsetter and the builder that turns text into the pieces of an embedded font. No `PdfDocument`, no `Syntax` types, no other `Fonts/` folder. A damaged program gives zeros, empty outlines or a null, never an exception; every count read from a file is bounded by the data. Glyph names are plain strings.

**Outlines.** `GlyphOutline.Segments` is a list of `OutlineSegment(Op, X, Y, X1, Y1, X2, Y2)` in font units, y up. `Op` is `Move`, `Line`, `Quad` (control point X1,Y1), `Cubic` (X1,Y1 and X2,Y2) or `Close`. `Bounds()` gives a `GlyphBounds(XMin, YMin, XMax, YMax)` over all points, null when empty.

**`TrueTypeFont`** reads sfnt files, TrueType or OpenType/CFF.
- `static int CollectionCount(byte[])` is 1 for a plain file, n for a .ttc, 0 for no sfnt. `static TrueTypeFont? TryParse(byte[], int collectionIndex = 0)` is null without usable head and maxp.
- Metrics in font units: `UnitsPerEm`, `GlyphCount`, `Ascent`, `Descent` (negative), `LineGap`, `CapHeight` (OS/2, else the box of H), `XHeight`, `FontBounds`, `ItalicAngle`, `IsFixedPitch`, `WeightClass`, `FamilyName`, `PostScriptName`.
- `GetAdvance(gid)`, `GetBounds(gid)` (null for a blank glyph), `GetOutline(gid)` (composites resolved; null for a glyph that does not exist).
- `GlyphForCodePoint(cp)` is 0 when absent. It uses cmap (3,10), (0,x), (3,1) in that order, and for a font with only a (3,0) symbol table tries the code and 0xF000 + code. Also `GlyphForCmap(platform, encoding, code)`, `HasCmap`, `GlyphForVariation(cp, selector)` (format 14).
- `GlyphName(gid)` and `GlyphForName(name)` read post formats 1 and 2, else the CFF charset. The Windows system fonts have post format 3 and no names.
- `FsType`, `EmbeddingAllowed` (false for fsType 0x0002 and 0x0200), `SubsettingAllowed` (false for 0x0100). `Cff`, `IsCff`, `HasOutlines`, `HasTable(tag)`.

**`CffFont`** reads a bare CFF (FontFile3 /Type1C, /CIDFontType0C) or the 'CFF ' table of an OpenType font. `TryParse(byte[])` and `TryParse(byte[], offset, length)` copy the bytes and return null on a broken file.
- `Name`, `IsCid`, `GlyphCount`, `FontMatrix`, `FontBounds`, `GetWidth(gid)`, `GetOutline(gid)` (Type 2 charstrings including subroutines, hint masks, flex, arithmetic and seac-style endchar).
- Name-keyed: `GlyphName`, `GlyphForName`, `GlyphForCode(code)` through the built-in encoding. CID-keyed: `GlyphForCid(cid)` and `CidForGlyph(gid)`; per-glyph FDSelect widths. A name-keyed font used as a CIDFont takes CID = gid (9.7.4.2).
- Limit: the predefined Expert charsets and Expert encoding are not tabulated; they read as identity or empty.

**`Type1Font`** reads PFA (hex or binary eexec), PFB and a FontFile stream. `TryParse(byte[])` is null when no charstring is found.
- `FontName`, `FontMatrix`, `FontBounds`, `BuiltInEncoding` (name per code, null where none; `StandardEncoding` is expanded), `GlyphNames` in file order, `HasGlyph`, `GetWidth(name)`, `GetOutline(name)` (Subrs, flex, hint replacement, div, seac, sbw; lenIV honoured, RD/-| both).

**`TrueTypeSubsetter.Subset(byte[] font, IReadOnlyCollection<int> glyphIds, int collectionIndex = 0)`** returns `SubsetResult(Status, Data, GlyphMap)`.
- Glyphs are renumbered densely in the order of the old IDs; .notdef stays 0; `GlyphMap` is old to new. A PDF font from it uses the new ID as the character code and `/CIDToGIDMap /Identity`. Composite glyphs bring their components; unknown IDs are ignored.
- Glyph programs are copied as they are, so cvt, fpgm and prep stay; nothing else of the hinting is dropped. Output tables: head, hhea, maxp, hmtx, loca, glyf, OS/2, post (format 3), name, and the three hinting tables if present. No cmap. Checksums and the head adjustment are set; tables are sorted and 4-byte aligned.
- `Status` is `Ok`, `Unreadable`, `NotTrueType` (CFF or no glyf), `EmbeddingForbidden`, `SubsettingForbidden`. Data and map are empty unless Ok.

**No CFF subsetter.** An OpenType font with CFF outlines is embedded whole as `/FontFile3 /Subtype /OpenType` under a `/CIDFontType0` descendant; a CFF that is not CID-keyed uses CID = glyph ID, so no `CIDToGIDMap`.

**`EmbeddedFontBuilder.Build(byte[] font, IEnumerable<string> texts, out EmbedStatus status, int collectionIndex = 0)`** returns an `EmbeddedFont?`, null with `status` `Unreadable`, `NoOutlines` or `EmbeddingForbidden`. Characters are the Unicode scalar values of the texts (below U+0020 skipped).
- TrueType: subset, code = new glyph ID, `IsSubset` true, `IsCff` false (`/CIDFontType2`, `/FontFile2`, Identity CIDToGIDMap). A TrueType font with `SubsettingAllowed` false, and any CFF font, is passed through whole with code = glyph ID, `IsSubset` false. A collection is subset by index but never passed through (null).
- `BaseFont` carries a six-letter tag, derived from the glyph list, when subset. `Program` is the file bytes.
- `Codes` maps code point to code; `Missing` lists code points with no glyph (they encode as 0). `Encode(string)` gives the two-byte codes of Identity-H. `ToUnicode()` gives code to code point for the /ToUnicode CMap; characters sharing a glyph keep the lowest code point.
- `Widths` are `WidthRun(FirstCid, Widths)` in 1/1000 em, one `/W` entry each, consecutive codes merged; `DefaultWidth` 1000. `Descriptor` is `FontDescriptorValues(Flags, FontBBox, ItalicAngle, Ascent, Descent, CapHeight, StemV)` in 1/1000 em; flags are Nonsymbolic, plus FixedPitch and Italic when they apply; StemV is estimated from the weight class.
- Turkish ğ Ğ ş Ş ı İ go through this path like any other character; WinAnsi is not involved.

### Document: reading

`PdfDocument : IDisposable` (partial, `Document/`) holds a file as one `byte[]` (Open does not copy it; do not change it while the document is open). Not safe to share between threads. Objects load on first use and are cached, so `Get(n)` returns the same instance every time and an edit to it stays.

**Opening.** `static PdfDocument Open(byte[] bytes, string? password = null)` and `Open(string path, string? password = null)`. Throws `PdfReadException` only: `NotPdf` (no `%PDF-` in the first 1024 bytes), `Damaged` (no catalog and no pages anywhere), `Unsupported` (a handler or filter we lack), `PasswordRequired` (new in `PdfReadProblem`: the password does not open the file; a null password tries the empty one). Bytes before the header are cut off, so offsets count from `%PDF` and `Length` is the size after the cut.

**Repair.** If the cross-reference data fails (no or wrong `startxref`, broken `/Prev`, missing trailer, truncation, a catalog that does not resolve) the file is scanned once for `n g obj` and trailers, the newest definition of each object wins, object streams are read and the catalog is found by `/Type /Catalog`, or made from the page tree, or the page tree from the `/Type /Page` objects. Offsets slightly off are fixed object by object when it is loaded. A wrong or missing `/Length` is fixed at `endstream`, a missing `endobj` is no problem. `IReadOnlyList<string> Repairs` says what was done (at most 100 lines, set as it happens: stream and page repairs appear when the stream or page is first used). Linear in file size.

**Members.** `Trailer`, `Catalog` (never null), `Info` (`PdfDictionary?`), `Id` (`IReadOnlyList<byte[]>`), `Version` (header or catalog `/Version`, the newer), `Length`, `IsEncrypted`, `PdfSecurity? Security`, `IsSigned`, `IsCertified`, `HasXfa`, `IsLinearized`, `IsTagged`, `int? PdfAPart`, `string? PdfAConformance`.

**Objects.** `PdfObject? Get(int number)` (null if free, unlisted or unreadable), `PdfObject? Resolve(PdfObject?)` (follows 32 hops, null for null or a loop), `T? Resolve<T>(PdfObject?)`, `IReadOnlyList<int> ObjectNumbers`. Typed helpers take a dictionary and a key, resolve, and return null on a type mismatch: `Dict`, `Array`, `Stream`, `Name` (string), `Bool`, `Number` (double?), `Integer` (long?, accepts 90.0), `Rect` (also takes a `PdfObject?`; corners in any order, null if no area). `PdfReference Add(PdfObject)` (new number, generation 0), `void Set(int number, PdfObject)`, `void Delete(int number)`.

**Streams.** `byte[] RawData(PdfStream)`: decrypted, still filtered. `byte[] Data(PdfStream)`: decrypted and decoded; `/Length`, `/Filter`, `/DecodeParms` are resolved first, then `PdfFilters.Decode`. `PdfStream` now has `Data` (`byte[]?`, settable: the bytes to store, filtered, not encrypted; null while the data is in the file), `Number`, `Generation`, and a constructor `PdfStream(PdfDictionary, byte[])`. When `Data` is set, `RawData` returns it.

**Encryption.** `PdfSecurity.Open` gets the fully resolved `/Encrypt` and the first `/ID` string; null from it means wrong password. Strings are decrypted in place as their object loads (`PdfString.Bytes` is settable), except in object streams, in `/Encrypt` and in a signature's `/Contents`. Objects in memory are therefore always plain: the saver encrypts again with `Security`, using the object's number and `GenerationOf(number)`.

**Pages.** `IReadOnlyList<PdfPage> Pages`, walked from the catalog tolerantly (loops, wrong `/Count`, missing `/Type` or `/Parent`, junk in `/Kids`, depth 256; a tree with no pages falls back to the page objects in the file, the first time only). `PdfPage`: `Dictionary`, `Reference`, `Index`, `Resources` (inherited), `MediaBox` (US Letter if unusable), `CropBox` (clipped to the media box), `TrimBox`, `BleedBox`, `ArtBox` (default the crop box), `Rotate` (0, 90, 180, 270), `UserUnit`, `byte[] Contents()` (streams joined by `\n`; one that fails is left out and noted in `Repairs`). Properties read the live dictionary; only what a page inherits was taken at the walk. After changing the tree call `internal RefreshPages()`.

**Geometry.** `PdfRect(x1, y1, x2, y2)` is normalized (`Left Bottom Right Top`, `Width`, `Height`, `IsEmpty`, `Intersect`, `ToArray`). `PageGeometry(PdfPage)` or `(PdfRect box, int rotate, double userUnit = 1)`: `Width`, `Height` (display points), `Rotation`, `Matrix` (user to display), `ToDisplay(x, y)`, `ToUser(x, y)`, and the same for rects (`DisplayRect(X, Y, Width, Height)`, top-left origin).

**For the saver (internal).** Every loaded object keeps a fingerprint of its text as read (after decryption); a save finds changes by comparison, nothing to call. `ChangedObjects()` gives the numbers, ascending, of loaded objects whose text differs, whose stream has `Data` set, or that were made by `Add`/`Set`. `DeletedObjects` gives numbers freed. `TrailerChanged` compares the trailer. Also `StartXref` (0 after a rebuild), `XrefIsStream`, `XrefRebuilt` (after it the old table is useless: write a full one), `NextObjectNumber`, `GenerationOf(n)`, `Source` (the bytes). A stream is compared by its dictionary and `Data` only, so to change one, set `Data`.

**Syntax changes.** `PdfDictionary` has `Count`, `Remove`, a key index past 12 entries; `PdfNumber(double)`; `PdfString.Bytes` and `IsHex` settable. The lexer is more forgiving (odd numbers, unclosed arrays and dictionaries at `endobj`, stray keys and hex digits). `Syntax/` is split into `PdfSyntax.cs`, `PdfBytes.cs`, `PdfLexer.cs`.

### Document: writing

**Incremental.** `byte[] PdfDocument.SaveIncremental()` returns the bytes read followed by an update (ISO 32000-1 7.5.6); the original bytes are never touched, which signatures rest on. Only changed or added objects are written (found by comparison with what was read, see "For the saver" above), plus free entries for deleted ones. The section is a classic table when the newest one in the file is a table (a hybrid file too: the older `/XRefStm` stays reachable through `/Prev`), a cross-reference stream when it is a stream. The trailer carries every key the file's has, `/Size`, `/Prev`, a new `/ID` (first string kept, second fresh; both fresh when there was none). An object that came from an object stream is written as a plain one. Strings and streams are encrypted again with `Security`, except the `/Encrypt` object, a signature's `/Contents` and the cross-reference stream. After a rebuild (`XrefRebuilt`) the section lists every object and has no `/Prev`. With no change the result is the bytes read. A file with bytes before `%PDF` loses them (offsets count from the header). Edits to the document stay in memory until saved; saving does not reset the change tracking, so reopen the result (`PdfDocument.Open`) to edit on.

**Rewrite.** `byte[] PdfDocument.SaveRewrite(PdfSaveOptions? options = null)` writes a new file of the objects reachable from `/Root` and `/Info`, numbered from 1 in the order met (catalog first), generation 0, references to missing objects dropped, no history. `PdfSaveOptions(bool UseObjectStreams = false, PdfSecurity? Security = null, byte[]? DocumentId = null)`: `UseObjectStreams` packs plain objects 100 to a stream and writes a Flate cross-reference stream (header 1.5 at least; the catalog, streams and signature dictionaries stay plain, because PdfPig asks for the catalog before it can decrypt). `Security` encrypts the output; null leaves it open, so an encrypted document written with null is decrypted, and `document.Security` keeps its encryption (and its first `/ID`, which the older handlers' keys are made from). A handler from `PdfSecurity.Create` for `Aes128` must have been given the same first id as `DocumentId`. Header is raised to 1.6 for R 4 and 1.7 for R 6. A new `/ID` otherwise. Streams with no filter, or only LZW, ASCII85, ASCIIHex or RunLength, are deflated when that is smaller; Flate streams, streams with a predictor, DCT, JPX, JBIG2, CCITT, Crypt filters and metadata are copied as stored; a stream that does not decode is copied as it is. Signatures do not survive a rewrite; the app checks `IsSigned` first. No linearization.

**Safe save.** `static void PdfFileSaver.Save(string path, byte[] bytes, string? password = null)`: writes a hidden temporary file in the same folder, flushes it, reads it back, checks the bytes are equal and `PdfDocument.Open` takes them, then `File.Replace` (a rename where the file system has no ReplaceFile), keeping attributes and creation time. Any failure deletes the temporary file and leaves the original. Throws `IOException`, `UnauthorizedAccessException` (a read-only file is not replaced) or `PdfReadException`.

**Edit session.** `PdfEditSession` holds a file as one growing buffer. `Open(byte[] bytes, string? password = null)`, `Open(string path, string? password = null)` (`PdfReadException` as the reader). `PdfDocument Document` is the document to edit; `ReadOnlyMemory<byte> Current` is the committed bytes, a complete valid PDF, replaced by a new array (never changed in place) on every commit, undo and redo, so a renderer may keep what it holds. `bool Commit(string label)` writes `Document`'s changes as one incremental update, drops the redo steps, reopens `Document` on the new bytes (any page or object held from the old one is stale) and returns false, adding nothing, when nothing changed; the new bytes are read back before they are taken. `bool Undo()` and `bool Redo()` move the end to the previous or next `%%EOF` of the session's own steps and drop uncommitted changes; history never reaches before the file as opened. `CanUndo`, `CanRedo`, `UndoLabel`, `RedoLabel` (null when none). `bool IsDirty`: the position differs from the last save or open, or `Document` holds uncommitted changes (a file the reader had to repair is dirty from the start). `void Save(string path)` commits what waits as a step with an empty label, then `PdfFileSaver.Save`. `void SaveCompact(string path)` writes `SaveRewrite` (object streams unless PDF/A-1, encryption kept) and continues from that file with no undo history. The buffer exists twice in memory (`Current` and the longest state after an undo); a commit copies it once.

**Versions.** `IReadOnlyList<PdfVersion> Versions`, oldest first, of the file as opened: `PdfVersion(int Number, int End)`, `End` the byte length of that state, found by following the cross-reference sections back and taking the `%%EOF` whose `startxref` names each one (so a `startxref` inside stream data, or a linearized file's first-page section, does not count). A rebuilt file has none. `byte[] ExtractVersion(PdfVersion)` is the file cut at `End`; `void SaveVersion(PdfVersion, string path)` writes it by `PdfFileSaver`.

**Limits.** Files up to 2 GB (`byte[]`). Object streams hold 100 objects. Whole files are built in memory.

### Review fixes

Changes to behaviour and limits in the layers above after review. No public signature was removed; two members were added to the internal surface and `PdfFileSaver` gained an internal overload.

**Limits (rule 4).**
- An object that needs another object to load (a `/Length`, an object stream, an object stream inside an object stream) nests at most 32 deep; past that the object reads as null.
- `Flatten`, which resolves `/Filter`, `/DecodeParms` and `/Encrypt`, stops after 4096 values; the rest reads as null.
- `PdfFunction.Parse` parses an object shared by several functions once. A function has at most 64 outputs, `/Domain` and `/Range` must have each min at most max, and a type 0 sample count that would pass 2^34 bits is damaged.
- Predictor `/Colors` above 65536 is damaged.
- A decoded object stream may not pass 64 MB, nor `/Metadata` 16 MB, nor the streams of one page 256 MB together; the stream over the limit is dropped with a repair, not thrown. Cached object streams are capped at 256 and 128 MB together.
- A CFF font reads at most 256 font DICTs, each cut to 64 KB; a TrueType composite may build 100000 points in all.
- A `/Size` past the object number limit is ignored, and an `/Index` entry past it makes the cross-reference stream damaged.

**Reading.**
- `PdfDocument.Data` strips the Crypt stage of an encrypted file's `/Filter` once decryption has done it, so `[/Crypt /FlateDecode]` with `/Name /StdCF` decodes.
- The standard security handler reads `/EFF`: a stream of `/Type /EmbeddedFile` without a Crypt filter uses it, not `/StmF`. AES-128 with a key that is not 128 bits is `Unsupported` when the handler opens.
- A trailer key older sections would supply is not removed by leaving it out. `PdfUpdate` writes `/Info null` after the `/Info` of a file was taken out.
- Repair scans a value after `trailer` that is not a dictionary once; running out of object numbers while repairing is a `PdfReadException`.
- `PdfDocument.Set` copies file-backed stream data into `Data` before the stream takes its new number.

**Writing.**
- The cipher for a stream is chosen from the same resolved `/Filter` and `/DecodeParms` on writing as on reading (`PdfObjectWriter.WriteStream` takes the resolved view).
- Updates and rewrites keep the first `/ID` string the file key was made from (`PdfDocument.FirstId`); an indirect `/ID` no longer gives a garbled one. An unencrypted rewrite keeps the first string unless `PdfSaveOptions.DocumentId` gives another; the second is always fresh.
- `SaveRewrite` keeps the pages `Pages` shows even when the tree does not reach them, drops a Crypt filter when the handler changes or goes, and keeps the original bytes of a stream whose Flate data does not decode to a clean end (`Data` with `strict`).
- An update to a file with an xref stream throws `InvalidOperationException` when no object number is left for the stream itself.
- `SaveIncremental` and `PdfEditSession.Save` work from the bytes read, so anything before `%PDF` is gone from the result.

**Safe save.** `PdfEditSession` saves through `PdfFileSaver.Save(path, bytes, password, source, samePages)` (internal): the read-back is refused when it needed a rebuild the source did not, and, except for `SaveVersion`, when the page count differs. `Commit` refuses an update that reads back rebuilt. Once the swap is done a failure to restore attributes or creation time is ignored. `Redo` drops uncommitted changes as `Undo` does.

### Content: parsing, writing, interpreting, fonts

Folder `Content/`, uses Document and Fonts. No user-visible text. Nothing here throws on file contents except `PdfReadException` from stream decoding; every loop and recursion has a cap.

**`ContentParser.Parse(byte[]) -> IReadOnlyList<ContentOperation>`** (ISO 32000-1 7.8.2, Annex A). Linear, about a million operations a second. `ContentOperation`: `Operator`, `Operands` (`PdfObject`s: numbers keep their text, strings their bytes and hex flag), `Start`/`End` (byte range from the first operand to just past the operator, so `source[..Start] + source[End..]` cuts it), `Image` (for `BI`), `Number(i)`. Tolerance: unknown operators stay and clear their operands, stray `) ] > { }` are skipped, an unclosed array or dictionary ends at the next known operator, `--5` is -5, `1.2.3` is 1.2 then .3, comments, `true false null` are operands. At most 512 operands per operator, 64 levels of nesting, operator names cut at 32 characters. Inline images: `InlineImage(Dictionary as written, Data)`; the end is found by the computed length when width, height, depth and a device space say it and no filter is set, else by `EI` between white space with ASCII text after it that starts a known operator; no `EI` runs to the end. `Expanded(Func<string, PdfObject?>? colorSpace)` gives full key names (`W`->`Width`...) and looks up named colour spaces.

**`ContentWriter`**. `static byte[] Write(IEnumerable<ContentOperation>)` writes operations one per line; parsing the result gives the same operators and operands (inline image data byte for byte). Instance builder, each call returns the writer: `Op(name, IReadOnlyList<PdfObject>)`, `Op(name, params ReadOnlySpan<double>)`, `Add(op)`, `Raw(text)`, `Save`, `Restore`, `Concat(PdfMatrix)`, `Rect`, `MoveTo`, `LineTo`, `CurveTo`, `Close`, `Fill`, `FillEvenOdd`, `Stroke`, `FillAndStroke`, `EndPath`, `Clip`, `LineWidth`, `Dash`, `FillGray/Rgb/Cmyk`, `StrokeGray/Rgb/Cmyk`, `GraphicsState(name)`, `BeginText`, `EndText`, `Font(name, size)`, `MoveText`, `TextMatrix`, `TextRenderMode`, `CharSpacing`, `WordSpacing`, `Show(ReadOnlySpan<byte>)` (hex string), `Paint(name)`, `Paint(name, PdfMatrix)` (q cm Do Q), `BeginMarked(tag[, mcid])`, `EndMarked`; `ToArray()`, `Length`. Numbers go through `PdfNumber(double)`: at most six decimals, no exponent, invariant.

**`PdfMatrix(A..F)`** record struct: `Identity`, `Translate`, `Scale`, `Multiply(m)` (this first, then m), `Transform(x, y)`, `Transform(PdfRect)` (bounding box), `Invert()`, `Determinant`, `ScaleFactor`, `FromArray`.

**`ContentInterpreter(PdfDocument)`**. `Run(PdfPage, ContentVisitor)` starts in the page's user space with its crop box as the clip; `Run(PdfStream form, ContentVisitor, PdfMatrix? = null)` runs one form. `WalkPatterns` (default true) runs a tiling pattern's cell once per run, on first paint with it. `IsTruncated` is set when the run hit 10 million operations. Limits: q stack 256 (deeper ones are counted so `Q` still pairs), form depth 20, 1024 marked-content levels, 1,000,000 segments a path, a form's data 64 MB; a form already running is skipped; a form that does not decode is empty. Resources are looked up in the current stream's, then the enclosing ones'. Clip is the bounding box only. Type 3 glyph procedures and text clip modes (Tr 4-7) are not run; invisible text (Tr 3) is reported.

**`ContentVisitor`** (abstract, all virtual no-ops): `ShowGlyph(ctx, in GlyphInfo)`, `PaintPath(ctx, PathInfo)`, `PaintImage(ctx, ImageInfo)`, `PaintShading(ctx, ShadingInfo)`, `BeginMarked/EndMarked(ctx, MarkedContent)`, `BeginForm/EndForm(ctx, FormInfo)` (patterns too, `IsPattern`). `ContentContext` is the interpreter's live object: `State` (`GraphicsState`), `Forms` (the `PdfStream` chain, outermost first, empty on the page), `OperatorIndex` and `Operation` (index into `ContentParser.Parse(page.Contents())` for the page, or of `document.Data(form)` for `Forms[^1]`), `Marked` (open sequences), `Mcid`, `OptionalContent`, `TextMatrix`, `TextLineMatrix`. Copy what you keep; the objects change as the walk goes.
- `GlyphInfo`: `Character` (`FontChar`), `Code`, `Unicode`, `Font`, `Matrix` (em square to the starting space: the text rendering matrix, a vertical font's origin shift included), `Bounds` (advance by ascent and descent, in the starting space), `Advance` (text space shift, spacing and Tz included), `Element` (operand index; the array item for `TJ`; 1 for `"`), `Offset` (byte position of the code in that string).
- `PathInfo`: `Operator` (S s f F f* B B* b b* n; `n` only when a clip is pending), `Segments` (`PathSegment(Kind Move/Line/Curve/Close, X1..Y3)`, already transformed), `Bounds` (control points count), `InkBounds` (plus half the line width), `Fill`, `Stroke`, `EvenOdd`, `Clips`. A tiling pattern's cell follows the path that first used it.
- `ImageInfo`: `Name`, `Stream` or `Inline`, `Dictionary` (full keys), `Width`, `Height`, `IsMask`, `Matrix` and `Bounds` of the unit square, `OptionalContent`. `ShadingInfo(Name, Shading, Bounds)`. `FormInfo(Stream, Name, Matrix, Bounds, IsPattern, OptionalContent)`. `MarkedContent(Tag, Properties, Mcid, OptionalContent)` (`OptionalContent` set for tag `OC`).
- `GraphicsState`: `Ctm`, `Clip`, `FillColor`, `StrokeColor` (`PdfColor`: `Space`, `Components`, `PatternName`, `Pattern`, `Rgb`), line width, cap, join, miter, `Dash`, `DashPhase`, `CharSpacing`, `WordSpacing`, `HorizontalScale` (1 = 100%), `Leading`, `Font`, `FontSize`, `RenderMode`, `Rise`, `FillAlpha`, `StrokeAlpha`, `BlendMode`, `SoftMask`. `ColorSpaceInfo`: `Family`, `Components`, `Definition`, `Base`, `ToRgb`; colour conversion is profile-free (Filters).

**`PdfFont.Get(document, fontDictionary)`**, cached per dictionary. Type1, MMType1, TrueType, Type3, Type0 over CIDFontType0 and 2. Members: `Subtype`, `BaseFont`, `Name` (no subset tag), `IsComposite`, `IsType3`, `IsVertical`, `IsEmbedded`, `HasToUnicode`, `Descriptor`, `Flags`, `IsBold/IsItalic/IsFixedPitch/IsSerif/IsSymbolic`, `Ascent`, `Descent`, `CapHeight` (1/1000 em), `FontMatrix`, `FontBBox`. `int Read(ReadOnlySpan<byte>, out FontChar)` takes the first character and returns the bytes used (always at least 1 for non-empty input); `Decode(span)`, `ToText(span)`. `FontChar(Code, Length, Cid, Width, Unicode, IsSpace, VerticalAdvance, OriginX, OriginY)`, widths in 1/1000 em (Type 3 scaled by its matrix).

- Composite fonts: `/Encoding` predefined or embedded CMap (`/UseCMap` one level), `/W`, `/DW`, `/DW2`, `/W2`, `/CIDToGIDMap`, at most 300,000 width entries.

Add(family, style, IEnumerable<string> texts, bool embed = false)` adds a font object to the document: a Standard 14 Type1 with WinAnsi (Arial, Times New Roman and Courier New map to them) when every character fits and `embed` is false, else a subset Type0 font with Identity-H, `/W`, `/DW`, descriptor, `/FontFile2` (or `/FontFile3` OpenType) and `/ToUnicode` from `EmbeddedFontBuilder`; null without a usable file or when embedding is forbidden. ### Text: characters, words, lines, selection, search

Folder `Text/`, uses Content. No user-visible text. Everything is in page user space, as in the content; the viewer converts with `PageGeometry`. A `TextPage` never changes and may be shared between threads; it is stale once the document is edited. Nothing throws on file contents: a content stream that cannot be decoded gives the text up to it.

**`TextPage`** (`sealed partial`)
- `static TextPage Create(PdfDocument, PdfPage, TextPageOptions? = null)` and `Create(ContentInterpreter, PdfPage, TextPageOptions? = null)` (the second reuses the caller's interpreter and its caches; it sets `WalkPatterns` off for the run and restores it). `record TextPageOptions(bool IncludeArtifacts = true, bool RemoveDuplicates = true)`.
- `PageIndex`, `Box` (crop box), `IsTruncated` (interpreter operation limit, or more than 1,000,000 glyphs), `Chars`, `Words`, `Lines`, `Blocks` (all `IReadOnlyList`), `Text`.
- `string GetText(TextRange, bool joinHyphens = false)`, `IReadOnlyList<TextQuad> Quads(TextRange)`, `TextRange WordRange(int)`, `LineRange(int)`, `TextHit? HitTest(x, y, maxDistance = infinity)`, `int CaretAt(x, y)`.
- Text rules: lines are joined by a line feed, blocks by a blank line, table cells and cells of one row by a tab; spaces at line ends are dropped. `joinHyphens` removes a `-`, U+2010, U+2011 or U+00AD that ends a line after a letter and joins the next line when it starts with a letter; before a capital the hyphen stays and only the break goes.

**Model.** `TextRange(Start, End)` (end excluded, `Count`, `IsEmpty`). `TextChar`: `Index`, `Text` (empty when the font gives none; Arabic presentation forms and Latin ligature code points are folded to plain letters; a ligature is one char with several characters), `Quad`, `Font` (null for implied spaces), `Size`, `Color` (stroke colour for Tr 1), `RenderMode`, `OperatorIndex` and `Form` (the innermost form, null on the page; the index is into the parse of that stream), `Element`, `Offset`, `Mcid`, `IsArtifact`, `IsSpace`, `IsImplied`, `IsRtl`, `Word` (-1 for spaces), `Line`. `TextWord(Index, Range, Text, Bounds, Line)`. `PageLine(Index, Range, Text, Bounds, Quad, Block, TextBreak Before, IsVertical, IsRtl)`; `enum TextBreak {None, Tab, Line, Block}` is what separates it from the line before. `TextBlock(Index, Lines, Bounds, IsTable)`. `TextHit(Char, Word, Line, Distance)`. `TextQuad(X0..Y3)`: bottom-left, bottom-right, top-right, top-left of the glyph box in the glyph's frame (rotation and skew kept); `Bounds`, `Center`, `Contains`, `DistanceTo`, `ToQuadPoints()` (the eight numbers of `/QuadPoints`, top-left first).

**What goes in.** Every glyph the interpreter shows, with: render mode 3 (OCR) kept, mode 7 left out; glyphs wholly outside the clip box or the crop box dropped; `/ActualText` replaces its glyphs (one char per line the span covers, the text on the first, empty text hides them); `/Artifact` marked, dropped if asked; a glyph drawn again at nearly the same place with the same text (within 0.2 em, fake bold) dropped; control characters removed. Not included: text in annotations and form fields, Type 3 glyph procedures, optional content that is switched off.

**Layout.** Per page /Rotate (reading order is of the page as shown) and per direction group (text turned by other angles comes after the main text; a vertical font is its own group, columns right to left). Lines are glyphs on one baseline with script glyphs taken in; a gap over 1.2 em splits a line into cells. Rows of at least three lines with two or more short cells (24 characters, 3 words) are a table: a block of its own, rows kept, cells joined by tabs. Other cells chain into blocks by vertical neighbourhood, one child each so that a heading over two columns does not join them, and blocks are ordered by recursive cuts: horizontal bands first, then column gutters (a stretch of x under 4% covered, so a page number in the gutter does not join the columns), bands that are columnar with a shared gutter stay together. Spaces: a space glyph, or a gap over 0.1 em of the two sizes, becomes a space (`IsImplied`, with a quad over the gap). Right to left: lines with Hebrew or Arabic letters are put in logical order (levels from nearest letters, numbers kept, brackets mirrored back); columns go right to left on a page that is mostly right to left. Limits: depth 48 and 20,000 blocks in the order search, 200 neighbours looked at per cell.

**`TextSelection`** (`Page`, `Ranges`, `IsEmpty`, `GetText(joinHyphens = false)`, `Quads()` one per stretch of a line, spaces at the ends left out). `Between(page, x1, y1, x2, y2)` is from caret to caret (either order; above all text is 0, below is the end), `InRectangle(page, PdfRect)` takes chars at least half inside, by line, `WordAt` (a space takes the next word), `LineAt`, `Of(page, TextRange)` (clamped).

**`TextSearch`** (static). `record TextSearchOptions(bool MatchCase = false, bool WholeWord = false, bool Regex = false, bool FoldDiacritics = false)`; `record SearchMatch(int Page, TextRange Range, string Text, IReadOnlyList<TextQuad> Quads)` with one quad per stretch of line. `Find(TextPage, query, options?, CancellationToken = default)` returns a list; `Find(TextCache, query, options?, first = 0, last = int.MaxValue, CancellationToken)` is an `IEnumerable` that searches a page as it is read and throws `OperationCanceledException`. White space in the query and the text, line breaks included, is one space. A hyphen at a line end is both ways: `in-` `formation` matches "information", `well-` `known` matches "well-known" (U+00AD joins only the first way). Matches do not overlap; the first of two overlapping ones wins. Case is `ToLowerInvariant` except U+0130, so I and i match, dotted and dotless I match nothing but themselves. Folding strips marks (decomposition, Hangul and CJK left whole), maps `ı İ ß æ œ ø ł đ` and their capitals to ASCII, so I, İ, ı, i all match. Whole word looks at the edge characters of the query. A regular expression runs on the page text with `CultureInvariant` and `IgnoreCase` unless `MatchCase`, over the folded text when folding (write it without marks); `WholeWord` wraps it in lookarounds; a pattern that takes over two seconds on a page gives no hits there; a bad pattern throws `ArgumentException`.

**`TextCache(PdfDocument, int maxChars = 2_000_000)`**: `Get(pageIndex)` builds on first use, least recently used pages go first once the characters pass the cap (the page just asked for always stays), `PageCount`, `Clear()` after an edit. Calls are serialized; the document is not safe to share. **`TextExport`**: `Page(TextPage, joinHyphens = false)` and `Range(TextCache, first, last, joinHyphens = false, CancellationToken)`, a form feed after each page.

**Measured.** A page takes a median of 0.9 ms with the content parsed (p99 16 ms) on the 4,158 corpus pages. Against `pdftotext` (4.06) the word sets of a page agree at Jaccard 0.98 on 89% of pages, 0.95 on 93%, 0.90 on 96%, in both default and `-layout`; what differs is mostly annotation text, shadows drawn as white copies, and cells that `pdftotext` splits differently.

### Pages

Rotate, delete, reorder, insert, import, merge, split, extract, boxes and resize (`Pages/`; uses Document only). Edits are made to an open `PdfDocument` in memory and the caller commits them through `PdfEditSession.Commit`. Pages are named by index from 0 as the document is when the call starts. A call that changes the set or order of pages lays the page tree out again, so any `PdfPage` held from before is stale (`document.Pages` is fresh). Arguments are checked before anything is changed: a bad index is `ArgumentOutOfRangeException`, other bad values `ArgumentException`.

**Page ranges.** `PageRange.Parse(string text, int pageCount)` is Lazy Print's parser ("1-3, 5, 8-", 1-based, order and repeats kept) giving `PageRangeResult(IReadOnlyList<int> Pages, PageRangeError? Error)` with 0-based pages. Its words are in `PagesText`.

**PageOperations** (`static`):
- `Rotate(PdfDocument, IEnumerable<int> pages, int degrees)` adds a multiple of 90 (negative turns back) to what the page shows, inherited value included, and writes `/Rotate` as 0, 90, 180 or 270.
- `SetBox(document, pages, PageBox box, PdfRect? rect)`; `PageBox` is `Media, Crop, Trim, Bleed, Art`. A box is clipped to the media box (one that misses it, or has no area, is refused); null removes it, except for the media box.
- `Resize(document, pages, double width, double height, ResizeMode mode)` with the size in points as the page is shown (turned pages and `/UserUnit` allowed for), 0 to 14400. `ScaleContent` fits and centres the page's crop box in the new size under a `q ... cm` / `Q` pair added round the content, maps the annotations' `/Rect`, `/QuadPoints`, `/L`, `/Vertices` and the trim, bleed and art boxes, and sets media and crop to the new size. Appearance streams follow their `/Rect`; other annotation geometry (`/InkList`, destinations' coordinates) is not mapped. `ChangeBox` sets media and crop to the new size from the crop box's lower-left corner and removes trim, bleed and art; the content stays.
- `RemoveTransitions(document, pages)` removes `/Trans` and `/Dur`.
- `Delete(document, pages)` refuses to remove every page. It removes the pages and frees their objects, and first: takes `/Dest` and GoTo `/A` away from outline items, links and other annotations that point at them (the item stays, the destination goes), removes the open action, removes named destinations (`/Dests` and the `/Names` tree) that point at them, removes their widgets from `/AcroForm /Fields` and `/CO` (a field with no widget or sub-field left goes, up to the root), and renumbers `/PageLabels` (a range with no page left is dropped, one that lost its first pages continues its numbering through `/St`; the tree is written flat). A tagged document loses `/StructTreeRoot`, `/MarkInfo` and every `/StructParents` when a deleted page had `/StructParents`; the structure is not edited. Resources that remaining pages inherit from the tree are left as they are.
- `Reorder(document, IReadOnlyList<int> order)`: the page at `order[i]` becomes page `i`; must name each page once. `Move(document, pages, int before)` puts the pages, in document order, before the page now at `before` (the count puts them last). Page labels stay with positions.
- `Duplicate(document, pages)` puts a copy after each page, sharing content, fonts and images; annotations and form fields are copied (a field is renamed "name_2").
- `InsertBlank(document, int at, double width, double height, int count = 1)`; `ImportPages(PdfDocument target, PdfDocument source, IReadOnlyList<int> sourcePages, int at)`.

**Import.** Everything a page uses is copied once per call. Source and target may each be encrypted (copied streams are decrypted and written again with the target's handler); the source may be the target. Inherited `/Resources`, `/MediaBox`, `/CropBox` and `/Rotate` are written onto the new page. Not copied: `/Parent`, `/B`, `/StructParents` and `/StructParent`, the tree, outlines, names, threads and tags. A reference to a page that did not come across, to a page tree node or to the catalog reads as nothing, whatever holds it. Resources the content never names are left out (a form without `/Resources` of its own is read for names; a Type 3 font without them, or a content stream that does not decode, stops the pruning for that page). Annotations are kept and copied for each copy of the page, `/P` points at the new page, a popup stays only with its note; links and GoTo actions to pages that came across are repointed (named destinations are looked up in the source and made explicit), a Link to a page that did not is dropped, any other annotation loses the dead `/Dest` or `/A`. Form fields join the target's `/AcroForm`: the chain above each widget is copied with only the widgets that came across; a root field whose `/T` is taken gets `_2`, `_3`... so values stay separate; `/DA` and `/Q` are carried to the root, the source's `/DR` entries the target lacks and `/NeedAppearances` are merged; a signature field loses its `/V`. References are followed through a queue (no recursion limit on chains), loops close on the copy.

**PageAssembly** (`static`): `Extract(source, pages)` makes a new `PdfDocument` (not yet saved) of those pages in that order, with the source's `/Info`. `Merge(IReadOnlyList<MergeSource>)` with `MergeSource(PdfDocument Document, IReadOnlyList<int>? Pages = null)` (null takes all; a document listed twice is copied once; first source's `/Info`). `SplitEvery(source, n)`, `SplitByRanges(source, IReadOnlyList<IReadOnlyList<int>>)`, `SplitAt(source, IEnumerable<int> starts)` (page 0 implied, repeats ignored; pass the pages of the top-level bookmarks), `SplitBySize(source, long maxBytes, PdfSaveOptions? options = null)`: as many pages per part as save (`SaveRewrite(options)`) to no more than `maxBytes`, a page too big alone is a part; found by galloping and bisecting, a few saves per part. A new document holds the pages and what they use and nothing else: no outlines, names, destinations, labels, tags, threads or open action; after `SaveRewrite` nothing of a page left out is in the bytes. Parts are built at once and share nothing with each other; the source is not changed.

**Page tree.** After any change the tree is rebuilt with at most 32 kids per node (flat up to 32 pages, a node per 32 and so on above), reusing the old inner nodes in order so that an edit near the end of a large file rewrites few objects. A page that took `/Resources`, `/MediaBox`, `/CropBox` or `/Rotate` from a removed inner node gets it written on itself. A tree that was damaged is rebuilt from `document.Pages`.

**Limits.** Trees, outline items and name trees are walked with node caps (1,000,000 and 100,000) and a depth of 32 for field and name chains; resource pruning stops after 64 rounds. An edit session keeps what a delete removed in its history; `SaveCompact` or `SaveRewrite` drops it.

### Structure: outlines, destinations, actions, links, labels, attachments, metadata, layers

### Forms: AcroForm fields, filling, authoring, scripts, flattening, data

Folder `Forms/`, namespace `LazyPDF.Core`. Uses Annotations (appearance canvas, flattener, FDF), Content and Fonts. Work is on the open `PdfDocument` in memory; the edit session commits it. The system renderer ignores `/NeedAppearances` and keeps a stale `/AP`, so every field whose value changes gets a new appearance stream from this layer. User text is in `FormText`. **`PdfForm`** (partial, sealed). `Read(document, IFontSource? fonts = null)`; no `/AcroForm` gives an empty form. `Fields` (terminal fields in tree order, orphans last), `Orphans`, `Find(name)`, `FindAll(name)`, `Document`, `AcroForm`, `NeedAppearances`, `CanFill` (permissions, enforcement is the app's), `Xfa` (`None`, `Static` when fields exist, `Dynamic`), `XfaRemoved`, `Refresh()` after hand edits. With no font file for text a Standard font cannot draw, `InvalidOperationException(FormText.NoFont)` is thrown before anything changes.
- `Recalculate()` and `SetValues` run `/CO`; `Validate(field, text)`, `DisplayText(field)`, `Scripts`, `CalculationOrder`.

**Scripts.** `FormScripts.List(form)`: `FormScript(Field, Event, Source, BuiltIn)` with `Ran` (built-in and event K F V C). Events are `/AA` keys, `A`, `OpenAction`, `Names/<name>`. Only a script made of calls to AFNumber_Format/Keystroke, AFPercent_Format/Keystroke, AFDate_Format/FormatEx/Keystroke/KeystrokeEx, AFTime_*, AFSpecial_Format/Keystroke/KeystrokeEx, AFSimple_Calculate (SUM AVG PRD MIN MAX) and AFRange_Validate is built-in; it is parsed and run in C# (numbers, strings, booleans, arrays and `new Array`; comments allowed). Format changes the drawn text (red for negative styles 1 and 3), not `/V`. Any other JavaScript is listed, never run, and a calculation using it is returned in `NotRun` (`FormText.ScriptNotRun`).

**Authoring.** `AddField(FieldSpec)` (kind, name, page, rect, value, default, options, flags, `MaxLength`, tooltip, font, size, colours, border, alignment, rotation, caption, export value; a dotted name makes parents), `AddWidget(field, page, rect, export)` (a second place; a merged field is split; radio buttons), `Move`, `Resize`, `Remove(field | widget)` (empty parents go too), `Rename`, `SetFlag`, `SetTooltip`, `SetDefaultValue`, `SetOptions`, `SetMaxLength`. Duplicate or overlapping names throw `InvalidOperationException`, bad names, pages and rectangles `ArgumentException`. Tab order: `GetTabOrder`, `SetTabOrder(page, TabOrder)`, `TabSequence(page)` (structure order reads as `/Annots`), `ReorderWidgets`.

**Detection.** `FieldDetector.Detect(document[, pageIndex])` gives `FieldProposal(PageIndex, Rect, Kind, Name, Label)` with `Cells`, `Multiline` and `ToSpec()`; nothing is added. Found: ruled lines and underscore or dot runs with no text on them, empty squares (check boxes), circles (radio buttons), empty boxes, rows of three or more equal boxes (comb), a short label ending in a colon followed by space. Closed cells, filled bars and blanks overlapping a widget are skipped; names come from the nearest label and are unique. Needs vector content.

**Flatten.** `Flatten(fields = null)` burns widgets through the annotation flattener (hidden ones just go), draws missing or stale appearances first, removes the fields and `/AcroForm` when none is left, returns the widgets burned. Annotations gained `internal PdfAnnotationFlattener.Flatten(document, page, Func<PdfAnnotation, bool>)`.

**Data.** `ExportFdf(fileName)` (write with `PdfFdf.Write` or `PdfXfdf.Write`), `ImportFdf(fdf)`, `ExportCsv()` (header row, value row). `BulkFill.Create(formBytes, csv, fonts, password)` reads CSV (comma, semicolon or tab; quotes; BOM): `Rows`, `Columns`, `UnmatchedColumns`, `Fill(row, flatten = false)` gives the form's bytes as an incremental update with that row's values. An empty cell empties its field.

**XFA.** Static: filled through the AcroForm and `/XFA` removed (`XfaRemoved`, `FormText.XfaRemoved`). Dynamic: every change throws `PdfReadException` Unsupported with `FormText.DynamicXfa`.

**Limits.** Digital signature fields are only reported. Choice and push button captions use the field's font; no icons. Combo arrows are not drawn. Month names are English. Tests: `LazyPDF.Core.Tests/Forms/` (fixture, reading, fill, authoring, scripts, flatten, data, detection, malformed input, corpus).

### Stamps: watermarks, backgrounds, headers, footers, Bates numbers, images

Folder `Stamps/`, uses Content and Fonts (and `PdfText` from Structure for the label strings). Nothing is saved here: the caller saves the document. Errors: `ArgumentException` for a spec with nothing to draw, `InvalidOperationException` with `StampsText.NoFont` when no font can draw the text (the document is then unchanged). `StampsText` holds the two user texts.

**`PdfImageWriter`** (static, also for signatures and pictures placed on a page). `record PdfImage(PdfReference Reference, int Width, int Height)`.
- `PdfImage? AddJpeg(PdfDocument, byte[] jpeg)`: DCTDecode as it is; colour and size from the frame header (1, 3 or 4 components; an Adobe CMYK file gets the inverting /Decode). Null for an unreadable header. `TryReadJpegHeader` is copied from Lazy Scan.
- `PdfImage AddRgba(PdfDocument, int width, int height, byte[] rgba)`: straight RGBA8, top row first, Flate, with an /SMask when any alpha is below 255. `ArgumentException` when the size does not fit the data. Both call `ContentImages`.

**`PdfStamper(PdfDocument, IFontSource? fonts = null)`**. All sizes and offsets are display points of the page as shown (crop box, `/Rotate` and `/UserUnit` applied through `PageGeometry`), y down, so text is upright on a rotated page. `Pages` in a spec are 0-based, null for all; out of range and repeated entries are ignored.
- `StampRun AddWatermark(WatermarkSpec)`, `AddBackground(BackgroundSpec)`, `AddHeaderFooter(HeaderFooterSpec)`. `record StampRun(int Id, int Pages, long NextBates, IReadOnlyList<int> Missing)`: the run's id, pages stamped, where the next document of a Bates batch starts (0 without Bates), code points the font has no glyph for.
- `StampRun Update(int id, WatermarkSpec | BackgroundSpec | HeaderFooterSpec)`: removes run `id` and adds the new one under it (adds it when there was none).
- `IReadOnlyList<StampInfo> List()`, `List(PdfPage)`: `record StampInfo(int Id, StampKind Kind, string? Label, bool Behind, IReadOnlyList<int> Pages)`, by id. `StampKind`: `Watermark`, `Background`, `HeaderFooter`, `Bates`. Label is the watermark text ("image" for a picture), or the header and footer texts joined by " | ".
- `int Remove(int id)` returns the pages it was on; it also takes out the run's resources and optional content group. `int RemoveAll()` returns the number of runs.

**Specs** (sealed records with `init` properties). `StampColor(R, G, B)` 0 to 1, `StampColor.Gray(l)`. `StampAnchor`: nine positions, `TopLeft` to `BottomRight`.
- `WatermarkSpec`: `Text` (lines split at `\n`) or `Image` (exactly one), `FontFamily` ("Helvetica"), `FontStyle` (Bold), `Color` (gray 0.5), `Opacity` (0.3, an /ExtGState `ca` and `CA`, none at 1), `Rotation` (degrees counter-clockwise about the centre), `Scale` (0.6: the unrotated width as a fraction of the page width, the text size follows; an image keeps its proportions), `Anchor` (Center), `OffsetX`, `OffsetY` (right and down), `Behind`, `LayerName`, `Pages`.
- `BackgroundSpec`: `Color`, `Image` (either or both, behind the content), `Fit` (`Cover` clips the overflow, `Contain`, `Stretch`), `Opacity` (1), `LayerName`, `Pages`.
- `HeaderFooterSpec`: `Header`, `Footer` as `HeaderFooterBand(Left, Center, Right)`; `EvenHeader`, `EvenFooter` replace them on the 2nd, 4th... page (null: same); `FontFamily`, `FontStyle`, `FontSize` (10), `Color`, `MarginX`, `MarginTop`, `MarginBottom` (36); `StartNumber` (1; page i shows StartNumber + i); `Date` (the app passes it, Core has no clock), `DateFormat` ("yyyy-MM-dd"), `Culture` (invariant); `FileName`; `Bates`; `Pages`. Tokens: `{page}`, `{pages}` (the last page's number), `{date}`, `{date:format}`, `{file}`, `{bates}` (left as typed without `Bates`). Unknown tokens, a lone brace and an invalid date format stay as typed. Slots are one line; left and right are set at the margin, centre on the page. A page whose slots are all empty gets nothing.
- `BatesSpec(Prefix = "", Suffix = "", int Digits = 6, long Start = 1)`, `Format(long)` pads to `Digits` (1 to 18). The pages stamped are numbered from `Start` in document order; pass the run's `NextBates` as the next document's `Start`.

**What is written.** Text uses `PdfFontEmbedder` with one font per run holding all its text: a Standard 14 font when WinAnsi fits, else an embedded subset from `fonts` (Turkish letters included; no source or file means `NoFont`). Per page one content stream: `q`, one `cm` into the shown page's y-up space, then each part inside `/Artifact <</Type /Pagination /Subtype /Watermark|Header|Footer /LazyPDF id>> BDC`, backgrounds as `/Type /Background`, and when a layer is named inside `/OC BDC` too; `Q`. A layer is an OCG named by `LayerName` with Print and View on and Watermark subtype, added to `/OCProperties` `/OCGs` and `/D /Order`, shared by the run, tagged with its id. The stream dictionary carries `/LazyPDF <</Id n /Kind /Watermark /Label (...) /Back true>>`; that key is what `List`, `Update` and `Remove` read. Resources are named `LPS<id>_F`, `_I`, `_G`, `_P` (font, image, state, layer).
- Placement: behind stamps (`Behind`, backgrounds) go first in `/Contents` and need nothing from the page. Stamps in front go last, between a pair of marked streams built once per page from the page's content: the first opens as many `q` as the content may pop (one more than its deepest underflow, at most 1000), the second closes `ET`, `EMC` and `Q` for what it leaves open. So unbalanced content, an open text object or open marked content cannot shift or break a stamp. The wrapper goes when the last front stamp on the page does.
- Ids are one more than the highest found in the file. A page with no `/Contents`, a single stream or an array takes stamps; an inherited `/Resources` is copied onto the page first.

**Limits.** A run is found only while its streams stay separate: a tool that merges a page's content streams loses the `/LazyPDF` key, and the stamp then reads as page content. The `Q` that a page pops without a `q` of its own pops the wrapper's, so a stray `Q` after a `cm` restores the initial state in front stamps' pages instead of being ignored. Removing leaves the font and image objects in the file until a rewrite. Optional content needs PDF 1.5, transparency 1.4; the header version is not raised. Only the 0-based page list selects pages (no "odd" or "even" ranges); `PageRange` in Pages parses typed ranges.

**Tests.** `windows/LazyPDF.Core.Tests/Stamps/`: every writer test reopens through `PdfDocument` and PdfPig; glyph positions are checked with the interpreter in display points on pages with `/Rotate`, `/CropBox`, `/UserUnit`; unbalanced pages; Turkish text with arial.ttf; a corpus run under `LAZYPDF_CORPUS`.

### Changes to finished layers

No signature changed. What differs in behaviour:

**Text.** `TextSearch` case folding turns U+0130 (dotted capital I) into `i`; dotless `ı` stays its own letter until `FoldDiacritics`. With `Regex` and `FoldDiacritics` the pattern is folded as the page is. A rejected whole-word candidate advances by one character, so an overlapping valid hit is found. Reading order follows the baseline, so a sheared matrix (synthetic italic) stays in its line. Type 3 glyph boxes and `Size` come from `/FontBBox` and `/FontMatrix`, not the font size. `/ActualText` without a byte order mark is read as PDFDocEncoding. Right-to-left lines: terminators (`%`, `$`) stay with their number, and a page that is right to left treats every line with a right-to-left letter as right to left.

**Content.** A bad `/ToUnicode` costs only the text; widths, `/Encoding` and vertical mode are still read. A ToUnicode map written at another code width than the font reads still applies, by numeric code. `/W` and `/W2` are bounded by entries written, not by distinct entries. `TJ` array items cost one operation each. A form with more than 1,000,000 operations is skipped; forms that are not cached cost operations in proportion to their size.

**Fonts.** `EmbeddedFont.Encode` skips control characters, as `Width` does. A CFF font embedded whole writes CIDs (through the charset) as codes. When characters are missing, CID 0 gets a `/W` entry with the `.notdef` advance. WinAnsi fitting accepts U+00A0 and U+00AD.

**Annotations.** `Regenerate`, `Resize`, `SetColor` and `SetOpacity` leave a stamp alone unless its appearance was drawn by `AddStamp` (it carries `/LazyPDFText true`): image stamps and stamps from other writers keep their artwork. `Delete` takes a widget out of its field's `/Kids` or `/Fields` and clears the owner's `/Popup` when a popup is deleted. `PdfAnnotationFlattener` does not burn an annotation whose `/OC` group is off. `PdfXfdf` writes and reads `justification` as left/centered/right, `symbol` as paragraph/none, `replyType` as reply/group, and names a parent before its reply. `PdfFdf.Export` leaves out `/StructParent`. `PdfFdf.Import` keeps a reply to an annotation the document already has, and skips a popup whose owner was skipped.

**Forms.** `AddWidget` repoints `/Annots` even when the widget has no `/P`, and the new widget takes the first one's `/MK` and `/BS`. A radio group's default on-state is the first `ChoiceN` not in use. Dates are read by the field's own format first; `AFNumber_Format` style 2 reads a lone `.` before three digits as a group mark; `AFSpecial_Format(2)` needs exactly 10 digits. A widget's own `/DA` and `/Q` win over the field's for colour, size and alignment. A push button with an `/MK /I` icon is not redrawn; redrawing keeps the other states of `/AP`. `SetFlag`, `SetMaxLength` and `SetDefaultValue` write an explicit empty value when an ancestor has one. `ExportFdf` writes a button's on-state name. Removing a radio or check box widget removes its `/Opt` entry and resets `/V` if it named that button.

**Pages.** `Extract`, `Merge` and `ImportPages` carry the optional content groups the pages use into `/OCProperties`, with the hidden ones in `/D /OFF`; direct dictionaries in `/Annots` are copied; field lists of `SubmitForm`, `ResetForm` and `Hide` keep only the fields that came across; `/AA` and `/Next` chains are fixed like `/A`; a form's own `/Resources` are pruned to the names its content uses. Merged runs of the same stamp id from different files are renumbered (`StampRuns.Separate`). `Delete` also cleans `/Threads`, `/Next` and `/AA` chains and `/OpenAction`, recomputes `/Limits` of the named destination tree and drops empty leaves, drops the structure tree when a deleted page has tagged annotations (removing `/StructParent` and `/Tabs /S`), and a page inserted at 0 into a labelled file gets `/S /D`. `Resize` with `ScaleContent` also maps `/InkList` and `/CL` and scales `/RD`.

**Stamps.** `PdfStamper.Update` draws the new run under a spare id first; if that throws the old run stays. `Remove` frees stamp streams only with the last page that lists them, and unlists the layer from `/ON`, `/OFF`, `/Locked`, `/RBGroups` and `/AS`. Background artifacts carry `/BBox`.

**Structure.** `Outline.Write` gives an item or root a new object when its old one was freed. `DocumentMetadata.Write` sets `dc:subject` from the keywords and keeps a `/CreationDate` or `/ModDate` that could not be parsed. `PdfAttachments.Remove` keeps a file specification another annotation still uses and deletes the popup and replies of the annotation. `/F` of a file specification is ASCII (`_` for the rest); `SubmitFormAction` writes a URL file specification.
